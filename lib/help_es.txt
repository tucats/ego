.topic command

La herramienta de línea de comandos Ego se utiliza para ejecutar
programas Ego. El comando tiene la siguiente forma:

    ego [options] [verb] [arguments]

El comando ego debe encontrarse en la variable de entorno PATH del
usuario o en la ruta de ejecución de Windows. Todas las variantes del
comando ego se ejecutan desde este único archivo de comando.

El comando ego puede ir seguido de opciones globales (aquellas
opciones disponibles para todos los comandos), un verbo de comando y
cualquier verbo o opción de subcomando correspondiente a ese comando.

Para cualquier comando, puedes especificar la opción -h o --help
para obtener ayuda sobre el comando y sus opciones.

Si especificas el comando "ego" sin opciones, se asume que
pretendes usar el comando "run". Puedes comprobarlo en el texto de
--help, que siempre indica cuál es el verbo de comando (o subcomando)
predeterminado si no se indica ninguno.

En general, los comandos ego constan de un verbo seguido de
argumentos, o de un verbo de comando seguido de verbos de subcomando.
Por ejemplo, para mostrar el estado del servidor predeterminado, el
comando es:

    ego server status

Sin embargo, si ejecutas el comando "ego server -h" verás que el
comando status es el subcomando predeterminado, por lo que también
puedes usar:

    ego server

para obtener el mismo resultado.

Cualquier subcomando puede ir seguido de la opción -h o --help para
obtener más ayuda sobre ese comando específico.

.topic command.options

Esta sección describe muchas de las opciones globales disponibles
para cualquier invocación del comando ego. Las opciones globales deben
ser los primeros argumentos en la línea de comandos, antes de
cualquier verbo o verbo de subcomando.

Ten en cuenta que esta lista no es exhaustiva, pero incluye muchas
de las opciones más comunes. Para obtener una lista completa, utiliza
el comando "ego -h".

.topic command.options.format

+--------+--------+--------+--------+--------+--------+--------+-------+
De forma predeterminada, el comando ego da formato a la salida del
comando para que sea legible por humanos. Esto significa que la
salida se formateará para que sea fácil de leer, e incluirá
encabezados y pies de página que indican el inicio y el fin de la
salida. Esta salida también es adecuada para la localización y se
puede traducir a otros idiomas.

Puedes cambiar el formato de salida de una instancia del comando
desde el valor predeterminado 'text' a 'json' o 'indented'. Ambos
formatos son adecuados para el procesamiento automático y no están
localizados.
El formato 'json' es un único flujo de datos json sin procesar, sin
ningún formato adicional. El formato 'indented' es igual que el
formato 'json', pero se presenta con sangría para facilitar su
lectura.

El formato del comando se especifica mediante la opción --format,
seguida del nombre del formato. Por ejemplo,

    ego --format json server status

hará que la salida del comando server status esté en formato json
sin procesar. Esto resulta útil si utilizas el comando ego en un
script o en una canalización (pipeline) y quieres procesar la salida
mediante un script.

Esta opción corresponde al parámetro de configuración
"ego.console.format". Si un parámetro de configuración especifica el
formato de salida, se utilizará ese formato a menos que lo
sobrescribas en la línea de comandos ego específica mediante la
opción --format (o su forma abreviada, -f).

.topic command.options.log

+--------+--------+--------+--------+--------+--------+--------+-------+
El comando ego puede registrar información adicional en la consola
stdout (o en un archivo de registro cuando se ejecuta como un servidor
independiente). Esta información puede resultar útil para depurar o
para comprender el funcionamiento del comando.

El nivel de registro se especifica mediante la opción --log, seguida
del tipo de salida de registro deseado. Cada clase de registro tiene
un nombre, y puedes especificar más de una clase de registro
indicándolas como una lista separada por comas. Si utilizas espacios
en esta lista, toda la lista debe ir entre comillas). Las clases de
registro son las siguientes:

    app             Estado e información de inicio de la aplicación ego
    asset           Gestión de recursos HTML del servidor
    auth            Autenticación y autorización del servidor
    bytecode        Generación de bytecode
    cache           Caché del servidor para servicios y recursos almacenados
    child           Generación de procesos hijos por parte del servidor
    cli             Análisis de la línea de comandos
    compiler        Compilación del código fuente de Ego
    db              Operaciones de base de datos
    optimizer       Operaciones del optimizador peephole
    resources       Objetos de recursos respaldados por base de datos
    rest            Operaciones de servicio RESTful (cliente y servidor)
    route           Procesamiento de rutas de servicios REST
    server          Operaciones generales del servidor
    services        Gestión de servicios REST de Ego compilados
    sql             Operaciones SQL generadas
    stats           Estadísticas de uso de memoria al salir de ego
    symbols         Operaciones de la tabla de símbolos durante la ejecución de programas Ego
    tables          Uso de los servicios REST /tables
    trace           Seguimiento de la ejecución de programas de bytecode de Ego
    user            Entradas de registro definidas por el usuario (directiva @log)

La salida de registro tiene el mismo formato independientemente de
la clase de registro. Cada entrada de registro es una única línea de
texto e incluye la marca de tiempo en que se creó la entrada, el
número de secuencia de la entrada, la clase de registro y el texto de
la línea de registro a continuación de un carácter ":".

.topic command.options.profile
+--------+--------+--------+--------+--------+--------+--------+-------+

Cuando se ejecuta un comando ego, este aplica las configuraciones en
el siguiente orden:

1. Los parámetros de configuración predeterminados del perfil activo
2. Los parámetros de configuración expresados como variables de entorno
3. Las sobrescrituras de la línea de comandos para parámetros de
   configuración individuales

Al ejecutar un comando ego, puedes especificar un perfil de
configuración que se utilizará en el paso 1 anterior. Esto se hace
con la opción --profile (-p), seguida del nombre del perfil que se
va a utilizar. Por ejemplo,

    ego --profile test server status

hará que el comando server status utilice los parámetros de
configuración del perfil "test". Esto resulta útil si tienes
diferentes configuraciones de comandos, servidores predeterminados o
credenciales de inicio de sesión distintas para diferentes entornos
(como desarrollo, pruebas y producción).

El perfil predeterminado se llama "default" y se utilizará si no se
especifica ningún perfil en la línea de comandos. Además, si se
indica el nombre de un perfil que no existe, este se creará
automáticamente.

Consulta la ayuda adicional en el tema "command config" para
obtener más información sobre cómo crear y gestionar perfiles.

.topic command.options.quiet

+--------+--------+--------+--------+--------+--------+--------+-------+
De forma predeterminada, la mayoría de los comandos ego generan un
texto que indica el éxito o el fracaso de la operación del comando.
Además, el comando ego establece el estado de salida del shell en 0
si el comando se ejecutó correctamente, y en un número positivo
distinto de cero si no fue así.

Puedes suprimir la salida normal del comando utilizando la opción
--quiet (-q). Esto hará que el comando no genere ninguna salida, y el
estado de salida del shell se establecerá en 0 si el comando se
ejecutó correctamente. Esto puede resultar útil cuando utilizas
comandos ego en un script y no quieres ni necesitas texto superfluo
cuando las operaciones se completan con éxito.

Ten en cuenta que si se produce un error, o si el comando está
diseñado para generar una salida distinta de un mensaje, la opción
--quiet no suprimirá esa salida. Por ejemplo,

    ego --quiet server user delete test33

+--------+--------+--------+--------+--------+--------+--------+-------+
no generará ninguna salida si el usuario test33 se elimina
correctamente, pero sí generará salida si el usuario no existe o si
hay un error en el comando. Por el contrario,

    ego --quiet server users list

siempre generará salida, incluso cuando se indique la opción
--quiet, ya que el propósito del comando es mostrar las cuentas de
usuario conocidas por el servidor.

.topic command.options.set
+--------+--------+--------+--------+--------+--------+--------+-------+

Puedes establecer un valor de configuración para un comando ego
específico utilizando --set (-s), seguido de uno o más parámetros de
configuración y sus valores asociados. Si esta lista contiene
espacios, debe ir entera entre comillas. Por ejemplo,

    ego --set ego.compiler.extensions=true run myprogram.ego

Esto establecerá el valor de configuración "ego.compiler.extensions"
en true para la ejecución de este comando específico,
independientemente de los parámetros de configuración del perfil
activo para este elemento de configuración.

Consulta el tema de ayuda adicional "command config" para obtener
más información sobre cómo establecer y gestionar los parámetros de
configuración.

.topic command.config
+--------+--------+--------+--------+--------+--------+--------+-------+

El comando ego utiliza un archivo de configuración para almacenar
los parámetros que utiliza el comando. Este archivo se encuentra en
el directorio de inicio del usuario, dentro del directorio oculto
".ego". La configuración predeterminada se llama "default", y la
información de ese perfil se almacena en el archivo
"default.profile". Este archivo contiene datos JSON legibles por
humanos con los parámetros de configuración del perfil
correspondiente.

Cuando ejecutas Ego por primera vez, se crea el perfil
predeterminado. Puedes crear perfiles adicionales simplemente
nombrándolos mediante la opción global --profile (-p). Consulta el
tema "command.options.profile" para obtener más información sobre
esta opción. Cuando se crea un nuevo perfil, sus datos se almacenan
con el nombre del perfil en el mismo directorio ".ego".

El comando ego config tiene varios subcomandos que se describen en
los temas adicionales a continuación. Si no incluyes un subcomando,
el comportamiento predeterminado es mostrar el contenido del perfil
activo (o del predeterminado si no se especifica otro nombre).

    ego config delete foo

.topic command.config.set

El comando "ego config set" establecerá un valor de configuración
en el perfil activo. Al comando le siguen el nombre del parámetro de
configuración y el valor que se le va a asignar. Por ejemplo,

    ego config set ego.compiler.extensions=true

Esto establece en 'true' la opción que controla el soporte del
compilador para las extensiones del lenguaje. Este parámetro se
utilizará en todos los comandos ego que usen el compilador, a menos
que se sobrescriba en la línea de comandos mediante la opción --set.

Ten en cuenta que no puedes establecer un valor de configuración
que no exista si comienza con el prefijo "ego.". Es decir, los
nombres de configuración de Ego deben especificarse correctamente y
no puedes crear nuevos valores de clave de configuración de Ego. Sin
embargo, puedes crear tus propios parámetros de configuración
adicionales que no lleven el prefijo "ego.", y estos se pueden
utilizar en tus propios programas Ego mediante el paquete 'profile'.

Por ejemplo,

    ego config set myapp.debug=true

Esto creará un nuevo parámetro de configuración llamado
"myapp.debug" y lo establecerá en el valor "true". Este parámetro se
puede usar en tus programas Ego mediante el paquete 'profile':

    import "profile"

    if profile.Get("myapp.debug") == "true" {
        fmt.Println("Debugging is enabled")
    }

+--------+--------+--------+--------+--------+--------+--------+-------+
.topic command.config.show

El comando "ego config show" mostrará el contenido del perfil
activo. Si especificas un nombre de clave de configuración opcional,
el comando mostrará solo el valor de esa clave. Por ejemplo,

    ego config show ego.compiler.extensions

Esto escribirá "true" o "false" en stdout. Esto se puede usar en un
script para consultar un valor específico de un perfil.

.topic command.dsns

El comando "ego dsns" accede a los nombres de origen de datos (dsn)
almacenados. Estos son elementos con nombre que contienen toda la
información necesaria para acceder a una tabla de base de datos
(mediante la API REST /tables o el comando "ego tables").

Un dsn contiene la información necesaria para identificar el tipo
de base de datos subyacente (Postgres, sqlite3, etc.), el nombre de
la base de datos y las credenciales necesarias para acceder a ella.
Esto permite que un usuario con privilegios para usar el dsn acceda
a los datos sin necesidad de conocer la información de conexión a la
base de datos (de hecho, a menos que sean usuarios administrativos,
no pueden ver esta información aunque estén autorizados a usar el
propio dsn para acceder a los datos).

.topic command.logon

El comando "ego logon" se utiliza para iniciar sesión en un
servidor Ego. El usuario debe indicar el nombre de usuario y la
contraseña que se usarán para iniciar sesión. Si no se indican en la
línea de comandos, Ego los solicitará (la contraseña se introduce
sin mostrar el texto al usuario, por razones de seguridad).

Cuando el servidor autentica a un usuario, le devuelve un token.
Este token se puede utilizar para accesos posteriores al servidor.
Cuando se usa el comando ego logon, el token se almacena en el
perfil activo. Los comandos posteriores dirigidos al servidor
utilizarán el token almacenado para autenticarse ante el servidor,
hasta que el token expire. Llegado ese momento, los comandos ego
posteriores que necesiten el token informarán de un error indicando
que el usuario debe volver a iniciar sesión.

A continuación se muestra un ejemplo de inicio de sesión. El
usuario omite la contraseña en la línea de comandos, por lo que el
comando ego la solicitará:

    ego -p payroll logon -u payroll_admin

El usuario iniciará sesión con el nombre de usuario "payroll_admin"
y la contraseña que Ego solicitará. El token resultante se almacena
en el perfil "payroll". Los comandos posteriores que hagan
referencia al perfil "payroll" utilizarán el token de inicio de
sesión para autenticarse ante el servidor.

.topic command.run

El comando "ego run" se utiliza para ejecutar un programa Ego. El
programa se especifica como el primer argumento del comando. Puede
ser un nombre de archivo o una ruta de directorio. Si es una ruta de
directorio, el comando ego buscará un archivo llamado "main.ego" en
ese directorio y lo ejecutará, utilizando todos los demás archivos
fuente del directorio para localizar cualquier código de programa
adicional que se necesite para la ejecución.

Cuando se ejecuta un programa, de forma predeterminada el control
comienza en la función main(). Puedes cambiar esto mediante la
opción "--entrypoint", que especifica un nombre de función
alternativo para iniciar el programa.

Si no especificas un nombre de programa o un directorio, el
comando ego asumirá que quieres ejecutar en modo interactivo y te
pedirá que introduzcas sentencias de programa en la consola. Ten en
cuenta que en el modo interactivo no hay un programa principal: las
sentencias se compilan y ejecutan a medida que las introduces. Para
salir de este modo, utiliza el comando "exit" para devolver el
control al shell.

Consulta la ayuda del comando "ego run" para obtener más
información sobre las opciones disponibles para este comando:

    ego run --help

.topic command.server

El comando "ego server" gestiona la ejecución de una instancia de
Ego como servidor RESTful. El servidor se puede utilizar para
ejecutar programas Ego como servicios web, y también para servir
contenido HTML estático.

De forma predeterminada, "ego server" mostrará el estado del
servidor predeterminado (el último servidor en el que se inició
sesión). Puedes especificar subcomandos adicionales al comando
server para examinar el estado de servidores arbitrarios, o para
iniciar, detener o reiniciar un servidor.

Otros subcomandos adicionales permiten gestionar las cuentas de
usuario del servidor, gestionar las cachés internas del servidor y
examinar el registro del servidor y/o habilitar o deshabilitar
clases específicas de registro en el servidor.

Consulta la ayuda de los subcomandos de server mediante:

    ego server --help

.topic command.sql

El comando "ego sql" se utiliza para enviar una o más sentencias
SQL al servidor. El servidor ejecutará las sentencias SQL y
devolverá los resultados al usuario. El comando SQL se puede
utilizar para crear, actualizar o eliminar datos en la base de datos
del servidor, y para consultar información específica en la base de
datos. Los resultados se pueden devolver como texto legible por
humanos o como datos JSON sin procesar.

El comando SQL permite especificar un dsn (nombre de origen de
datos) que identifica la base de datos específica y las credenciales
que se van a utilizar. Consulta la ayuda adicional sobre el comando
SQL mediante:

    ego sql --help

+--------+--------+--------+--------+--------+--------+--------+-------+
.topic command.table

El comando "ego table" se utiliza para gestionar las tablas de la
base de datos del servidor. Este comando se puede utilizar para
crear, actualizar o eliminar tablas en la base de datos del
servidor, y para consultar información específica en la base de
datos. Los resultados se pueden devolver como texto legible por
humanos o como datos JSON sin procesar.

A diferencia del comando "ego sql", el comando "ego tables" tiene
un conjunto más limitado de operaciones para gestionar las tablas de
la base de datos del servidor. Estas equivalen a las operaciones de
la API /table admitidas por el servidor.

Para obtener más información sobre el comando "ego tables",
utiliza:

    ego tables --help

.topic language

El lenguaje Ego es un superconjunto del lenguaje Go, y está
diseñado para ser compatible con Go. Añade tipado dinámico, manejo
de excepciones y otras características al lenguaje Go.

Ego es un lenguaje de scripting, diseñado para usarse en un entorno
REPL o como lenguaje de scripting para aplicaciones pequeñas o
medianas. No está pensado para aplicaciones a gran escala o donde el
rendimiento sea crítico. Es una herramienta útil para prototipar
código.

Además, los programas Ego se pueden ejecutar como servicios web y
usarse para crear aplicaciones web. El lenguaje incluye varios
paquetes que dan soporte a los servicios web, entre ellos el paquete
rest, el paquete sql y el paquete exec.

Para ejecutar un programa, utiliza:

    ego program.ego

Esto ejecutará el programa llamado "program.ego". Si omites la
extensión, se asume ".ego". Si omites el nombre del programa por
completo, Ego se ejecuta en modo REPL (Read-Eval-Print-Loop, bucle
de lectura-evaluación-impresión), en el que puedes introducir
sentencias Ego de forma interactiva.

Puedes obtener más información sobre las características del
lenguaje mediante los temas adicionales que se indican a
continuación.

.topic language.data

Esta sección trata sobre las variables (almacenamiento con nombre
para valores), las constantes (almacenamiento con nombre para
valores que no pueden cambiar) y las expresiones (secuencias de
variables, valores y operadores que dan como resultado un valor
calculado).

.topic language.data.types

El lenguaje Ego admite varios tipos base que expresan un único
valor de algún tipo (string, integer, boolean, etc.). Estos tipos
base pueden ser miembros de tipos complejos formados por arreglos
(listas ordenadas), mapas (pares clave/valor de tipos dinámicos) y
estructuras (pares nombre de campo/valor). Además, el usuario puede
crear tipos basados en los tipos base o complejos, como un tipo que
describa una estructura que registre información sobre un empleado;
este tipo se puede usar para crear instancias de la estructura, etc.

|------------|----------|------------------------------|---------------------------------------------------------|
| int64      | 1573     | -2^63 a 2^63-1               | Un valor entero con signo de 64 bits                    |
|------------|----------|------------------------------|---------------------------------------------------------|
| uint8      | 200      | 0 a 255                      | Un entero sin signo de 8 bits (igual que byte)          |
|------------|----------|------------------------------|---------------------------------------------------------|
| uint16     | 17000    | 0 a 65535                    | Un entero sin signo de 16 bits                          |
|------------|----------|------------------------------|---------------------------------------------------------|
| uint32     | 1553     | 0 a 4294967295               | Un entero sin signo de 32 bits                          |
|------------|----------|------------------------------|---------------------------------------------------------|
| uint       | 12345678 | 0 a 2^64-1                   | Un entero sin signo (de 64 bits en todos los puertos    |
|            |          |                              | actuales)                                               |
|------------|----------|------------------------------|---------------------------------------------------------|
| uint64     | 5505955  | 0 a 18446744073709551615     | Un valor entero sin signo de 64 bits                    |
|------------|----------|------------------------------|---------------------------------------------------------|
| float32    | -3.14    | -1.79e+38 a 1.79e+38         | Un valor de coma flotante de 32 bits                    |
|------------|----------|------------------------------|---------------------------------------------------------|
| float64    | -153.35  | -1.79e+308 a 1.79e+308       | Un valor de coma flotante de 64 bits                    |
|------------|----------|------------------------------|---------------------------------------------------------|
| complex64  | 3+4i     | Partes real e imaginaria en  | Un número complejo con componentes float32              |
|            |          | float32                      |                                                         |
|------------|----------|------------------------------|---------------------------------------------------------|
| complex128 | 3+4i     | Partes real e imaginaria en  | Un número complejo con componentes float64              |
|            |          | float64                      |                                                         |
|------------|----------|------------------------------|---------------------------------------------------------|
| string     | "Andrew" | cualquiera                   | Un valor de cadena formado por caracteres Unicode       |
|------------|----------|------------------------------|---------------------------------------------------------|
| chan       | chan     | cualquiera                   | Un canal, utilizado para comunicar valores entre hilos  |
|------------|----------|------------------------------|---------------------------------------------------------|

Ten en cuenta que los valores de rango numérico mostrados son
aproximados. Los tipos int y uint tienen 64 bits en todos los
puertos actuales de Ego; utiliza la función sizeof() si necesitas
determinar el tamaño real de un valor.

Un valor expresado en un programa Ego tiene un tipo implícito. El
procesador del lenguaje intentará determinar el tipo del valor. En
el caso de los valores booleanos, el valor solo puede ser true o
false. Para los tipos numéricos, el lenguaje distingue entre valores
enteros y de coma flotante. El valor 1573 se interpretará como un
valor int porque no tiene exponente ni parte fraccionaria, pero
-153.35 se interpretará como un valor float64 porque tiene un punto
decimal y una parte fraccionaria. Un valor de cadena entre comillas
dobles (") no puede abarcar varias líneas de texto. Un valor de
cadena entre comillas invertidas () sí puede abarcar varias líneas
de texto si es necesario.

Un literal entero también se puede escribir en binario (0b101),
octal (0o644 o en la forma abreviada con cero inicial 0644), o
hexadecimal (0x41), siguiendo la notación de Go.

Un número seguido inmediatamente de i, sin espacio (3i, 2.5i), es
un literal imaginario: la mitad imaginaria de un número complejo.
Ego convierte automáticamente un número real a complejo cuando es
necesario, pero el proceso inverso siempre requiere una llamada
explícita a real() o imag().

Un valor chan no tiene expresión constante; es un tipo que se
puede usar para crear una variable utilizada para comunicarse entre
hilos. Los canales de Ego no llevan un tipo de elemento: escribe
siempre chan solo, no chan string. Consulta el tema de ayuda sobre
language threads para obtener más información.

.topic language.data.arrays

Un arreglo es una lista ordenada de valores. Es decir, es un conjunto
donde cada valor tiene una posición numérica llamada su índice. El
primer valor de un arreglo tiene un índice de 0; el segundo valor
del arreglo tiene un índice de 1, y así sucesivamente. Un arreglo
tiene un tamaño fijo; una vez creado, no puedes añadir elementos al
arreglo directamente.

Las constantes de arreglo se pueden expresar usando corchetes, que
contienen una lista de valores separados por comas. Los valores
pueden ser cualquier valor válido (tipos base, complejos o
definidos por el usuario). Los valores no tienen que ser del mismo
tipo. Por ejemplo,

    [ 101, 335, 153, 19, -55, 0 ]
    [ 123, "Fred", true, 55.738]


El primer ejemplo es un arreglo de enteros. El valor en la posición
0 es 101. El valor en la posición 1 es 335, y así sucesivamente. El
segundo ejemplo es un arreglo heterogéneo, donde cada valor es de
un tipo distinto. Por ejemplo, el valor en la posición 0 es el
entero 123 y el valor en la posición 1 es la cadena "Fred".

Este tipo de arreglos son arreglos "anónimos", ya que no tienen un
tipo específico para los valores. También puedes especificar un
tipo para el arreglo usando una constante de arreglo tipada. Por
ejemplo,


    a := []int{101, 102, 103}


En este ejemplo se crea un arreglo que solo puede contener valores
int (enteros). Si especificas en la lista de inicialización del
arreglo (o más adelante almacenas en un elemento) un valor que no
sea int, el comportamiento de Ego depende del modo de verificación
de tipos actual:

* dynamic - el arreglo se convierte en un arreglo de "cualquier tipo"
* relaxed - el valor se convierte automáticamente a int, o se
  produce un error en tiempo de ejecución si no se puede convertir
* strict  - se informa un error si el valor no es ya un int

Suponiendo que Ego se ejecuta en modo strict, se esperarían los
siguientes resultados:

    a[1] = 1325    // Funciona
    a[1] = 1325.0  // Falla, debe ser de tipo int

Consulta el tema de ayuda directives.type para saber cómo
controlar este modo.


.topic language.data.structures

Una estructura (llamada struct en el lenguaje Ego) es un conjunto
de pares clave/valor. La clave es un símbolo de Ego, y el valor es
cualquier tipo de valor admitido. Cada clave debe ser única. Los
valores se pueden leer o escribir en la estructura según el nombre
de la clave. Una vez creada una estructura, no se le pueden añadir
nuevas claves directamente. Una constante de estructura se indica
mediante llaves, como en:


    {  Name: "Tom", Age: 53 }


Esta estructura tiene dos miembros, Name y Age. Ten en cuenta que
los nombres de los miembros (las claves del par clave/valor)
distinguen entre mayúsculas y minúsculas. El miembro Name de la
estructura es un valor string, y el miembro Age es un valor int.

Este tipo de estructura se conoce como estructura anónima porque
no tiene un tipo específico, y de hecho todos los campos se
declaran como tipo interface{} para que puedan contener cualquier
valor arbitrario, a menos que la verificación estática de tipos
esté habilitada.

No puedes añadir nuevos campos a esta estructura si ya la creaste
como una constante de estructura con campos. Es decir, no puedes
hacer esto:

    a := { Name: "Bob" }
    a.Age = 43


La segunda línea generará un error porque Age no es un miembro de
la estructura. Existe un caso especial de estructura anónima que
puede tener campos añadidos (o eliminados) dinámicamente. Se trata
de una estructura anónima vacía,

    a := {}
    a.Name = "Fred"
    a.Gender = "M"


A la estructura anónima vacía se le pueden añadir campos
simplemente nombrándolos, y se crean según sea necesario. También
puedes eliminar un campo usando la función delete() en este mismo
tipo de estructura anónima:

    a := {}
    a.Name = "Fred"
    a.Age = 55
    delete(a, "Age")

El nombre de campo que se pasa a delete() debe existir, o se
genera un error.

.topic language.data.maps

Un mapa en el lenguaje Ego funciona igual que en Go. Un mapa se
declara con un tipo de clave y un tipo de valor, y se construye
una tabla hash basada en esa información. Puedes establecer un
valor en el mapa y puedes obtener un valor del mapa.

Puedes crear un mapa asignando un valor a una constante de mapa
vacía. Por ejemplo,

    staff := map[int]string{}


Esto crea un mapa (almacenado en staff) que tiene un valor entero
como clave, y almacena un valor string para cada clave única. Un
mapa solo puede contener una clave con un valor dado; establecer
el valor de la clave una segunda vez simplemente reemplaza el
valor del mapa para esa clave.

También puedes inicializar los valores del mapa usando la
notación {}, como en:


    staff := map[int]string{101:"Jeff", 102:"Susan"}

    staff[103] = "Buddy"
    staff[104] = "Donna"


Esto añade miembros al mapa. Ten en cuenta que la clave debe ser
un valor entero, y el valor debe ser un valor string, porque así
fue declarado el mapa. A diferencia de una variable, un mapa
siempre tiene una definición estática una vez creado y no puede
contener valores de un tipo diferente. Por ejemplo, intentar
almacenar un booleano en el mapa produce un error en tiempo de
ejecución.

    id := 102
    name := staff[id]


Esto usa una variable entera para obtener un valor del mapa. En
este caso, el valor de name será "Susan". Si no hay nada en el
mapa con la clave dada, el valor de la expresión es nil.

Puedes comprobar la existencia de un elemento cuando intentas
leerlo del mapa. En esta notación, el segundo valor devuelto en la
asignación es un booleano que indica si el elemento fue encontrado
o no.

    emp, found := staff[105]


En este ejemplo, found será true si había un valor en el mapa para
la clave 105, y el valor del elemento del mapa (una cadena en este
caso) se almacenará en emp. Si no había ningún valor en el mapa
para la clave dada, found tendrá el valor false, y emp será nil.
(Ten en cuenta que esto es ligeramente distinto del Go tradicional,
donde el resultado sería el valor cero del tipo, es decir, una
cadena vacía en este caso).

Puedes eliminar un miembro de un mapa usando la función delete(),
como en:

    delete(staff, 103)


Esto elimina una entrada del mapa staff con un valor de clave de
103. Si el miembro no existe, no se genera ningún error.

.topic language.data.pointers

El lenguaje Ego adopta los estándares de Go para los punteros. Los
punteros existen únicamente para identificar la dirección de otro
objeto. Esta dirección se puede pasar a través de los límites de
una función para permitir que la función modifique el valor de un
parámetro.

No se permite la aritmética de punteros; un puntero solo se puede
establecer como la dirección de otra variable.

    var x *int                     // (1)

    y := 42
    x = &y                         // (2)

    fmt.Println(*x)                // (3)


En este ejemplo,

1. Se crea una variable x como puntero a un valor entero. Ten en
   cuenta que en Ego (a diferencia de Go), "var x *int" no produce
   un puntero nil, sino que produce el valor cero para int (es
   decir, 0). Para obtener un puntero nil real, devuelve nil
   explícitamente desde una función o asigna nil directamente:
   x = nil.

2. El valor de x ahora se establece en un valor distinto de nil;
   se convierte en la dirección de la variable y. A partir de este
   punto (hasta que el valor de x cambie de nuevo) puedes
   referenciar el valor de y usando el símbolo y, o desreferenciando
   el puntero a y almacenado en x.

3. Esto muestra la desreferenciación del valor del puntero para
   acceder al valor subyacente de 42 como resultado de la
   operación de impresión. Si hubieras impreso el valor x en lugar
   de *x, se imprimiría la cadena &42 para mostrar que el valor
   apunta a 42.

Los ejemplos anteriores ilustran las funciones básicas de un
puntero, pero el caso más común es como valor de retorno de una
función o como parámetro de una función.

    func hasPositive( x int ) *int {
        if x >= 0 {
            return &x
        }
        return nil
    }

    v := hasPositive(55)
    if v == nil {
        fmt.Println("Not positive; no value returned")
    }


En este ejemplo un tanto artificial, la función hasPositive no
devuelve un entero, sino un puntero a un entero. La lógica de la
función es tal que si se proporcionó un valor positivo, este se
devuelve; de lo contrario, se devuelve un valor nil como valor del
puntero, indicando que la función no devolvió ningún valor.

Como ejemplo final, puedes usar punteros para permitir que una
función modifique un valor:

    func setter( destination *int, source int) {
        *destination = source
    }

    x := 55
    setter(&x, 42)
    fmt.Println(x)


En este ejemplo, a la función setter se le proporciona la
dirección de un entero y un valor para almacenar en ese entero.
Como el valor se pasa por puntero, el valor de destination es la
dirección del valor 55. La función setter sobrescribe ese valor
con el parámetro pasado (en este caso, el valor 42). El resultado
es que el valor de x ahora ha sido modificado por la función, y el
valor impreso será "42".

Esta es la única forma en que una función puede cambiar el valor
de un parámetro. Por defecto, se hace una copia de un valor (como
source en el ejemplo anterior), y es esa copia la que se pasa a la
función. Si la función setter hubiera modificado el valor de
source, el valor sería diferente en la copia local de la función,
pero el valor global (42, en este caso) no habría cambiado.

.topic language.data.user-defined

El lenguaje Ego incluye la capacidad de crear tipos definidos por
el usuario. Estos se limitan a definiciones de struct. Permiten
que el programa defina una abreviatura para un tipo específico, y
luego haga referencia a ese tipo al crear una nueva variable de
ese tipo. La sentencia type se usa para definir el tipo. Aquí
tienes un ejemplo:

    type Employee struct {
        Name    string
        Age     int
    }


Esto crea un nuevo tipo llamado Employee, que es un struct con dos
miembros, Name y Age. Una variable creada con este tipo siempre
será una estructura, y siempre contendrá estos dos miembros.
Luego puedes crear una variable de este tipo usando:

    e := Employee{}


El {} indica que se trata de un tipo, y se crea una nueva
estructura (de tipo Employee) que se almacena en la variable e.
Si lo deseas, puedes inicializar los campos de la estructura al
crearla,

    a := Employee{ Name: "Robin" }


En este ejemplo, se crea un nuevo Employee y el campo Name se
inicializa con la cadena "Robin". El valor a también contiene un
campo Age porque este fue declarado en el tipo, pero en este punto
contiene el valor cero de su tipo (en este caso, un entero cero).
Solo puedes inicializar los campos de un tipo que hayan sido
declarados en el tipo original.

.topic language.data.variables

Una variable es una ubicación de almacenamiento con nombre,
identificada por un símbolo. El lenguaje Ego es, por defecto, un
lenguaje que distingue entre mayúsculas y minúsculas, de modo que
las variables Age y age son dos valores diferentes. Los nombres de
símbolo pueden estar formados por letras, números, o el carácter
de guion bajo ("_"). El primer carácter debe ser un guion bajo o
un carácter alfabético. Aquí tienes algunos ejemplos de nombres
válidos e inválidos:


|-----------|-----------------------------------------------------------|
| Nombre    | Descripción                                               |
|-----------|-----------------------------------------------------------|
| a123      | Nombre válido                                             |
|-----------|-----------------------------------------------------------|
| user_name | Nombre válido                                             |
|-----------|-----------------------------------------------------------|
| A123      | Nombre válido, distinto de a123                           |
|-----------|-----------------------------------------------------------|
| _egg      | Nombre válido, pero es una variable de solo lectura       |
|-----------|-----------------------------------------------------------|
| 15States  | Nombre inválido, no comienza con un carácter alfabético   |
|-----------|-----------------------------------------------------------|
| $name     | Nombre inválido, el signo de dólar no es válido en        |
|           | símbolos                                                  |
|-----------|-----------------------------------------------------------|


Existe un nombre reservado que es simplemente un guion bajo, "_".
Este nombre significa "valor que se ignorará". Así que cada vez
que necesites referenciar una variable para cumplir con la
sintaxis del lenguaje, pero no quieras o necesites el valor para
tu programa en particular, puedes especificar "_", que es un
valor abreviado para "descartar este valor".

Un nombre de símbolo que comienza con un carácter de guion bajo es
una variable de solo lectura. Es decir, su valor se puede
establecer una vez cuando se crea, pero no se puede cambiar una
vez que tiene su valor inicial. Por ejemplo, cuando se ejecuta un
programa Ego, siempre existe una variable de solo lectura llamada
_version que se puede leer para determinar la versión de la
herramienta de línea de comandos ego, pero el valor no puede ser
establecido por un programa de usuario.

El término ámbito se refiere al mecanismo mediante el cual un
nombre de símbolo se resuelve en una variable. Cuando se ejecuta
un programa Ego, cada función individual, y de hecho cada bloque
básico (código encerrado entre llaves {...}) tiene su propio
ámbito. Una variable creada en un ámbito es visible para cualquier
ámbito contenido dentro de ese ámbito. Por ejemplo, una variable
creada en la primera línea de una función es visible para todo el
código dentro de la función. Una variable creada dentro de un
bloque básico solo es visible dentro del código de ese bloque
básico. Cuando un ámbito termina, todas las variables creadas en
ese ámbito se eliminan y dejan de tener un valor.

Esto quedará más claro más adelante cuando hablemos de funciones y
bloques básicos. Por ahora, basta con saber que puedes referenciar
(leer o escribir) un valor en cualquier símbolo de tu mismo ámbito
o de un ámbito externo, pero solo puedes crear variables en el
ámbito actual, y una vez que ese ámbito termina, las variables
creadas dejan de existir. A un símbolo se le puede asignar un
valor mediante una sentencia de asignación. Esta consiste en el
nombre de la variable que recibirá el valor, seguido de "=" o
":=", y luego el valor que se almacenará en esa variable. La
diferencia entre los dos operadores de asignación es que := creará
un nuevo valor en el ámbito actual, mientras que = localizará un
valor que ya existe y le escribirá un nuevo valor.

    name := "Bob"
    name = "Mary"


En este ejemplo, la primera sentencia usa el operador :=, que hace
que se cree el símbolo name, y luego se almacena el valor de
cadena "Bob" en la variable. Si la variable ya existe, esto es un
error y deberías usar = en su lugar para actualizar un valor
existente. El operador = busca el valor con ese nombre en el
ámbito actual, y si lo encuentra, le asigna el valor "Mary". Si la
variable no existe en este ámbito, pero sí en un nivel de ámbito
externo, entonces se actualiza la variable de ese ámbito externo.

Ego también admite la asignación paralela al estilo de Go, donde
se asigna más de una variable en una sola sentencia usando una
lista de destinos separados por comas a la izquierda y una lista
correspondiente de valores separados por comas a la derecha. Se
admiten tanto = como :=:

    var a, b, c int

    a, b, c = 10, 20, 30
    x, y, z := 1, 2, 3

Todos los valores de la derecha se evalúan primero, antes de que
ocurra cualquiera de las asignaciones, lo que hace que esta sea
una forma conveniente de intercambiar valores sin usar una
variable temporal:

    a, b := 1, 2
    a, b = b, a       // ahora a vale 2, b vale 1

El número de valores a la derecha debe coincidir exactamente con
el número de destinos a la izquierda. Como con cualquier
asignación, se puede usar _ para un destino cuyo valor no
necesitas. Esta forma también cubre la captura de todos los
valores devueltos por una función de valores múltiples, y la forma
de dos valores de una recepción de canal:

    lo, hi := minMax(data)     // retorno de función con múltiples valores
    v, ok := <-ch              // recepción de canal con dos valores

Ten en cuenta que Ego permite un atajo para una sentencia de
asignación específica que suma o resta la constante 1 a un valor.
Por ejemplo:

    i = i + 1
    i++


Estas sentencias tienen la misma función. Requieren que la
variable i ya exista, y se le suma el valor 1 a i. Lo mismo se
puede hacer usando el operador -- para restar uno a un valor.
Esto se usa comúnmente en los bucles for, que se explican más
adelante.

Si las extensiones del lenguaje Ego están habilitadas, los
operadores ++ y -- se pueden usar como valor dentro de una
expresión. Por ejemplo, considera este código:

    i := 10
    j := 5 + i++


Esto tiene el efecto de establecer j en el valor 15, y establecer
i en el valor 11. Es decir, la operación de incremento ++ se
realiza sobre la variable i después de que su valor se lee en la
operación de suma que establece el valor de j.

    t := i
    i = i + 1
    j := 5 + t


El código anterior tiene el mismo efecto que la segunda sentencia
en el ejemplo de valor de expresión con autoincremento anterior.
Usar la operación de autoincremento (o autodecremento) evita la
necesidad de almacenar el valor previo al incremento en una
variable temporal, y reduce el desorden del código.

Ego también admite operadores implícitos en la asignación, usando
los operadores de asignación +=, -=, *= y /=. Cada uno de ellos
realiza una asignación que incluye la operación indicada (suma,
resta, multiplicación o división) con el valor que sigue al
carácter =. Por ejemplo,

    i := 10
    i += 5


El uso del operador += requiere que el valor a la izquierda de la
asignación ya exista. En este ejemplo, al valor de i se le suma la
constante 5. Esto es lo mismo que i = i + 5, pero es más fácil de
leer.

También puedes crear una variable usando la sentencia var, que va
seguida de una lista de nombres separados por comas y finalmente
un valor de tipo. Todas las variables se crean y se establecen con
el tipo indicado, con un "valor cero" apropiado para ese tipo.

    var first, last string
    var e1 Employee

El segundo ejemplo declara una variable e1 del tipo definido por
el usuario Employee, establecida en su valor cero. Para crear una
instancia inicializada, usa := con el nombre del tipo y llaves en
su lugar:

    e1 := Employee{}
    e2 := Employee{ Name: "Bob", Age: 55}

El tipo de e2 es Employee y contiene valores inicializados para
los campos permitidos de ese tipo. Si el inicializador no
especifica un valor para todos los campos, los campos no nombrados
explícitamente se establecen en el valor cero de su tipo.

Una declaración var también puede proporcionar un valor inicial en
lugar de obtener el valor cero del tipo, ya sea indicando el tipo
explícitamente o dejando que Ego lo infiera a partir del valor
proporcionado:

    var age int = 25       // tipo explícito
    var pi = 3.14          // tipo inferido a partir del valor (float64)

Si más de un nombre comparte un único inicializador (var a, b =
42), cada nombre se establece con una copia de ese único valor.
Alternativamente, una declaración var puede proporcionar una lista
de inicializadores separados por comas, un valor por nombre,
exactamente igual que en la asignación paralela:

    var a, b, c = 10, "hello", true   // tipo inferido por separado
    var x, y, z int = 1, 2, 3         // tipo explícito compartido

Varias declaraciones var se pueden agrupar dentro de paréntesis,
evitando la necesidad de repetir la palabra clave var en cada
línea:

    var (
        greeting = "hi"          // tipo inferido (string)
        count    int             // valor cero (0)
        rate     float64 = 1.5   // tipo explícito con valor inicial
    )

.topic language.data.constants

La sentencia const puede definir valores constantes en el ámbito
actual. Estos valores son siempre de solo lectura y no puedes usar
el nombre de una constante como nombre de variable. Puedes
especificar una sola constante o un grupo de ellas; para
especificar más de una en una sola sentencia, encierra la lista
entre paréntesis:


    const answer = 42

    const (
        first = "a"
        last = "z"
    )


Esto define tres valores constantes. Ten en cuenta que el valor se
establece usando el carácter =, ya que en realidad no se está
creando un símbolo.

Dentro de un grupo const (...) entre paréntesis, el identificador
predeclarado iota representa un contador que comienza en 0 para la
primera constante del grupo y aumenta en uno para cada constante
posterior. Cualquier entrada sin su propia "= expr" repite la
expresión de la entrada más cercana por encima de ella que sí
tenía una, de modo que el contador sigue avanzando aunque iota
solo se escriba una vez:

    const (
        Sunday = iota // 0
        Monday        // 1
        Tuesday       // 2
    )

iota también puede aparecer como parte de una expresión más
grande, y es esa expresión la que se repite para cada entrada
siguiente:

    const (
        _  = iota             // se omite el 0
        KB = 1 << (10 * iota) // 1 << 10 == 1024
        MB                    // 1 << 20 == 1.048.576
    )

iota solo tiene sentido dentro de una declaración const; cada
declaración const independiente obtiene su propio contador que
comienza de nuevo en 0.

.topic language.data.expressions

Operadores es el término para los elementos del lenguaje que te
permiten realizar operaciones matemáticas u otras operaciones
usando tanto valores constantes como valores de variables, para
producir un nuevo valor calculado. Algunos operadores pueden
operar sobre una amplia gama de tipos de valores diferentes, y
otros operadores tienen una funcionalidad más limitada.

Existen operadores de desreferenciación que se usan para acceder
a los miembros de una estructura, a los valores de un tipo, o
para indexar un arreglo.


+----------+----------+----------------------------------------------------|
| Operador | Ejemplo  | Descripción                                        |
+----------+----------+----------------------------------------------------|
| .        | emp.age  | Encuentra el miembro llamado age en la estructura  |
|          |          | emp                                                |
+----------+----------+----------------------------------------------------|
| []       | items[5] | Encuentra el valor en el índice 5 del arreglo items|
+----------+----------+----------------------------------------------------|
| {}       | emp{}    | Crea una instancia de una estructura del tipo emp  |
+----------+----------+----------------------------------------------------|

El operador [] también se puede usar para acceder a un mapa,
proporcionando el valor de la clave entre corchetes. Este valor de
clave debe ser del mismo tipo que el tipo de clave declarado del
mapa. Así que si el mapa se declara como map[string]int, entonces
la clave debe ser de tipo string.


Existen operadores monádicos que preceden a una expresión y operan
sobre el único valor dado.



+----------+----------+----------------------------------------------------|
| Operador | Ejemplo  | Descripción                                        |
+----------+----------+----------------------------------------------------|
| -        | -temp    | Calcula el negativo del valor en temp              |
+----------+----------+----------------------------------------------------|
| !        | !active  | Calcula la negación booleana (NOT) del valor en    |
|          |          | active                                             |
+----------+----------+----------------------------------------------------|



Existen operadores diádicos que operan sobre dos valores, uno de
los cuales precede al operador y el otro lo sigue.



+----------+----------+----------------------------------------------------|
| Operador | Ejemplo  | Descripción                                        |
+----------+----------+----------------------------------------------------|
| +        | a+b      | Calcula la suma de valores numéricos, el AND de    |
|          |          | dos valores booleanos, o concatena cadenas         |
+----------+----------+----------------------------------------------------|
| -        | a-b      | Calcula la diferencia de los valores numéricos     |
+----------+----------+----------------------------------------------------|
| *        | a*b      | Calcula el producto de los valores numéricos, o el |
|          |          | OR de dos valores booleanos                        |
+----------+----------+----------------------------------------------------|
| /        | a/b      | Calcula la división de los valores numéricos       |
+----------+----------+----------------------------------------------------|
| %        | a%b      | Calcula el resto de la operación de división       |
+----------+----------+----------------------------------------------------|
| ^        | 2^n      | Calcula 2 elevado a la potencia n                  |
+----------+----------+----------------------------------------------------|
| &        | a&b      | AND a nivel de bits de dos valores enteros         |
+----------+----------+----------------------------------------------------|
| |        | a|b      | OR a nivel de bits de dos valores enteros          |
+----------+----------+----------------------------------------------------|
| <<       | a<<n     | Desplaza a hacia la izquierda n bits (n debe ser >=|
|          |          | 0)                                                 |
+----------+----------+----------------------------------------------------|
| >>       | a>>n     | Desplaza a hacia la derecha n bits (n debe ser >=  |
|          |          | 0)                                                 |
+----------+----------+----------------------------------------------------|
| &&       | a&&b     | AND lógico de dos booleanos (cortocircuito)        |
+----------+----------+----------------------------------------------------|
| ||       | a||b     | OR lógico de dos booleanos (cortocircuito)         |
+----------+----------+----------------------------------------------------|

Ten en cuenta que aplicar + a dos valores booleanos devuelve su
AND lógico, y aplicar * a dos valores booleanos devuelve su OR
lógico. Esto es contraintuitivo; se prefiere usar && y || para la
lógica booleana.

Para la división, los valores enteros producirán el valor entero
de la división, así que 10/3 dará como resultado 3 como valor de
la expresión. Un valor de coma flotante conserva la parte
fraccionaria de la conversión, así que 10.0/3.0 da como resultado
3.333333333.

El operador de módulo solo es válido para tipos enteros, y el
divisor no puede ser cero. La cantidad de desplazamiento para <<
y >> debe ser no negativa; desplazar por una cantidad negativa es
un error en tiempo de ejecución.

Las expresiones se pueden combinar entre sí, y siguen el orden
habitual de precedencia matemática (la multiplicación y la
división se realizan antes que la resta y la suma). Así, la
expresión a+b*c primero multiplicará b y c, y luego sumará el
producto al valor de a. Puedes usar paréntesis para controlar el
orden de evaluación, de modo que (a+b)*c calculará la suma de a+b
y luego multiplicará ese resultado por el valor de c.


Existen operadores relacionales que operan sobre dos valores, uno
de los cuales precede al operador y el otro lo sigue. El resultado
del operador es siempre un valor booleano (true o false) que
describe la relación entre los dos valores.


+----------+------------+--------------------------------------------------+
| Operador | Ejemplo    | Descripción                                      |
+----------+------------+--------------------------------------------------+
| ==       | a == b     | Verdadero si a es igual a b                      |
+----------+------------+--------------------------------------------------+
| !=       | a != b     | Verdadero si a es distinto de b                  |
+----------+------------+--------------------------------------------------+
| >        | a > b      | Verdadero si a es mayor que b                    |
+----------+------------+--------------------------------------------------+
| >=       | a >= b     | Verdadero si a es mayor o igual que b            |
+----------+------------+--------------------------------------------------+
| <        | a < b      | Verdadero si a es menor que b                    |
+----------+------------+--------------------------------------------------+
| <=       | a <= b     | Verdadero si a es menor o igual que b            |
+----------+------------+--------------------------------------------------+

Existen tipos adicionales de expresiones que solo se habilitan
cuando se permiten las extensiones del compilador: las expresiones
opcionales y las expresiones condicionales.

Una expresión opcional es una expresión que, si al calcularla
produce un error, se reemplaza en su lugar por un valor
predeterminado:

    x := 0
    y := ?(15/x):-1

El carácter ? indica que el siguiente término o subexpresión es
opcional. Si al calcularlo se produce un error, se usa en su lugar
el valor que sigue a los dos puntos; aquí y se convierte en -1
porque la división entre cero falló.

Una expresión condicional evalúa una expresión booleana y, según
si es verdadera o falsa, determina cuál de dos valores se usa:

    wage := 22.50
    hours := 40
    pay := if hours >= 0 {wage * hours} else {wage}

Este valor de expresión condicional puede formar parte de una
expresión más grande, como:

    x := "got a " + if wasCorrect { "true" } else { "false" } + " answer"
.topic language.data.conversion

Cuando se realiza una operación entre dos valores (ya sea una variable
o un valor constante) del mismo tipo, no se realiza ni se requiere
ninguna conversión adicional. Si la operación se realiza entre dos
valores de tipos diferentes, Ego convertirá los valores al mismo tipo
si es posible antes de realizar la operación. Por ejemplo, la
expresión 10.0/3 divide un valor entero entre un valor de coma
flotante; el lenguaje Ego convierte el entero a un valor de coma
flotante antes de realizar la división. En general, Ego convertirá
los valores al tipo que produzca la mínima pérdida de precisión, o
ninguna.

Estas conversiones ocurren automáticamente, aunque puedes usar
funciones de conversión de tipo como int() o string(), que se
explican más adelante, para forzar un tipo específico de conversión.
Por ejemplo, si se usa un valor booleano en una expresión que
requiere un valor float64, el booleano se convierte de modo que
false se convierte en 0.0 y true se convierte en 1.0. De forma
similar, si se necesita un valor numérico o booleano como cadena,
el valor de cadena es la versión formateada del valor original. Así,
un valor de 123.5 como float64 se convierte en la cadena "123.5".

.topic language.data.casting

Esto se refiere a las funciones utilizadas para cambiar
explícitamente el tipo de un valor, o convertirlo en un valor
comparable cuando sea posible. Esto puede hacerse tanto para valores
de tipos base (int, bool, string) como para arreglos.

Para los tipos base, están disponibles las siguientes funciones:


+--------------+------------------+----------------------------------------------+
| Función      | Ejemplo          | Descripción                                  |
+--------------+------------------+----------------------------------------------+
| bool()       | bool(55)         | Convertir a booleano; cero/distinto de cero  |
| byte()       | byte(65)         | Convertir a un entero de 8 bits              |
| int16()      | int16(25434)     | Convertir a un entero de 16 bits             |
| int32()      | int32(4096)      | Convertir a un entero de 32 bits             |
| int()        | int(78.3)        | Convertir a un entero, en este caso 78       |
| int64()      | int64(2^20)      | Convertir a un entero de 64 bits             |
| uint8()      | uint8(240)       | Convertir a un entero sin signo de 8 bits    |
| uint16()     | uint16(40000)    | Convertir a un entero sin signo de 16 bits   |
| uint32()     | uint32(2503)     | Convertir a un entero sin signo de 32 bits   |
| uint()       | uint(240)        | Convertir a un entero sin signo de tamaño    |
|              |                  | predeterminado                               |
| uint64()     | uint64(12071957) | Convertir a un entero sin signo de 64 bits   |
| float32()    | float32(33)      | Convertir a un valor de coma flotante de 32  |
|              |                  | bits                                         |
| float64()    | float64(33)      | Convertir a un valor de coma flotante de 64  |
|              |                  | bits                                         |
| complex64()  | complex64(3)     | Convertir un número real a complejo, p. ej.  |
|              |                  | 3+0i                                         |
| complex128() | complex128(3)    | Convertir un número real a complejo, p. ej.  |

| string()     | string(true)     | Convertir el argumento a un valor de cadena  |
+--------------+------------------+----------------------------------------------+


Una nota especial sobre string(): tiene una característica según la
cual, si el valor pasado es un arreglo de valores enteros, cada uno
se trata como un valor de rune Unicode y la cadena resultante es el
valor devuelto. Cualquier otro tipo simplemente se convierte a su
valor formateado predeterminado.

Ten en cuenta que string(int) en Ego se convierte a la representación
decimal en cadena del entero, no al carácter Unicode de ese punto de
código, a diferencia de Go, donde string(65) produce "A". En Ego,
string(65) produce "65". Usa string([]int{65}) para convertir un
único punto de código a su carácter Unicode.

También puedes realizar conversiones sobre arreglos, en un grado
limitado. Esto se hace con las siguientes funciones:

+-------------+----------------------------+------------------------------------------------+
| Función     | Ejemplo                    | Descripción                                    |
+-------------+----------------------------+------------------------------------------------+
| []bool()    | []bool([1, 5, 0])          | Convertir el arreglo en un arreglo []bool      |
| []int()     | []int([1, 5.5, 0])         | Convertir a []int.                             |
| []any()     | []any([true, 5, "string"]) | Convertir a []any, sin tipo de elemento        |
|             |                            | estático                                       |
| []float64() | []float64([1, 5, 0])       | Convertir el arreglo en un arreglo []float64   |
| []float32() | []float32([1, 5, 0])       | Convertir el arreglo en un arreglo []float32   |
| []string()  | []string([1, 5, 0])        | Convertir el arreglo en un arreglo []string    |
+-------------+----------------------------+------------------------------------------------+


En todos los casos, el resultado es un arreglo tipado del tipo de
conversión indicado. Cada elemento del arreglo se convierte al tipo
de destino y se almacena en el arreglo. Así, []bool() sobre un arreglo
de enteros produce un arreglo de valores bool, donde los ceros se
convierten en false y cualquier otro valor se convierte en true. El
nombre de tipo especial any significa que no se especifica un tipo y
se usa para arreglos con valores heterogéneos.

Ten en cuenta el caso especial de []int("string"). Si el parámetro
no es un arreglo sino un valor de cadena, el arreglo []int resultante
contiene cada rune de la cadena original.

.topic language.data.make

La pseudofunción make se utiliza para asignar un arreglo, un mapa o
un canal con capacidad para contener varios mensajes. El primer
argumento debe ser una especificación de tipo de dato, y el segundo
argumento es el tamaño del elemento (elementos del arreglo o mensajes
del canal); para un tipo mapa, el tamaño es opcional.

    a := make([]int, 5)
    m := make(map[string]int)
    b := make(chan, 10)


El primer ejemplo crea un arreglo de 5 elementos, cada uno de tipo
int, inicializados con el valor cero del tipo indicado. Esto podría
haberse hecho con la sentencia a := [0,0,0,0,0], pero usando la
función make() puedes especificar el número de elementos de forma
dinámica en tiempo de ejecución.

El segundo ejemplo crea un mapa con clave de tipo string y valor de
tipo int. El argumento opcional de tamaño existe por compatibilidad
con Go; actualmente Ego lo ignora.

El tercer ejemplo crea un objeto canal capaz de contener hasta 10
mensajes. Crear un canal así es necesario si el canal se comparte
entre varios hilos. Si una variable de canal se declara por defecto,
solo contiene un único mensaje. Esto significa que, antes de que un
hilo pueda enviar un valor, otro hilo debe leer ese valor; si hay
varios hilos esperando para enviar, en la práctica se ejecutan de uno
en uno. Al crear un canal que puede contener varios mensajes, hasta
10 (en el ejemplo anterior) hilos podrían enviar un mensaje al canal
antes de que se leyera el primer mensaje.

.topic language.data.assertions

Cuando un valor se almacena en una variable de tipo any, Ego recuerda
el tipo concreto del valor junto con el propio valor. Una aserción de
tipo (a veces llamada "desenvolver" la interfaz) te permite preguntar,
en tiempo de ejecución, si ese valor almacenado realmente contiene un
valor de un tipo específico, y recuperarlo como ese tipo: x.(T). Esto
no es una conversión de tipo: no se realiza ninguna coerción, sino que
simplemente confirma el tipo concreto o falla.

La forma de dos valores (la forma "comma-ok") es la manera segura de
comprobar el tipo de un valor sin arriesgarse a un error en tiempo de
ejecución:

    var x any = 42
    n, ok := x.(int)
    if ok {
        fmt.Println("x is an int:", n)
    }

La forma de un solo valor (value := x.(T)) genera un error de tiempo
de ejecución capturable si la aserción falla, igual que una división
entre cero:

    try {
        m := y.(int)
    } catch(e) {
        fmt.Println("assertion failed:", e)
    }

Escribe la forma de un solo valor como su propia sentencia de
asignación independiente; usarla en línea como parte de una expresión
más grande no está totalmente admitido.

Cualquier nombre de tipo base es un objetivo válido para una
aserción, y afirmar hacia any (o interface{}) siempre tiene éxito, ya
que todo valor lo satisface. Un tipo estructura (o un puntero a una),
un slice, un mapa o un tipo arreglo, e incluso un tipo función,
también pueden ser objetivos de aserción:

    f, ok := v.(func(int, int) int)

La sentencia switch tiene una forma especial, switch v := x.(type),
que te permite bifurcar según el tipo concreto de x directamente, sin
tener que escribir una cadena de aserciones individuales. Consulta el
tema de ayuda language.switch para más detalles.

.topic language.conditional

La naturaleza general de una sentencia condicional if es la
siguiente:

     if <condition> {
         <statements>
     } else {
         <statements>
     }


La cláusula else es opcional, como se describe más adelante. Incluso
cuando solo hay una única sentencia en el bloque, se utiliza un
bloque básico por motivos de legibilidad.

Considera el siguiente código de ejemplo:


    salary := hours * wage                  // (1)
    if salary < 100.0 {                     // (2)
      fmt.Println("Not paid enough!")       // (3)
    }                                       // (4)

    total = total + salary                  // (5)


Esto introduce varios elementos nuevos en un programa, así que
vamos a repasarlos línea por línea. Los números entre paréntesis no
forman parte del programa, sino que se usan para identificar cada
línea del código.

1. Esta primera línea calcula un nuevo valor multiplicando las horas
   por el salario, y lo almacena en un nuevo valor llamado salary.
   Esto utiliza una sentencia de asignación; el := indica que la
   variable aún no existe y se creará mediante esta operación.
   Suponemos que los valores de hours y wage ya se calcularon
   previamente en el programa.

2. Esta sentencia realiza una evaluación condicional. Después de la
   sentencia if hay una expresión relacional que puede convertirse en
   un valor booleano. En este caso, si salary tiene un valor menor
   que 100.0, entonces el código ejecutará alguna(s) sentencia(s)
   adicional(es). Después de la expresión, el carácter { define el
   inicio de un bloque básico, que es un grupo de sentencias que se
   ejecutan todas juntas.

3. Si salary es menor que 100.0, se ejecuta la operación
   fmt.Println(). No te preocupes por no haber hablado de esto
   todavía; se explica más adelante en la sección sobre el paquete
   fmt, pero por ahora basta con saber que esto produce una línea de
   salida con la cadena Not paid enough!. Si, en cambio, el valor de
   salary no es menor que 100.0, el bloque básico no se ejecuta, y el
   programa continúa con la sentencia posterior al bloque.

4. El carácter } define el final del bloque básico. Si no se cumple
   la condición de la sentencia if, la ejecución continúa después de
   este indicador de fin de bloque.

5. Esta sentencia se ejecutará a continuación, independientemente de
   si salary era menor que 100.0 o no. Esta sentencia actualiza el
   valor de total para que sea la suma de total y salary.

En lugar de que la sentencia if avance a la siguiente sentencia
cuando la condición no es verdadera, se puede definir un segundo
bloque básico con las sentencias que se ejecutan si la condición es
falsa. Es decir, el resultado de la expresión hará que se ejecute uno
u otro de los dos bloques básicos.

    salary := hours * wage
    if salary < 100 {
        scale = "small"
    } else {
        scale = "large"
    }


En este ejemplo, después de calcular un valor para salary, se
compara para ver si es menor que 100. Si es así, el valor scale se
establece en "small". Pero si el valor de salary no es menor que
100, el valor de scale se establece en "large". Independientemente
de cuál de los dos bloques básicos se haya ejecutado, al finalizar el
bloque el programa continúa con la siguiente sentencia después de la
sentencia if.

.topic language.switch

Una sentencia switch selecciona uno de varios bloques para ejecutar
según el valor de una expresión: una alternativa más concisa que una
cadena de sentencias if/else if/else. No hay "fall-through" (caída
continua) entre los casos, a diferencia de lenguajes como C.

    switch <expression> {
    case <value1>:
        <statements>
    case <value2>, <value3>:
        <statements>
    default:
        <statements>
    }

    day := "Saturday"
    switch day {
    case "Saturday":
        fmt.Println("Weekend")
    case "Sunday":
        fmt.Println("Weekend")
    default:
        fmt.Println("Weekday")
    }

Puedes ejecutar una expresión inicializadora cuyo resultado queda
disponible dentro del bloque switch y (si omites la expresión
siguiente) se usa automáticamente como el valor del switch:

    switch x := f(); x {
    case 1:
        ...
    }

Una sentencia switch escrita sin ninguna expresión hace que cada
case proporcione una condición booleana; se selecciona el primer
case que sea verdadero. Esta forma es equivalente a una cadena de
sentencias if/else if:

    switch {
    case score >= 90:
        fmt.Println("A")
    case score >= 80:
        fmt.Println("B")
    default:
        fmt.Println("F")
    }

Un switch también puede bifurcar según el tipo concreto de un valor
de tipo any, usando switch v := x.(type) { ... }. Consulta el tema
de ayuda language.data.assertions para más detalles.

Como un case coincidente nunca continúa hacia el siguiente (no hay
fall-through), no es necesario usar break solo para evitar que un
case pase al siguiente. Una sentencia break dentro de un switch solo
finaliza el propio switch; si el switch está dentro de un bucle for,
break no sale del bucle. Para finalizar un bucle que envuelve al
switch desde dentro de este, etiqueta el bucle y usa esa etiqueta en
la sentencia break; consulta el tema de ayuda language.break-continue.

.topic language.for

La sentencia "for" se utiliza para crear un bucle que se ejecutará
mientras una condición sea verdadera. Esto puede expresarse como una
condición simple, un índice o un range.

.topic language.for.condition

La forma más simple de ejecución iterativa (también llamada "bucle")
es la sentencia for, seguida de una condición y un bloque básico que
se ejecuta mientras la condición sea verdadera.

    for <condition> {
    <statements>
    }


Aquí tienes un ejemplo

    value := 0                  // (1)
    for value < 5 {             // (2)
        fmt.Println(value)      // (3)
        value = value + 1       // (4)
    }                           // (5)


1. Esta línea inicializa la variable value con el entero cero.
2. La sentencia for especifica que, mientras la variable
   value contenga un número menor que 5, el siguiente bloque básico
   se ejecutará una y otra vez.
3. Esta línea del bloque básico imprime el valor actual
4. Esta línea incrementa la variable sumándole uno a sí misma.
   Esto hace que value aumente cada vez que se ejecuta el bucle.
5. Este es el final del bloque básico que describe el cuerpo del
   bucle, que se ejecutará hasta que la condición deje de ser
   verdadera.

Este programa hace que se impriman los números del 0 al 4 en la
salida. Cuando value se incrementa hasta el valor 5, la condición de
la línea nº2 deja de ser verdadera, el bucle deja de ejecutarse, y el
programa continúa con lo que sigue después de la línea 5.

Ten en cuenta que, en este ejemplo, sin la línea número 4 el
programa se ejecutaría eternamente, porque la variable value se
inicializaría en cero pero nunca cambiaría, por lo que la condición
sería siempre verdadera.

.topic language.for.index

Puedes crear un bucle for que especifique explícitamente una
expresión que defina el valor inicial, la condición de finalización
y cómo cambia el valor en cada iteración del bucle. Por ejemplo,

    for i := 0; i < 10; i++ {
        fmt.Println(i)
    }


Este bucle imprimirá los valores del 0 al 9 en la consola estándar.
La variable índice i se inicializa primero con el valor 0 en la
primera cláusula de la sentencia for. La segunda cláusula describe
la condición que debe ser verdadera para que se ejecute el cuerpo
del bucle. Esta se evalúa antes de ejecutar el cuerpo del bucle en
cada iteración. La tercera cláusula es la sentencia que modifica el
valor del índice después de que se ejecuta el cuerpo del bucle, pero
antes de la siguiente evaluación de la cláusula que determina si el
bucle continúa. En este ejemplo, podríamos haber usado:

    for i := 0; i < 10; i = i + 1 {
        fmt.Println(i)
    }


pero el uso del operador de incremento ++ expresa mejor la operación
deseada ("sumar uno a este valor").

La variable i del ejemplo anterior tiene su ámbito limitado a la
sentencia for y al cuerpo del bucle. Es decir, una vez que el bucle
termina de ejecutarse, la variable i deja de existir porque se creó
(usando el operador :=) dentro del ámbito del bucle. Puedes usar una
asignación simple (=) de una variable ya existente si quieres que el
valor actualizado del índice esté disponible después de que termine
el cuerpo del bucle.

    var i int
    for i = 0; i < 10; i++ {
        fmt.Println(i)
    }

    fmt.Println("The final value of i is ", i)


Este ejemplo usa una variable que ya existe fuera del ámbito del
bucle for, de modo que el valor sigue existiendo después de que el
bucle termina. Esto permite que la sentencia final imprima el valor
de la variable índice que finalizó el bucle.

.topic language.for.range

Puedes crear un bucle que recorra todos los valores de un arreglo,
en orden secuencial. El valor del índice es el valor del elemento del
arreglo. Por ejemplo,


    ids := [ 101, 143, 202, 17]
    for i, j := range ids {
        fmt.Println("Array member ", i, " is ", j)
    }


Este ejemplo imprimirá una línea por cada valor del arreglo, en el
orden en que aparecen en el arreglo. En cada iteración del bucle, la
variable i contendrá el índice numérico del arreglo, y la variable j
contendrá los valores reales del arreglo en cada iteración del cuerpo
del bucle. Durante la ejecución del cuerpo del bucle, el valor de i
(la variable índice) contiene el siguiente valor del arreglo en cada
iteración del bucle. También puedes especificar un segundo valor, en
cuyo caso el bucle define tanto un número de índice como un valor de
índice, como en:

    for _, v := range ids {
        fmt.Println(v)
    }


En este ejemplo, en cada iteración del bucle, la variable v
contendrá los valores reales del arreglo en cada iteración del
cuerpo del bucle. Al usar el nombre reservado _ para la variable
índice, el valor del índice no está disponible en cada iteración.
De forma similar, puedes usar range para obtener todos los valores
de índice de un arreglo:

    for i := range ids {
        fmt.Println(ids[i])
    }


En este caso, si el arreglo ids tiene 4 valores, entonces i toma los
valores 0, 1, 2 y 3. El valor del arreglo se puede acceder dentro del
cuerpo del bucle como ids[i].

De forma similar, puedes usar la construcción range para recorrer
los valores de un tipo de dato mapa. Por ejemplo,

    inventory := map[string]int{}
    inventory["wrenches"] = 5
    inventory["pliers"] = 12
    inventory["hammers"] = 2

    for product, count := range inventory {
        fmt.Println("There are ", count, " ", product, " in stock.")
    }


Cuando se ejecuta el bucle, el valor de product se establece en
cada clave del mapa, y count se establece en el valor asociado a esa
clave. Estas variables existen únicamente dentro del cuerpo del
bucle. Ten en cuenta que si omites cualquiera de las dos y usas la
variable _ en su lugar, ese elemento (clave o valor) no se lee del
mapa. Puedes usar esto para generar una lista de las claves, por
ejemplo:

    names := []string{}
    for name := range inventory {
        names = names + name
    }

    fmt.Println("The products are all named", names)


Esto crea un arreglo de valores string y almacena el nombre de cada
clave en la lista, agregándolos uno a uno.

También puedes usar range para recorrer los caracteres de un valor
string. La variable índice recibe el desplazamiento en bytes de cada
carácter dentro de la cadena (no un simple conteo 0, 1, 2, ...), y la
variable de valor recibe el punto de código Unicode decodificado como
un int32, no como una cadena de un solo carácter:

    for i, ch := range "Hi!" {
        fmt.Printf("i=%d, ch=%v, type=%T\n", i, ch, ch)
    }

El índice puede saltar más de una posición entre iteraciones si un
carácter se codifica con más de un byte en UTF-8. Si necesitas el
carácter como una cadena de un solo carácter en lugar de su punto de
código entero, conviértelo explícitamente con string([]int32{ch}).

.topic language.break-continue

A veces, al ejecutar un bucle, es posible que quieras cambiar el
flujo de ejecución del bucle según condiciones no relacionadas con
la variable índice. Por ejemplo, considera:

    for i := 1; i < 10; i = i + 1 {
        if i == 5 {                      // (1)
            continue                     // (2)
        }

        if i == 7 {                      // (3)
            break                        // (4)
        }

        fmt.Println("The value is ", i)  // (5)
    }


Este bucle imprimirá los valores 1, 2, 3, 4 y 6. Esto es lo que hace
cada sentencia:

1. En cada ejecución del cuerpo del bucle, el valor del índice se
   compara con 5. Si es igual a 5 (usando el operador ==), se
   ejecuta la sentencia condicional.
2. La sentencia continue hace que el control regrese al inicio del
   bucle. El valor del índice se incrementa y luego se comprueba de
   nuevo para ver si el bucle debe ejecutarse otra vez. La sentencia
   continue significa "deja de ejecutar el resto de este cuerpo del
   bucle, pero continúa iterando".
3. De forma similar, el índice se compara con 7, y si es igual a 7
   se ejecuta la sentencia condicional.
4. La sentencia break sale del bucle por completo. Significa "sin
   cambiar ninguno de los valores, comportarse como si se hubiera
   cumplido la condición del bucle y reanudar la ejecución después
   del cuerpo del bucle.

Ten en cuenta que si creas un bucle for sin condición, índice ni
valor range, el cuerpo del bucle debe contener al menos una
sentencia break. Si no hay ninguna sentencia break, el bucle nunca
terminaría.

Opcionalmente, puedes especificar una etiqueta en la sentencia break
o continue. Una sentencia simple opera sobre el bucle más interno,
pero con una etiqueta puedes desenrollar bucles externos antes de
finalizar o continuar el bucle que tiene ese nombre. Las etiquetas de
sentencia solo pueden usarse antes de una sentencia for:

    outer:
    for i := 0; i < 5; i++ {
        for j := 0; j < 5; j++ {
            if j == 2 {
                continue outer
            }
            if i == 3 {
                break outer
            }
        }
    }
.topic language.functions

Además de las funciones incorporadas que aparecen bajo "language
builtins", el programa del usuario puede crear funciones que se
pueden ejecutar desde el programa Ego. Igual que las variables,
las funciones tienen ámbito, y solo se puede acceder a ellas desde
dentro del programa en el que se declaran. La mayoría de las
funciones se definen en el archivo del programa antes del cuerpo
del programa.

.topic language.functions.declaration

Utiliza la sentencia func para declarar una función. La función
debe tener un nombre, opcionalmente una lista de valores de
parámetro que se le pasan, y un tipo de retorno que indica qué se
espera que la función devuelva. A esto le sigue el cuerpo de la
función, descrito como un bloque básico. Cuando se llama a la
función, este bloque se ejecuta, con los argumentos de la función
disponibles como variables locales. Por ejemplo,

    func addValues( v1 float64, v2 float64) float64 {
        x := v1 + v2

        return x
    }

    // Calcula el resultado de sumar el valor de una variable (10.5) a 3.8
    a := 10.5
    x := addValues(a, 3.8)
    fmt.Println("The sum is ", x)


En este ejemplo se crea la función addValues. Acepta dos
parámetros; en este ejemplo, cada uno es de tipo float64. Los
valores de parámetro que realmente pase quien llama a la función
se almacenarán en las variables locales v1 y v2. La definición de
la función también indica que el resultado de la función también
será un valor float64.

Los tipos de parámetro y el tipo de retorno provocan que ocurra
una conversión de tipo, donde los valores se convierten al tipo
requerido si no son ya del tipo correcto. Por ejemplo,

    y := addValues("15", 2)


Esto haría que y contuviera el valor de coma flotante 17.0. Esto
es porque el valor de cadena "15" se convertiría a un valor
float64, y el valor entero 2 se convertiría a un valor float64
antes de invocar el cuerpo de la función. Así, typeof(v1) dentro
de la función devolverá "float64" como resultado,
independientemente del tipo del valor pasado cuando se llamó a
la función.

La sentencia func permite un tipo de dato especial, any
(equivalente a interface{} de Go), que en realidad significa "se
permite cualquier tipo" y no ocurre ninguna conversión. Si el
cuerpo de la función necesita conocer el tipo real del valor
pasado, se usaría la función typeof().

Una función que no devuelve ningún valor debe omitir la
declaración del tipo de retorno.

Ego permite declarar una función con nombre dentro de otra
función con nombre, como una forma cómoda de organizar lógica
auxiliar (esto no es sintaxis válida en Go; Go solo permite
literales de función dentro de funciones). A diferencia de un
closure, una función anidada con nombre no captura el ámbito de
la función que la contiene: solo puede ver sus propios
parámetros, sus propias variables locales, y los nombres
definidos a nivel de paquete o global. Acceder a un parámetro o
variable local de la función que la contiene es un error en
tiempo de compilación:

    func outer(a int) int {
        func inner(b int) int {
            return a + b   // compile error: cannot access outer's a
        }
        return inner(5)
    }

Para compartir el ámbito que la contiene, utiliza en su lugar un
literal de función (closure), tal como se describe en el tema de
ayuda language.functions.variables.

.topic language.functions.return

Cuando una función está lista para devolver un valor, se utiliza
la sentencia return. Esta identifica una expresión que define qué
se debe devolver. La sentencia return hace que esta expresión se
convierta al tipo de dato indicado en la sentencia func como
valor de retorno. Si el ejemplo anterior tuviera un tipo de
resultado string,

    func addValues( v1 float64, v2 float64) string {
        x := v1 + v2

        return x
    }

    y := addValues(true, 5)


El valor resultante de y sería la cadena "6". Esto es porque no
solo se convertirán a valores de coma flotante el valor booleano
true y el entero 5, sino que además el resultado se convertirá a
un valor de cadena al salir la función.

Ten en cuenta que si la sentencia func no especifica un tipo para
el resultado, se asume que la función no devuelve ningún
resultado. En este caso, la sentencia return no puede especificar
un resultado de función, y si la sentencia return es la última
sentencia, entonces es opcional. Por ejemplo,

    func show( first string, last string) {
        name := first + " " + last

        fmt.Println("The name is ", name)
    }

    show("Bob", "Smith")


Este ejemplo ejecutará la función show con los dos valores de
cadena, e imprimirá el mensaje formateado "The name is Bob Smith".
Sin embargo, la función no devuelve ningún valor (no se especificó
ninguno después de la lista de parámetros y antes del cuerpo de
la función), así que en este caso no hace falta ninguna sentencia
return.

Observa también que la invocación de la función show no
especifica ninguna variable en la que almacenar el resultado,
porque no hay ninguno. De esta manera puedes ver que una función
se puede llamar con un valor que puede usarse en una sentencia de
asignación o en una expresión, o simplemente llamarse e ignorar
el valor del resultado. Incluso si la función show devolviera un
valor, la invocación ignora el resultado y este se descarta.

.topic language.functions.defer

A veces una función puede tener varios puntos desde los que
retorna, pero siempre quiere ejecutar el mismo bloque de código
para limpiar la función (por ejemplo, cerrar un archivo que se
había abierto).

    func getName() bool {
        f := io.Open("name")

        defer io.Close(f)

        s := io.ReadLine(f)
        if s == "" {
            return false
        }

        return true
    }


En este ejemplo, la función abre un archivo (el paquete io se
trata más adelante). Como hemos abierto un archivo, queremos
asegurarnos de cerrarlo cuando terminemos. Esta función tiene dos
sentencias return. Podríamos programarla de manera que, antes de
cada una, también llamáramos a la función io.Close() cada vez.
Pero la sentencia defer permite que la función especifique una
sentencia que se ejecutará siempre que la función realmente
retorne, sin importar cuál de las ramas del código condicional se
ejecute.

Cada sentencia defer identifica una sentencia o un bloque básico
de sentencias (encerrado entre "{" y "}") que se debe ejecutar.
Si hay varias sentencias defer, todas se ejecutan en el orden
inverso al que se definieron. Así, la primera sentencia defer
siempre es la última que se ejecuta antes de que la función
retorne.

Ten en cuenta que las sentencias defer se ejecutan cuando la
función llega al final de su cuerpo, incluso si no hay ninguna
sentencia return, como en el caso de una función que no devuelve
ningún valor.

Una sentencia defer aplaza la llamada en sí, pero no aplaza la
evaluación de los argumentos de la llamada: estos se evalúan de
inmediato, en el momento en que se ejecuta la propia sentencia
defer, y los valores quedan congelados hasta que la llamada
aplazada ocurre realmente más tarde:

    func example() {
        x := 1
        defer fmt.Println("x was", x)   // "x was 1" -- x is read now
        x = 2
    }

Por eso, aplazar código dentro de un bucle captura el valor de
cada iteración, y no el valor que termine teniendo la variable
del bucle cuando la función retorne. Cualquier otra cosa a la que
haga referencia la llamada aplazada, aparte de un argumento
pasado (una variable del ámbito circundante, o un campo alcanzado
a través de un receptor), se sigue buscando de forma normal cuando
la llamada aplazada realmente se ejecuta, exactamente igual que
en un closure ordinario.

.topic language.functions.variables

Las funciones pueden ser valores en sí mismas. Por ejemplo,
considera:

    p := fmt.Println


Esta sentencia obtiene el valor de la función fmt.Println y lo
almacena en la variable p. A partir de este punto, si quisieras
llamar a la función del paquete que imprime elementos en la
consola, en lugar de usar fmt.Println puedes usar la variable p
para invocar la función:

    p("The answer is", x)


Esto significa que puedes pasar una función como parámetro a otra
función. Considera,

    func show( fn any, name string) {
        fn("The name is ", name)
    }

    p := fmt.Println
    show(p, "tom")


En este ejemplo, la función show tiene un primer parámetro que es
una función, y un segundo parámetro que es una cadena. En el
cuerpo de la función, la variable fn se usa para llamar a la
función fmt.Println. Podrías usar esto si quisieras enviar la
salida a la consola (usando fmt.Println) o a un archivo (usando
io.WriteString). El código que hace la llamada podría decidir qué
función es la adecuada, y pasarla directamente a la función show,
que es quien realiza la llamada.

Incluso puedes crear un valor de literal de función, que defina
el cuerpo de la función, y almacenarlo en una variable o pasarlo
como parámetro. Por ejemplo,

    p := func(first string, last string) string {
                return first + " " + last
            }

    name := p("Bob", "Smith")


Ten en cuenta que, cuando se define como literal de función, la
palabra clave func no va seguida de un nombre de función, sino
que directamente contiene la lista de parámetros, el tipo de
valor de retorno y el cuerpo de la función. No hay ninguna
diferencia significativa entre lo anterior y declarar
func p(first string... salvo que la variable p tiene un ámbito
que podría estar limitado al bloque básico de código actual.
Incluso puedes definir una función como parámetro de otra función
directamente, como en:

    func compare( fn interface{}, v1 any, v2 any) bool {
        return fn(v1, v2)
    }

    x := compare( func(a1 bool, a2 bool) bool { return a1 == a2 }, true, false)


Este ejemplo, algo artificial, muestra una función llamada compare
que tiene un primer parámetro que será un nombre de función, y dos
parámetros adicionales de tipo desconocido. La invocación de
compare pasa un literal de función como primer parámetro, que es
una función que compara valores booleanos. Finalmente, los dos
valores booleanos reales se pasan como segundo y tercer parámetro
en la llamada a la función compare. La función compare invocará
inmediatamente el literal de función (almacenado en fn) para
comparar dos valores booleanos, y devolverá el resultado.

Un ejemplo más complejo podría ser una función cuyo trabajo es
ordenar una lista de valores. Ordenar una lista de valores
escalares está disponible como función incorporada del paquete
sort, pero ordenar una lista de tipos complejos no se puede hacer
de esta manera. Podrías escribir una función de ordenación que
acepte como parámetro la operación de comparación, y esa función
sabría cómo decidir entre dos valores cuál va primero. Esto
permite que la función de ordenación que crees sea genérica, sin
importar los tipos de datos.

.topic language.functions.receiver

Se puede escribir una función de tal manera que solo se pueda
usar cuando se referencia a través de una variable de un tipo
específico. Este tipo lo crea el usuario, y luego las funciones
que se escriben para operar sobre ese tipo usan cualquier
variable del tipo como receptor, lo que significa que esa
variable, dentro de la función, obtiene el valor del elemento en
la invocación de la función sin ser un parámetro explícito. Esto
también permite que existan varias funciones con el mismo nombre
que simplemente hacen referencia a tipos diferentes. Por ejemplo,

    type Employee struct {                        // (1)
        first string
        last  string
        age   int
    }

    func (e Employee) Name() string {             // (2)
        return e.first + " " + e.last
    }

    foo := Employee{                              // (3)
        first: "Bob",
        last: "Smith"}

    fmt.Println("The name is ", foo.Name())       // (4)


Analicemos este ejemplo más de cerca para ver qué está pasando.

1. Esto define el tipo, llamado Employee, que tiene varios campos
   asociados a él.
2. Esto declara una función que tiene una variable e de tipo
   Employee como receptor. El trabajo de esta función es formar
   una cadena con el nombre del empleado. Ten en cuenta que el
   nombre de la variable no es un parámetro, sino que se
   considera el receptor.

3. Esto crea una instancia del tipo Employee y la almacena en una
   variable foo.
4. Esto imprime una etiqueta y el valor de la función Name cuando
   se llama usando foo como instancia de la variable. La función
   Name no se puede llamar directamente; es un símbolo
   desconocido a menos que se llame con un receptor de tipo
   Employee en su invocación.

En la línea de declaración (2) anterior, podrías usar un carácter
asterisco ("*") antes del tipo Employee del receptor, como en:

    func (e *Employee) SetName(f string, l string)  {
        e.first = f
        e.last = l
    }


Esta función se puede usar para establecer los nombres en la
variable receptora. Si la función se hubiera declarado sin el
marcador "*", el receptor en realidad sería solo una copia de la
instancia. Así, la función Name() anterior puede leer cualquiera
de los valores del receptor, pero si los establece, está
cambiando una copia de la instancia que solo existe mientras la
función se ejecuta, y los valores de la instancia foo no cambian.

Al usar el * como en el ejemplo de SetName, el receptor e no es
una copia de la instancia, sino la instancia real. Así, los
cambios hechos al receptor e se realizarán realmente en la
variable de instancia foo. Una forma fácil de recordar esto es
que, sin el *, el receptor no cambia la instancia que hace la
llamada, pero con el "*" los cambios sí afectarán a la instancia
que hace la llamada.

Debido a que especificar una variable y un tipo de receptor hace
que el nombre de la función tenga ámbito propio del tipo, puedes
tener varias funciones con el mismo nombre, cada una con un
receptor diferente. Un ejemplo sería que cada tipo defina un
método String() cuyo trabajo es formatear la información del
valor para que la lea una persona. El programa se puede escribir
entonces de manera que no importe cuál sea el tipo de una
variable de instancia. Al llamar a la función String() desde
cualquier instancia, se ejecutará la función String() adecuada
según el tipo.

Ten en cuenta que los tipos se pueden anidar. Considera este
ejemplo:

    type EmpInfo struct {
        First string
        Last string
        Age int
    }

    type Employee struct {
        Info  EmpInfo
        Manager bool
    }

    e := Employee{
        Info: EmpInfo{
            First: "Bob",
            Last:  "Smith",
            Age:   35,
        },
        Manager: false
    }


El tipo Employee contiene dentro un elemento Info que es de otro
tipo, EmpInfo. Ten en cuenta que, al inicializar los campos de la
variable de instancia e recién creada, debes identificar
explícitamente el nombre del tipo para el campo Info, ya que este
actúa como generador de instancia en sí mismo para una instancia
de EmpInfo, que luego se almacena en el campo Info de la
estructura.

.topic language.errors

Hay dos tipos de errores que se pueden gestionar en un programa
Ego.

El primero son los errores generados por el usuario o en tiempo
de ejecución, que en realidad son valores de un tipo de dato
llamado error. Puedes crear un nuevo valor de error usando la
función errors.New(), como en:

    if v == 0 {
        return errors.New("invalid zero value")
    }


Este código, ejecutado dentro de una función, devolvería un valor
de tipo error que, al imprimirse, muestra el texto indicado. Un
error también puede tener el valor nil, que significa que no hay
ningún error almacenado en el valor. Algunas funciones de tiempo
de ejecución devuelven un valor de error, y tu código puede
comprobar si el resultado es nil o si es un error real.

El segundo tipo son los errores de pánico, que son errores
generados por el propio Ego mientras ejecuta tu programa. Por
ejemplo, un intento de dividir por cero genera un error de
pánico. De forma predeterminada, esto hace que el programa deje
de ejecutarse y se imprima un mensaje de error.

.topic language.errors.try-catch

Puedes usar la sentencia try para ejecutar un bloque de código (en
el mismo ámbito que la sentencia que lo contiene) y capturar
cualquier error de pánico que ocurra durante la ejecución de ese
bloque. El error hace que Ego ejecute el código de la cláusula
catch de la sentencia. Si no hay errores, la ejecución continúa
después del bloque catch. Por ejemplo:

    x := 0
    try {
        x = pay / hours
    } catch {
        fmt.Println("Hours were zero!")
    }

    fmt.Println("The result is ", x)


Si el valor de hours es distinto de cero, la sentencia de
asignación asignará el dividendo a x. Sin embargo, si hours es
cero, se generará un error de pánico de división por cero.
Cuando esto ocurre, el resto de las sentencias (si las hay) en el
bloque try se omiten, y se ejecuta el bloque catch.

Opcionalmente puedes especificar el nombre de una variable que se
creará dentro del bloque catch y que contendrá el error real
encontrado. Hazlo añadiendo el nombre entre paréntesis antes del
bloque catch.

    x := 0
    try {
        x = 125 / x
    } catch (e) {
        fmt.Println("unexpected error, ", e)
    }


Esto se puede usar en el bloque catch si necesita gestionar más
de un posible error, por ejemplo.

Ten en cuenta que la cláusula catch es opcional. Si omites la
cláusula catch, entonces el error se descarta. Ten en cuenta que
el resto del bloque try posterior al momento en que ocurrió el
error no se ejecuta, pero no se genera ningún error y no hay
ningún cambio en la ejecución del programa después del bloque
try. Por ejemplo, esta sección de código proporcionará un valor
predeterminado y luego intentará una operación de división. Si la
operación falla (por ejemplo, con una división por cero), el
valor predeterminado permanece sin cambios:

go
x := 1000
try {
    x = a / b
}


En este ejemplo, si el valor de b es cero, entonces el valor de x
permanece establecido en 1000. Si el valor de b es distinto de
cero (y no ocurren otros errores), el valor de x se restablece al
valor de a/b. A esto se le llama idiomáticamente en inglés un
"nice try" (un buen intento).

.topic language.errors.conditional-expression

Si necesitas capturar un posible error en una expresión, puedes
usar una forma abreviada de try y catch que funciona dentro de
una expresión. Considera el siguiente ejemplo:

    emp := {
        name: "Donna",
        age: 32,
    }

    hours := 40
    pay := emp.wage * hours


Este código generará un error en la sentencia que intenta
referenciar el miembro de estructura wage, que no existe. Si
crees que el campo podría no existir, o si estás realizando una
operación que podría producir un error (división por cero, por
ejemplo) para la que tienes un valor predeterminado útil, usa la
sintaxis de expresión condicional:

    emp := {
        name: "Donna",
        age: 32,
    }

    hours := 40
    pay := ?emp.wage : 25.0 * hours


El "?" indica que el siguiente componente de la expresión (hasta
el ":") está envuelto en un bloque try/catch. Si no ocurre ningún
error, se usa la expresión tal como se especificó. Pero si hay un
error ("no such structure field", por ejemplo), entonces se usa
en su lugar la expresión después de los ":". Así, en el ejemplo
anterior, como no hay un campo wage en el registro de este
empleado, el programa asume un salario de $25 por hora en el
cálculo de la paga.

.topic language.errors.panic

Puedes hacer que se señalice un error de pánico desde dentro de
tu código, el cual opcionalmente podría capturarse mediante un
bloque try/catch, usando la función panic:

    if x == 0 {
        panic("Invalid value for x")
    }


Cuando este código se ejecuta, si el valor de x es cero, entonces
se señaliza un error de pánico con el mensaje de error "Invalid
value for x". Este error es indistinguible de un error de pánico
generado por el propio Ego. Si hay un bloque catch{}, el valor de
la variable de error será la cadena "Invalid value for x".

.topic language.errors.throw

La sentencia throw es una extensión del lenguaje Ego que genera
un valor de error ya construido como un error de tiempo de
ejecución capturable, si (y solo si) no es nil:

    throw expr

expr debe evaluarse como un valor de error. Si no es nil, se
genera exactamente como si hubiera ocurrido un error de tiempo de
ejecución real, de modo que puede capturarlo un try/catch que lo
contenga. Si el valor es nil, throw no hace nada y la ejecución
continúa con la siguiente sentencia. Esto convierte a throw en un
reemplazo de una sola sentencia para el idioma habitual de Go
"if err != nil { return err }", usado para propagar una condición
de error:

    func mustBePositive(n int) {
        throw validate(n)
    }

    func validate(n int) error {
        if n < 0 {
            return errors.New("value must not be negative")
        }
        return nil
    }
.topic language.threads

Igual que su inspiración, Ego admite el concepto de "go routines", que son
hilos que un programa Ego puede iniciar y que se ejecutan de forma
asíncrona. Una goroutine siempre es la invocación de una función, o un
valor constante de función. Esa función se inicia en un hilo paralelo,
y se ejecuta de forma independiente del programa principal.

Puedes usar canales como mecanismo de comunicación entre las goroutines
y el programa principal.

.topic language.threads.go

Utiliza la sentencia go para iniciar un hilo. Aquí tienes un ejemplo muy
simple:

    func beepLater(duration string) {
        d, _ := time.ParseDuration(duration)
        time.Sleep(d)
        fmt.Println("BEEP!")
    }

    go beepLater("1s")


Este ejemplo define una función beepLater a la que se le pasa una
expresión de cadena que representa una duración. La función convierte
esa expresión de cadena en un valor nativo time.Duration, y luego
espera a que transcurra esa duración antes de imprimir el mensaje en
la consola.

La sentencia go inicia este hilo, pasándole los parámetros desde el
ámbito actual, los cuales se copian al hilo y se almacenan en la
variable duration de ese hilo.

Ten en cuenta que este no es un ejemplo muy interesante, y peor aún:
muestra un problema al ejecutar goroutines. Si el programa anterior es
el único código que se ejecuta en el programa, no producirá ninguna
salida. Esto se debe a que el programa principal termina (completa
todas sus sentencias) y eso finaliza la sesión de Ego, incluso si un
hilo todavía se está ejecutando. No hay garantía de que el hilo pueda
llegar a completarse si el programa que lo inició finaliza antes.

.topic language.threads.synchronization

Ego proporciona varios tipos de datos que se usan para sincronizar la
ejecución de hilos en competencia, y para ayudar a gestionar el acceso a
recursos de forma predecible cuando sea necesario.

+----------------+------------------------------------------------------------+
| Tipo de dato   | Descripción                                                |
+----------------+------------------------------------------------------------+
| sync.Mutex     | Un bloqueo de exclusión mutua simple para serializar el    |
|                | acceso a un recurso                                        |
+----------------+------------------------------------------------------------+
| sync.RWMutex   | Un bloqueo de lectura/escritura: cualquier número de       |
|                | lectores concurrentes, o un único escritor exclusivo       |
+----------------+------------------------------------------------------------+
| sync.WaitGroup | Una forma de iniciar un número variable de goroutines y    |
|                | esperar a que terminen                                     |
+----------------+------------------------------------------------------------+

.topic language.threads.channels

Puedes resolver el problema de sincronización (y también permitir que
se devuelvan datos desde la goroutine) usando canales. Aquí tienes una
versión modificada del programa:


    func beepLater(duration string, c chan) {
        d, _ := time.ParseDuration(duration)
        time.Sleep(d)
        c <- "BEEP"
    }

    var xc chan
    go beepLater("1s", xc)

    m := <- xc

    fmt.Println(m)


En este ejemplo, el programa principal define una variable cx, que es
una variable de canal, de tipo chan. La duración y la variable de
canal se pasan a la goroutine. Es importante notar que el programa
luego recibe datos del canal, usando la notación <-. Esto hace que el
programa principal espere hasta que se coloque un mensaje en el canal,
y ese mensaje se almacena en la variable m.

Mientras tanto, la goroutine comienza a ejecutarse y realiza la espera
como antes. Una vez completada la espera, coloca un mensaje (en
realidad, cualquier valor) en el canal, usando de nuevo una variante
de la sintaxis <- para mostrar la escritura de un valor en un canal.
Cuando ocurre esta escritura, la operación de recepción del programa
principal se completa y se imprime el mensaje.

De esta forma, la función go realiza su trabajo y luego envía el
resultado de vuelta a través del canal. El programa principal esperará
a que se almacenen datos en el canal antes de continuar. La goroutine
puede enviar más de un elemento de datos al canal, simplemente
realizando más operaciones de escritura en el canal. El receptor puede
saber de antemano cuántas veces debe leer el canal, o puede usar una
operación for...range sobre el canal para simplemente seguir
recibiendo datos hasta terminar.

    func beepLater(count int, c chan) {
        for i := 0; i < int; i = i + 1 {
            c <- "Item " + string(i)
        }
    }

    var xc chan
    go beepLater(5, xc)

    for msg := range xc {
        fmt.Println("Received ", msg)
    }


En este caso, quien llama a la goroutine incluye un conteo del número
de mensajes a enviar, y esa función envía esa cantidad de mensajes. El
programa principal usa la operación range sobre el canal, lo que
significa "tantos como recibas", y cada mensaje se almacena en msg. El
bucle terminará cuando la goroutine deje de ejecutarse. La goroutine
también puede indicarle explícitamente al programa principal que ha
terminado usando la función close() sobre el canal. Cuando esto
ocurre, el bucle range termina. Ten en cuenta que tanto el programa
principal como la goroutine seguirán ejecutándose hasta el final
incluso después de que el canal se cierre.

Una recepción también puede indicarte si el canal sigue abierto,
usando la forma de dos valores ("coma-ok"):

    value, ok := <-xc

ok es false cuando el canal se ha cerrado y se ha vaciado por completo
(value tendrá entonces el valor cero), y true en caso contrario. Esta
es la forma habitual de detectar el cierre de un canal sin depender de
for...range. Ten en cuenta que <-xc no está limitado a ser todo el
lado derecho de una asignación; funciona en cualquier lugar donde se
espere un valor, como en un argumento de llamada a función.

Un canal es un valor como cualquier otro, así que puede almacenarse en
un campo de estructura, en un elemento de arreglo, o en un valor de
mapa, y se puede enviar o recibir directamente a través de esa
ubicación de almacenamiento.

Un canal nunca tiene un tipo de elemento; siempre se escribe chan solo,
sin importar dónde aparezca el tipo (una declaración var, un parámetro
o tipo de retorno de función, un campo de estructura, make(), o el
destino de una aserción de tipo). A diferencia de Go, donde chan string
declara un canal que solo transporta cadenas, los canales de Ego
pueden transportar cualquier valor. Escribir chan T en cualquiera de
estas posiciones es un error de compilación.

.topic language.import

Utiliza la sentencia import para incluir otros archivos en la
compilación de este programa. La sentencia import no puede aparecer
dentro de ningún otro bloque o definición de función. Lógicamente, la
sentencia detiene la compilación actual, compila el objeto indicado
(añadiendo las definiciones de funciones y constantes al paquete
indicado) y luego reanuda la compilación en curso.

    import factor
    import "factor"
    import "factor.ego"


Las tres formas tienen el mismo efecto. La primera asume que se
encuentra un archivo llamado "factor.ego" en el directorio actual. La
segunda y la tercera asumen que la cadena entre comillas contiene una
ruta de archivo. Si no se incluye el sufijo ".ego", se asume de todos
modos.

Opcionalmente puedes especificar un alias para el paquete importado
colocando un identificador antes del nombre del paquete o de la ruta
como cadena. Por ejemplo,

    import str "strings"


En este ejemplo, el paquete "strings" se importa al programa actual,
pero se hará referencia a él usando el nombre str en el código. Esto
te permite importar varios paquetes que tendrían el mismo nombre y
usar el alias para diferenciarlos sin ambigüedad.

Si el nombre de importación no se encuentra en el directorio actual,
el compilador usa la variable de entorno EGO_PATH para formar una ruta
de directorio, y añade el directorio "lib" a esa ruta para localizar
la importación. Así, la sentencia anterior podría resolverse en
/Users/cole/ego/lib/factor.ego si EGO_PATH estuviera configurado como
"~/ego".

Finalmente, la sentencia import puede leer un directorio completo de
archivos fuente que contribuyen todos al mismo paquete. Si el destino
del import es un directorio dentro de $EGO_PATH/lib, entonces todos
los archivos fuente dentro de ese directorio se leen y procesan como
parte de un único paquete.

Las siguientes secciones describirán los paquetes incorporados que se
proporcionan automáticamente como parte de Ego. Puedes extender los
paquetes escribiendo los tuyos propios, como se describe más adelante
en la sección sobre Paquetes de Usuario.

.topic packages

Los paquetes son un mecanismo para agrupar funciones relacionadas.
Estas funciones se acceden usando notación de punto para hacer
referencia al nombre del paquete y luego localizar la función dentro
de ese paquete para llamarla.

Los paquetes pueden estar disponibles automáticamente para tu programa
si la preferencia ego.compiler.auto-import está configurada como true.
Si no, debes importar cada paquete antes de poder usarlo. Además, el
usuario puede crear paquetes para extender el soporte en tiempo de
ejecución de Ego.

.topic packages.base64

El paquete base64 codifica y decodifica cadenas usando la codificación
estándar Base64 (RFC 4648).

.topic packages.base64.encode

base64.Encode(data string) string codifica una cadena como una cadena
codificada en Base64 usando las reglas de codificación estándar.

    s := base64.Encode("Hello, World!")

Esto produce la cadena "SGVsbG8sIFdvcmxkIQ==".

.topic packages.base64.decode

base64.Decode(data string) (string, error) decodifica una cadena
codificada en Base64 y devuelve el valor de cadena original. Si la
entrada no es Base64 válido, se devuelve un error.

    s, err := base64.Decode("SGVsbG8sIFdvcmxkIQ==")

Esto produce la cadena "Hello, World!".

.topic packages.cipher

El paquete cipher proporciona primitivas criptográficas: hash
unidireccional, cifrado simétrico, cadenas de bytes
criptográficamente aleatorias, "sellado" in situ de variables de
cadena sensibles, y la creación y validación de tokens de autenticación
firmados (el mismo tipo de token que el servidor Ego emite a los
clientes REST tras un inicio de sesión exitoso).

.topic packages.cipher.hash

cipher.Hash(text string) string calcula un resumen SHA-256 de text y
lo devuelve como una cadena hexadecimal en minúsculas de 64 caracteres.
El resumen es unidireccional (irreversible); la misma entrada siempre
produce la misma salida. Este es un resumen de contenido de propósito
general; no lo uses para almacenar contraseñas.

    h := cipher.Hash("Hello, World!")

.topic packages.cipher.encrypt

cipher.Encrypt(text, key string) (string, error) cifra text usando key
como frase de paso y devuelve el resultado como una cadena hexadecimal.
Cifrar el mismo texto dos veces con la misma clave produce una salida
diferente cada vez.

    e, err := cipher.Encrypt("Hello, World!", "my secret key")

cipher.Decrypt(encryptedText, key string) (string, error) revierte
Encrypt(), dada la misma clave. Se devuelve un error si la clave es
incorrecta o si el texto cifrado fue modificado.

    d, err := cipher.Decrypt(e, "my secret key")

.topic packages.cipher.random

cipher.Random([bits int]) (string, error) genera un valor
criptográficamente aleatorio y lo devuelve como una cadena codificada
en Base64 segura para URL. bits es el número de bytes aleatorios a
generar; si se omite, se generan 32 bytes.

    r, err := cipher.Random()     // 32 bytes aleatorios
    r8, err := cipher.Random(8)   // 8 bytes aleatorios

.topic packages.cipher.seal

cipher.Seal(&text string) (string, error) cifra la cadena referenciada
por el argumento puntero y devuelve el resultado. Como efecto
secundario, la variable original se establece como cadena vacía, de
modo que el texto en claro ya no permanece en una variable que podría
quedar registrada en un log o inspeccionarse más tarde.
cipher.Unseal(sealedText string) string revierte el proceso.

    secret := "top secret"
    sealed, err := cipher.Seal(&secret)
    // secret ahora es ""
    plain := cipher.Unseal(sealed)

.topic packages.cipher.token

cipher.New(name string [, data string [, expiration string]]) (string, error)
crea un nuevo token de autenticación firmado que contiene name
(normalmente un nombre de usuario) y un payload de datos opcional, que
se devuelve como una cadena opaca codificada en hexadecimal apta para
usarse como token portador (bearer token). expiration es una cadena de
duración de Go (por ejemplo, "15m", "2h"); por defecto usa el tiempo de
expiración de token configurado en el servidor.

    token, err := cipher.New("alice", "role=admin", "1h")

cipher.Validate(token string) bool indica si un token producido por
cipher.New() es actualmente válido (correctamente firmado, no expirado
y no incluido en la lista negra). Nunca devuelve un error; un token
inválido simplemente se valida como false.

cipher.Extract(token string) (cipher.Token, error) decodifica un token
y devuelve su contenido como una estructura cipher.Token (campos Name,
Data, TokenID, AuthID y Expires), o un error que explica por qué el
token no es válido.

.topic packages.cmplx

El paquete cmplx proporciona funciones matemáticas para números
complejos, reflejando el paquete estándar math/cmplx de Go. Cada
función opera únicamente sobre valores complex128; convierte un valor
complex64 con complex128(x) primero si es necesario.

+-------------------------------+-----------------------------------------+
| Función                       | Descripción                             |
+-------------------------------+-----------------------------------------+
| cmplx.Abs(x)                  | Valor absoluto (módulo) de x            |
| cmplx.Phase(x)                | Fase (ángulo, en radianes) de x         |
| cmplx.Conj(x)                 | Conjugado complejo de x                 |
| cmplx.Sqrt(x)                 | Raíz cuadrada compleja de x             |
| cmplx.Exp(x)                  | Exponencial compleja en base e de x     |
| cmplx.Log(x) / cmplx.Log10(x) | Logaritmo complejo natural/base-10      |
| cmplx.Sin(x)/Cos(x)/Tan(x)    | Funciones trigonométricas complejas     |
| cmplx.Polar(x)                | Convierte x a forma polar (r, theta)    |
| cmplx.Rect(r, theta)          | Construye un valor complejo desde forma |
|                               | polar                                   |
| cmplx.Pow(x, y)               | x elevado a la potencia compleja y      |
| cmplx.IsNaN(x) / IsInf(x)     | Indica si una parte de x es NaN/Infinito|
| cmplx.NaN() / cmplx.Inf()     | Valor complejo con partes en NaN/Inf    |
+-------------------------------+-----------------------------------------+

    fmt.Println(cmplx.Abs(3+4i))    // 5
    fmt.Println(cmplx.Sqrt(-1))     // (0+1i)

A diferencia de math.Sqrt(), Sqrt() acepta un número real negativo sin
error, ya que la raíz cuadrada de un número negativo es un valor
complejo válido.

.topic packages.error

El paquete errors implementa tipos de error simples. Hay un único
método, New(), que se usa para crear un nuevo error. El error
resultante tiene una serie de funciones a las que se puede acceder.

.topic packages.error.new

La función New() crea una nueva instancia de un error. El primer
parámetro es el texto del mensaje de error, que debe ser un valor de
cadena.

El segundo valor, opcional, es un valor de contexto que se almacena en
el error. Este se muestra cuando el error se formatea, y se puede
recuperar usando la función Unwrap().

    var e error

    fn := "foobar.txt"
    e = errors.New("not found", fn)


Esto crea un nuevo error con un valor de cadena de "not found" y un
valor de contexto igual a la variable fn. Este se añadirá al mensaje
de error cuando se formatee. Si no se proporciona un valor de contexto
(es decir, solo se pasa un argumento a New) entonces no se muestra
ningún valor de contexto.

.topic packages.error.error

(e error) Error() string

La función Error() se puede usar con cualquier error como valor
receptor, y generará una representación textual del error.

    var e error

    fn := "foobar.txt"
    e = errors.New("not found", fn)

    m := e.Error()



Tras ejecutarse este código, m contendrá el valor de cadena "not
found: foobar.txt".

.topic packages.error.is

(e error) Is(other error) bool

La función Is() se puede usar con cualquier error como valor receptor,
y comparará el error con el parámetro proporcionado, que también es un
valor de error. Esto te permite comparar mensajes de error para ver si
coinciden. Ten en cuenta que esto no compara el contexto, solo el
mensaje de error en sí.

.topic packages.error.unwrap

(e error) Unwrap() any

La función Unwrap() se puede usar con cualquier error como valor
receptor, y devolverá el valor de contexto almacenado en el error. Si
no hay contexto, el resultado es nil.


    var e error

    fn := "foobar.txt"
    e = errors.New("not found", fn)

    f2 := e.Unwrap()


Tras ejecutarse este código, f2 contendrá el valor de cadena
"foobar.txt".

.topic packages.error.code

(e error) Code() string devuelve el código de error localizable de Ego,
como "div.zero" para un error de "división por cero". Si el error no
es un error de Ego, sino un error del sistema operativo, el código de
cadena será "not.an.ego.error".

    try {
        x := hours / 0.0
    } catch (e) {
        code := e.Code()    // Será "div.zero"
    }

.topic packages.error.next

(e error) Next() error devuelve el siguiente error encadenado a este
error. Los errores del sistema pueden contener una lista de errores.
Si no hay un siguiente error, devuelve nil.

.topic packages.error.context

(e error) Context(v any) error devuelve un nuevo error con el valor de
contexto establecido en v. Esta es una forma alternativa de adjuntar
el valor de contexto descrito en errors.New(); útil cuando el contexto
no se conoce hasta después de crear el error. Context() no modifica el
receptor; devuelve un valor de error distinto.

    e := errors.New("not found")
    e2 := e.Context("foobar.txt")
    // e.Error() es "not found"; e2.Error() es "not found: foobar.txt"

.topic packages.error.in

(e error) In(name string) error devuelve un nuevo error con el nombre
de ubicación establecido en name, normalmente el nombre de un archivo
fuente, paquete o función. No modifica el receptor.

.topic packages.error.at

(e error) At(line int) error devuelve un nuevo error con el número de
línea de ubicación establecido en line. Esto se combina con el nombre
de ubicación (ver In()) cuando el error se formatea. No modifica el
receptor.

    e := errors.New("not found").In("readFile").At(42)
    // e.Error() es "at readFile(line 42), not found"

.topic packages.exec

El paquete exec es un subconjunto del paquete de Go que permite
ejecutar un comando como subproceso del programa Ego actual. Este
paquete permite a quien lo invoca crear un nuevo objeto exec.Cmd, y
luego usar ese objeto para establecer opcionalmente argumentos y
valores de stdin para el comando, ejecutar el comando, y luego acceder
a los valores de stdout.

La estructura exec.Cmd incluye un campo Env, que es un arreglo de
cadenas para variables de entorno, las cuales deben ser todas cadenas
con la forma "name=value", y que se establecen en el contexto del
proceso a ejecutar. Además, el campo Stdin es un arreglo de cadenas
opcional; si está presente, el arreglo de cadenas se convierte en un
flujo de bytes y se convierte en el contenido de stdin para el comando
que se va a ejecutar.

Cuando el comando finaliza, si se completó sin errores, el campo
Stdout de la estructura del comando contiene un arreglo de cadenas con
la salida del comando. Por ejemplo,

    func main() {
        c := exec.Command("ls", "-l")
        c.Run()

        for _, line := range c.Stdout {
            fmt.Println(line)
        }
    }


Este programa crea un objeto exec.Cmd que invoca el comando "ls" como
su operación, con el argumento "-l". Ten en cuenta que estos son
comandos de estilo Unix; usarías comandos de estilo Windows en una
implementación de Ego basada en Windows. El programa ejecuta el
comando, y luego imprime las líneas de salida almacenadas en el campo
Stdout de la estructura del comando.

.topic packages.exec.command

exec.Command()

La función Command() crea un nuevo objeto Cmd y lo devuelve a quien la
invoca. La llamada puede incluir parámetros, que son el nombre del
comando a ejecutar seguido de cualquier cadena de argumento opcional
que se pase al programa que se va a ejecutar.

La estructura resultante admite el método Run(). Después de
inicializar un objeto exec.Cmd, se puede ejecutar usando su método
Run(). Este método devuelve un error si el comando no se completa
correctamente. Si se completa correctamente, se puede consultar el
arreglo Stdout para recopilar cualquier salida del comando como
cadenas.

.topic packages.filepath

El paquete filepath es un simple intermediario hacia el paquete
estándar path/filepath de Go, para la manipulación de rutas basada
únicamente en cadenas (ninguna de estas funciones toca el sistema de
archivos excepto Abs, que consulta el directorio de trabajo actual).
Un programa en sandbox no puede usar estas funciones para calcular una
ruta fuera de la raíz del sandbox configurada.

+----------------------------+-------------------------------------------+
| Función                    | Descripción                               |
+----------------------------+-------------------------------------------+
| filepath.Base(path)        | Último elemento de path                   |
| filepath.Dir(path)         | Todo excepto el último elemento de path   |
| filepath.Ext(path)         | Extensión de archivo de path, o "" si no  |
|                            | tiene                                     |
| filepath.Clean(path)       | Ruta equivalente más corta                |
| filepath.Join(elements...) | Une elementos de ruta con el separador    |
|                            | del sistema operativo                     |
| filepath.Abs(path)         | Representación absoluta de path           |
+----------------------------+-------------------------------------------+

    filepath.Base("/a/b/c.txt")       // "c.txt"
    filepath.Dir("/a/b/c.txt")        // "/a/b"
    filepath.Ext("/a/b/c.txt")        // ".txt"
    filepath.Join("a", "b", "c.txt")  // "a/b/c.txt"

.topic packages.fmt

El paquete fmt contiene una biblioteca de funciones para dar formato e
imprimir información en la consola estándar (stdout). En general, son
análogas a las funciones de Go del mismo nombre. Algunas funciones
devuelven dos valores (un resultado o longitud, y un error). Si quien
llama no especifica que el resultado se asigne a dos variables,
entonces el error se ignora.

Ten en cuenta que Ego solo admite un subconjunto de las funciones
equivalentes de Go.

.topic packages.fmt.printf

fmt.Printf(fmt string, args... any) (int, error)

La función Printf da formato a uno o más valores utilizando una cadena
de formato, y envía la cadena resultante a la salida estándar. Devuelve
la longitud en caracteres de la cadena escrita en la salida, y un error
que será nil si no se produjo ningún error durante el procesamiento del
formato.

    answer := 42
    kind := "correct"
    count, err := fmt.Printf("The %s answer is %d\n", kind, answer)


En este ejemplo, se procesa la cadena de formato, y los operadores de
sustitución de formato leen los parámetros (en el orden en que
aparecen) de la llamada. Así, el primer operador %s busca un valor de
cadena en la variable kind y lo inserta en el mensaje. Luego usa el
segundo operador %d para indicar que busca un valor entero, que se
inserta en la cadena utilizando el valor de answer.

Consulta la documentación oficial de Go
https://golang.org/pkg/fmt/#hdr-Printing) para obtener información
detallada sobre los operadores de formato admitidos por el paquete fmt.

.topic packages.fmt.print

fmt.Print(args... any) (int, error)

La función Print imprime uno o más elementos utilizando el formato
predeterminado de su tipo de dato en la salida estándar. No hay
operaciones de formato disponibles, y no se añade un salto de línea al
final.

A diferencia de Println, Print no siempre coloca un espacio entre los
elementos que imprime. Se inserta un espacio entre dos elementos
adyacentes solo cuando ninguno de los dos es una cadena:

    fmt.Print("hello", "world")   // "helloworld"  -- ambas son cadenas
    fmt.Print(1, 2)               // "1 2"         -- ninguno es una cadena
    fmt.Print("hello", 42)        // "hello42"     -- uno es una cadena

Si deseas un espacio entre cada elemento sin importar el tipo, usa
Println o Sprint más " ".

.topic packages.fmt.println

fmt.Println(args... any) (int, error)

La función Println imprime uno o más elementos utilizando el formato
predeterminado de su tipo de dato en la salida estándar. La salida va
seguida de un carácter de salto de línea. Sigue las mismas reglas de
espaciado que fmt.Print(): se coloca un espacio entre dos elementos
adyacentes solo cuando ninguno es una cadena. No hay operaciones de
formato disponibles.

    answer := 42

    fmt.Println("The answer is", answer)


Esto genera la cadena "The answer is 42" seguida de un carácter de
salto de línea, que se envía a la consola de salida.

.topic packages.fmt.scanf

fmt.Sscanf(fmt string, data string, args... any) (int, error)

La función Sscanf() acepta una cadena de datos, una especificación de
formato, y uno o más punteros a valores de tipo base. La cadena de
datos se procesa utilizando la especificación de formato, y los
valores resultantes se escriben en las variables de parámetro. La
función devuelve la cantidad de elementos procesados, y cualquier
error (como un valor no válido para un formato determinado).

    var age int
    var temp float64

    data := "35 101.2"

    fmt.Sscanf(data, "%d%f", &age, &temp)


La especificación de formato %d hace que se analice un valor entero a
partir de la cadena. A esto le sigue un número de punto flotante.
Estos se almacenan en age y temp respectivamente.

Cualquier carácter que no sea de formato en la cadena de formato debe
estar presente en la cadena de entrada exactamente como se muestra.
Por ejemplo,

    data := "age 35 temp 101.2"

    fmt.Sscanf(data, "age %d temp %f", &age, &temp)


Ten en cuenta que tanto en la cadena de datos como en la cadena de
formato, los caracteres de espacio en blanco múltiples (" ", etc.) se
ignoran. Los valores de formato admitidos son:

+-----------+--------------------------------------------------------+
| Formato   | Descripción                                            |
+-----------+--------------------------------------------------------+
| %t        | Valor booleano                                         |
| %f        | Valor de punto flotante                                |
| %d        | Valor entero                                           |
| %s        | Valores de cadena                                      |
+-----------+--------------------------------------------------------+


Ten en cuenta que esto es un subconjunto de las operaciones de formato
admitidas por el runtime de Go. Ten en cuenta también que Ego no
admite una especificación de ancho en el formato.

.topic packages.fmt.sprint

fmt.Sprint(args... any) string

La función Sprint() funciona exactamente igual que la función Print(),
pero devuelve la cadena con formato como su valor de resultado en
lugar de imprimirla en algún lugar. Sigue la misma regla de espaciado:
se inserta un espacio entre dos elementos adyacentes solo cuando
ninguno es una cadena.

    s1 := fmt.Sprint("hello", "world")   // "helloworld"
    s2 := fmt.Sprint(1, 2)               // "1 2"

.topic packages.fmt.sprintf

fmt.Sprintf(fmt string, args... any) string

La función Sprintf() funciona exactamente igual que la función
Printf(), pero devuelve la cadena con formato como su valor de
resultado, en lugar de imprimirla en algún lugar. Esto te permite usar
las operaciones de formato para construir un valor de cadena que
incluya otros valores dentro de la cadena.

    v := "foobar"
    msg := fmt.Sprintf("Unrecognized value %s", v)


Esto crea una cadena llamada msg que contiene "Unrecognized value
foobar" como contenido. El valor no se imprime en la consola como
parte de esta operación.

.topic packages.http

El paquete http proporciona los tipos utilizados para escribir puntos
finales de servicio REST alojados por el servidor Ego: Request (la
solicitud entrante, pasada como primer argumento del manejador) y
ResponseWriter (utilizado para construir la respuesta, pasado como
segundo argumento), además de las constantes estándar de código de
estado y nombre de método. Este paquete solo tiene sentido dentro de
un manejador de servicio que se ejecuta bajo "ego server"; no tiene
equivalente del lado del cliente -- para realizar llamadas HTTP
salientes desde código Ego, utiliza en su lugar el paquete rest.

    import "http"

    func handler(req http.Request, w *http.ResponseWriter) {
        // ... inspeccionar req, escribir una respuesta a través de w ...
    }

.topic packages.http.request

req describe todo lo que se sabe sobre la solicitud entrante. Todos
los campos son de solo lectura.

+----------------+---------------------------------------------------------+
| Campo          | Descripción                                             |
+----------------+---------------------------------------------------------+
| URL            | La URL de la solicitud: Path (incluye la cadena de      |
|                | consulta) y Parts                                       |
| Endpoint       | La ruta del propio punto final del servicio             |
| Method         | El método HTTP, p. ej. "GET", "POST"                    |
| Headers        | Los encabezados HTTP de la solicitud                    |
|                | (map[string][]string)                                   |
| Parameters     | Los parámetros de la cadena de consulta de la solicitud |
| Body           | El cuerpo bruto de la solicitud, para                   |
|                | POST/PUT/PATCH/DELETE                                   |
| Username       | El nombre de usuario del emisor autenticado, o ""       |
| Authenticated  | true si el emisor estaba autenticado de algún modo      |
| Authentication | "none", "user" o "token"                                |
| IsAdmin        | true si el emisor tiene privilegios de administrador    |
| IsJSON         | true si el emisor desea una respuesta JSON              |
| IsText         | true si el emisor desea una respuesta de texto sin      |
|                | formato                                                 |
| Permissions    | Las cadenas de permisos del emisor autenticado          |
| SessionID      | El número interno de sesión/solicitud del servidor      |
+----------------+---------------------------------------------------------+

req.URL es en sí misma una pequeña estructura: Path (la ruta de la
solicitud, incluida su cadena de consulta) y Parts, un mapa con una
entrada por cada marcador de posición {{name}} declarado en la ruta
del punto final.

    @endpoint get path="/services/sample/users/{{name}}"

    func handler(req http.Request, w *http.ResponseWriter) {
        name := req.URL.Parts["name"]
    }

.topic packages.http.responsewriter

w se utiliza para construir la respuesta, enteramente a través de sus
métodos.

+------------------------+--------------------------------------------------------------+
| Método                 | Descripción                                                  |
+------------------------+--------------------------------------------------------------+
| Header()               | Devuelve el Header de la respuesta, para                     |
|                        | añadir/reemplazar/eliminar encabezados                       |
| WriteHeader(status)    | Establece el código de estado HTTP (200 OK por defecto)      |
| Write(data)            | Escribe datos en el cuerpo de la respuesta                   |
| WriteJSON(i)           | Convierte i a JSON y lo escribe en el cuerpo                 |
| WriteTemplate(file, i) | Renderiza un archivo de plantilla con i y escribe el         |
|                        | resultado                                                    |
+------------------------+--------------------------------------------------------------+

El comportamiento de Write() depende del tipo de dato: un valor
[]byte se escribe en el cuerpo exactamente como se proporciona;
cualquier otro valor se formatea como JSON si el encabezado Accept del
emisor lo solicitó, o como texto sin formato en caso contrario.
Header() devuelve un http.Header, que envuelve los encabezados de la
respuesta con los métodos Add(key, value), Set(key, value) y Del(key).

    func handler(req http.Request, w *http.ResponseWriter) {
        w.Header().Add("Content-Type", "application/json")
        w.WriteHeader(http.StatusOK)
        w.WriteJSON({message: "hello", count: 3})
    }

.topic packages.http.status

El paquete http define las mismas constantes de código de estado y
nombre de método que net/http de Go, para usarlas con
w.WriteHeader() y al comparar req.Method:

    if req.Method != http.MethodGet {
        w.WriteHeader(http.StatusMethodNotAllowed)
        return
    }

http.StatusOK (200), http.StatusBadRequest (400),
http.StatusUnauthorized (401), http.StatusForbidden (403),
http.StatusNotFound (404), y http.StatusInternalServerError (500)
cubren la mayoría de los manejadores; también está disponible el
conjunto completo que coincide con el registro IANA de códigos de
estado, junto con http.MethodGet, http.MethodPost, http.MethodPut,
http.MethodPatch, http.MethodDelete, y el resto de los nombres
estándar de métodos HTTP.

.topic packages.i18n

A diferencia de la mayoría de los paquetes de Ego, i18n no tiene un
equivalente directo en la biblioteca estándar de Go. Proporciona
soporte de internacionalización/localización: busca un mensaje por
clave en el idioma que esté activo, y sustituye valores con nombre
(con formato opcional) en el texto resultante. Funciona de la mano con
la directiva @localization, que define el catálogo de mensajes propio
de un programa por idioma, y recurre al catálogo de mensajes
incorporado de Ego para cualquier clave que el bloque @localization
propio del programa no defina.

.topic packages.i18n.language

i18n.Language() string devuelve el código de idioma predeterminado
actual ("en", "fr", "es", etc.). Esto se resuelve una vez por proceso,
a partir de la variable de entorno EGO_LANG, luego LANG, y luego un
valor predeterminado incorporado de "en".

    lang := i18n.Language()

.topic packages.i18n.t

i18n.T(key string [, parameters map[string]any [, language string]]) (string, error)
busca key y devuelve su texto localizado y sustituido. Si el programa
tiene un bloque @localization activo, key se busca allí primero
(recurriendo a "en" dentro de ese bloque), y luego en el catálogo de
mensajes incorporado propio de Ego. Si key no se encuentra en ningún
lugar, se devuelve el texto literal de la clave sin cambios.

    @localization {
        "en": { "hello.msg": "hello, {{Name}}" },
        "fr": { "hello.msg": "bonjour, {{Name}}" },
    }

    m, err := i18n.T("hello.msg", {Name: "Tom"}, "fr")
    // "bonjour, Tom"

parameters proporciona valores para cualquier marcador de posición
{{tag}} en el texto del mensaje. language es opcional; si se omite,
se utiliza el valor predeterminado actual de i18n.Language() -- útil
para un servicio REST que desea respetar la preferencia de idioma de
un emisor individual en lugar de la predeterminada del servidor.

.topic packages.i18n.format

i18n.Format(text string [, parameters map[string]any]) (string, error)
aplica la sustitución de marcadores de posición {{tag}} directamente
sobre text, sin realizar una búsqueda en el catálogo. Utilízala cuando
ya tengas el texto del mensaje disponible (leído de la configuración o
compuesto en tiempo de ejecución) en lugar de una clave de catálogo.
Si parameters se omite o está vacío, text se devuelve sin cambios. Si
parameters no contiene un valor para cada marcador de posición
referenciado, el resultado contiene el texto sustituido con el mejor
esfuerzo posible y un error detectable que identifica la clave
faltante.

    s, err := i18n.Format("Total: {{amount|%.2f}}", {amount: 9.5})
    // "Total: 9.50"

.topic packages.io

El paquete io admite operaciones de entrada/salida utilizando archivos
nativos del sistema de archivos de la computadora que ejecuta Ego.

.topic packages.io.dirlist

io.DirList(path string) string

La función DirList genera una cadena que contiene un listado de
directorio con formato legible para humanos, similar al comando "ls"
de Unix. La cadena resultante ya está formateada con saltos de línea,
etc.

    s := io.DirList("/tmp")

Esto generará una cadena s que contiene los nombres de cada archivo en
el directorio "/tmp", uno por línea.

.topic packages.io.expand

io.Expand(path string, filter ...string) ([]string, error)

La función Expand() genera un arreglo con los nombres de ruta
absolutos de todos los archivos encontrados dentro de path, junto con
un error (nil si tiene éxito). Si path nombra un único archivo en
lugar de un directorio, el resultado es un arreglo de un elemento que
contiene la ruta de ese archivo. El argumento opcional filter, si se
proporciona, restringe los resultados a los nombres que terminan con
ese sufijo (típicamente una extensión de archivo como ".go").
Expand() recorre los subdirectorios de forma recursiva.

    a := "/tmp"
    fns, err := io.Expand(a)


El valor de fns es un []string y contiene los nombres de cada archivo
encontrado en el directorio "/tmp".

.topic packages.io.open

io.Open(filename [, mode]) (io.File, error)

La función Open() abre un archivo, y devuelve un manejador de archivo
que se puede usar para realizar operaciones específicas sobre el
archivo.

    fn := "mydata.txt"
    mode := "create"
    f := io.Open(fn, mode)


Este programa abre un archivo llamado "mydata.txt" para salida, y crea
el archivo si aún no existe. La variable mode puede tener uno de los
siguientes valores

+-----------+---------------------------------------------------------------+
| Modo      | Descripción                                                   |
+-----------+---------------------------------------------------------------+
| append    | El archivo debe existir, y se abre para escritura. Todos      |
|           | los datos nuevos se escriben al final del archivo.            |
+-----------+---------------------------------------------------------------+
| create    | El archivo se crea (se pierde cualquier contenido anterior)   |
|           | y queda disponible para escritura.                            |
+-----------+---------------------------------------------------------------+
| read      | El archivo debe existir ya, y se abre solo para lectura       |
+-----------+---------------------------------------------------------------+  
| write     | El archivo debe existir ya, y se abre solo para escritura     |
+-----------+---------------------------------------------------------------+


Una vez creado un manejador de archivo, puedes usarlo para realizar
operaciones adicionales sobre el archivo, hasta que uses el método
Close() del manejador, que cierra el archivo para que complete todas
las operaciones; después de eso, el manejador no puede volver a
usarse hasta otra operación io.Open(). Las funciones del manejador de
archivo son:

+----------------+-------------------------------------------------------------+
| Función        | Descripción                                                 |
+----------------+-------------------------------------------------------------+
| Close()        | Cierra el archivo, después de lo cual el objeto de archivo  |
|                | ya no se puede usar.                                        |
+----------------+-------------------------------------------------------------+
| ReadString()   | Lee una línea de texto del archivo y la devuelve como una   |
|                | cadena                                                      |
+----------------+-------------------------------------------------------------+
| WriteString()  | Escribe una cadena en el archivo de salida y añade un       |
|                | salto de línea                                              |
+----------------+-------------------------------------------------------------+
| Write()        | Escribe un valor arbitrario en el archivo de salida         |
+----------------+-------------------------------------------------------------+
| WriteAt()      | Escribe un valor arbitrario en una posición específica del  |
|                | archivo                                                     |
+----------------+-------------------------------------------------------------+

.topic packages.io.readdir

io.ReadDir(path string) ([]io.Entry, error)

La función ReadDir() lee la lista de archivos en una ruta de
directorio dada, devolviendo un arreglo de estructuras que describen
cada entrada, y un error (nil si tiene éxito). Se devuelve un arreglo
vacío (no un error) si el directorio está vacío.

    entries, err := io.ReadDir("/tmp")
    for _, e := range entries {
        fmt.Println(e.Name, e.Size, e.IsDirectory)
    }

Cada estructura io.Entry tiene los siguientes miembros:

+-------------+-----------+----------------------------------------------+
| Campo       | Tipo      | Descripción                                  |
+-------------+-----------+----------------------------------------------+
| Name        | string    | El nombre del archivo (no la ruta completa)  |
+-------------+-----------+----------------------------------------------+
| IsDirectory | bool      | true si la entrada es un subdirectorio       |
+-------------+-----------+----------------------------------------------+
| Mode        | string    | Cadena de modo estilo Unix para los permisos |
+-------------+-----------+----------------------------------------------+
| Size        | int       | El tamaño del contenido del archivo en bytes |
+-------------+-----------+----------------------------------------------+
| Modified    | time.Time | Fecha y hora de la última modificación       |
+-------------+-----------+----------------------------------------------+

.topic packages.io.prompt

io.Prompt(text string) string

La función Prompt() escribe text en la consola como un mensaje, y
luego lee y devuelve una sola línea de texto escrita por el usuario
(sin el salto de línea final). Si text comienza con el prefijo
especial "password~", el resto de text se usa como el mensaje, pero
la entrada escrita no se muestra en la consola.

    name := io.Prompt("Enter your name: ")
    secret := io.Prompt("password~Enter your password: ")

Ten en cuenta que la lectura y escritura de archivos completos de una
sola vez se realiza con os.ReadFile() y os.WriteFile() -- consulta el
tema de ayuda packages.os para más detalles.

.topic packages.json

El paquete json se utiliza para convertir un valor de datos de Ego en
el JSON equivalente expresado como un valor de cadena, o para
convertir una cadena JSON en un valor de datos comparable de Ego.

.topic packages.json.marshal

La función Marshal convierte un valor en un arreglo de bytes JSON, que
es el resultado de la función.

    a := { name: "Tom", age: 44 }
    s := string(json.Marshal(a))


Esto hace que s contenga el valor "{ \"name\":\"Tom\", \"age\": 44}".
Esto se debe a que la operación Marshal devuelve un arreglo de bytes,
y luego se usa string() para convertirlo en un valor de cadena.

.topic packages.json.marshalindent
json.MarshalIndent(v any, prefix, indent string) []byte

La función MarshalIndent convierte un valor en un arreglo de bytes
JSON, que es el resultado de la función. También debes proporcionar
una cadena prefix y una cadena indent. Estas se usan como prefijo
antes de cada línea de la salida en el JSON con formato resultante,
así como el valor de espaciado de sangría para los elementos
anidados. Ambas se interpretan como cadenas, y el uso más común es
especificar una cadena con la cantidad necesaria de espacios en
blanco para cada parte.


    a := { name: "Tom", age: 44 }
    s := string(json.MarshalIndent(a, "", "   "))


Debido a que el arreglo []byte resultante se convierte en un valor de
cadena, el resultado en s es el valor de cadena

    {
        "name" : "Tom",
        "age" : 44
    }


.topic packages.json.unmarshal
json.Unmarshal(data []byte, value *any) error

Analiza el texto JSON en data (un []byte, aunque también se acepta
una cadena simple) y escribe el resultado en value, que debe ser un
puntero. El valor existente al que apunta actúa como modelo: su tipo
concreto determina cómo se convierte el JSON, y para estructuras,
arreglos y mapas, su contenido existente se actualiza en el lugar en
vez de reemplazarse.

    r := { age:0, name:""}
    err := json.Unmarshal(s, &r)


Si s contiene el arreglo de bytes JSON del ejemplo de Marshal
anterior, el resultado es una estructura { age: 44, name:"Tom"} en la
variable r. Puedes usar la función reflect.Members() para examinar si
una estructura contiene un campo que esperabas. Los campos JSON
desconocidos se ignoran silenciosamente, y los campos de destino
existentes que no están presentes en el JSON se dejan sin cambios.
Las discrepancias de tipo (como convertir "notanumber" en un int) se
devuelven como un error normal, no se generan como una excepción.

.topic packages.json.parse

json.Parse(text string, expression string) (string, error)

Extrae un único valor de una cadena JSON utilizando un pequeño
lenguaje de consulta, sin requerir un modelo de destino. El resultado
siempre se devuelve como una cadena, sin importar el tipo JSON
subyacente.

    text := `{"user": {"name": "Jane", "age": 28}}`
    name, err := json.Parse(text, "user.name")
    // "Jane"

Las expresiones de consulta pueden nombrar un campo de objeto ("name"
o ".name"), encadenar campos con "." ("user.name"), indexar un
arreglo ("[2]" o "items[1].age"), o proporcionar un valor alternativo
("name?fallback" si el campo está ausente). Una expresión que
coincide con más de un valor devuelve un error ("ambiguous query
returns multiple values") en lugar de una lista.

.topic packages.json.writefile

json.WriteFile(filename string, v any) error

Convierte v a JSON (utilizando las mismas reglas que Marshal()) y lo
escribe en filename, creando o truncando el archivo según sea
necesario. Devuelve un error (nil si tiene éxito) si v no se puede
convertir o el archivo no se puede escribir.

    a := { name: "Tom", age: 44 }
    err := json.WriteFile("person.json", a)

.topic packages.json.readfile

json.ReadFile(filename string) (any, error)

Lee filename y analiza su contenido como JSON, devolviendo el valor
decodificado junto con un error (nil si tiene éxito). A diferencia de
Unmarshal(), no hay un modelo de destino, por lo que un objeto JSON se
convierte en un mapa de Ego (los números como float64), un arreglo
JSON se convierte en un arreglo de Ego, y un escalar de nivel superior
se devuelve directamente.

    v, err := json.ReadFile("person.json")
    fmt.Println(v["name"], v["age"])   // Tom 44

.topic packages.math.abs
math.Abs(n numeric) numeric

Para un valor numérico dado, devuelve el valor absoluto del número.

    posInt := math.Abs(signedInt)


En este ejemplo, posInt siempre será un valor positivo o cero.

.topic packages.math.factor

math.Factor(i int) []int

Para un entero positivo i dado, devuelve un arreglo con todos los factores
únicos de ese valor. El arreglo siempre es un arreglo de enteros. Para un
número primo, esto siempre devolverá un arreglo con dos elementos: uno y
el número primo. Para el resto de los números, devuelve un arreglo que
contiene el uno, el número, y todos los factores del número.

    a := math.Factor(11)
    b := math.Factor(12)


En el primer ejemplo, a contiene [1, 11] porque 11 es un número primo. El
valor de b contiene [1, 2, 3, 4, 6, 12].

.topic packages.math.log

math.Log(f float64) float64

Para un valor de coma flotante f dado, devuelve el logaritmo natural del valor.

    f := math.Log(2.1)

El valor de f es 0.7419373447293773.

.topic packages.math.max
math.Max(...numeric) numeric

Para una lista arbitraria de valores numéricos, devuelve el valor más grande
de la lista. La lista se puede enviar como elementos individuales, o como un
arreglo de elementos.

a := math.Max(n, 100)

b := [1, 2, 6, 3, 0]
c := math.Max(b...)


El valor de a es el mayor entre el valor de n y el valor 100. Esto es
comparable a usar el valor de n, pero con la condición de que sea como
mínimo 100. El valor de c será 6. La notación de puntos suspensivos "..."
indica que el arreglo b debe tratarse como parámetros individuales de la
función, y el valor más grande del arreglo b es 6.


.topic packages.math.min
math.Min(...numeric) numeric

Para una lista arbitraria de valores numéricos, devuelve el valor más pequeño
de la lista. La lista se puede enviar como elementos individuales, o como un
arreglo de elementos.

    a := math.Min(n, 10)

    b := [1, 2, 6, 3, 0]
    c := math.Min(b...)


El valor de a es el menor entre el valor de n y el valor 1. Esto es
comparable a usar el valor de n, pero con la condición de que no sea mayor
que 10. El valor de c será 0. La notación de puntos suspensivos "..." indica
que el arreglo b debe tratarse como parámetros individuales de la función,
y el valor más pequeño del arreglo b es 0.

.topic packages.math.primes

math.Primes(i int) []int

La función Primes acepta un valor entero positivo y devuelve un arreglo

El arreglo a contendrá los enteros [3, 5, 7]. Los valores '1' y '2'

.topic packages.math.sum

math.Sum(...numeric) numeric

La función Sum devuelve la suma aritmética de todos los valores numéricos.
Estos se pueden pasar como valores individuales o como un arreglo.

.topic packages.os

El paquete os proporciona una serie de funciones que acceden a las
características del sistema operativo, sea cual sea el sistema (macOS,
Windows, Linux, etc.) en el que se ejecuten. Los resultados y el
comportamiento de las rutinas pueden ser específicos de ese sistema
operativo. Los ejemplos mostrados aquí corresponden a macOS (la compilación
"darwin" de Go).

.topic packages.os.args

La función Args() devuelve un arreglo con los argumentos de línea de
comandos, como cadenas, cuando un programa Ego se ejecuta desde la shell
o línea de comandos. Considera el siguiente programa sencillo:

    func main() int {
        fmt.Println(os.Args())
    }


Esto tiene una función main (la función que siempre se invoca con el comando
ego run). Esta obtiene la lista de argumentos mediante os.Args() y la
imprime en la salida estándar. Si esto se coloca en un archivo -- por
ejemplo, "args.ego" -- entonces se puede ejecutar con una línea de comandos
similar a:

bash
    tom$ ego run args.ego stuff I want


El "tom$" es el símbolo del sistema (prompt) de la shell; el resto es la
línea de comandos introducida. Ten en cuenta que después del nombre del
archivo de programa hay tokens adicionales de línea de comandos. La función
main en "args.ego" los recuperará y los imprimirá, y la salida se verá así:

    [ "stuff", "I", "want"]


El resultado es un arreglo en el que cada elemento es el siguiente
token de la línea de comandos original.

.topic packages.os.exit

La operación Exit() detiene la ejecución del programa Ego y su entorno
de ejecución, y devuelve el control a la shell/línea de comandos desde
la que se invocó. Si se proporciona un parámetro opcional, este es un
entero que se convierte en el código de retorno del sistema del comando
ego run.

    main() int {
        if true {
            os.Exit(55)
        }

        return 0
    }


En este ejemplo, la condición siempre es true, por lo que se realiza la
llamada os.Exit(55). Cuando el comando ego finaliza, el código de retorno
de la shell ("$?" en la mayoría de las shells Linux/Unix, por ejemplo)
será el valor "55".

Si el programa principal devuelve un código de retorno distinto de cero,
esto tiene el mismo efecto que llamar a os.Exit() con ese valor. Si no se
realiza ninguna llamada a os.Exit() y el programa principal simplemente
termina, se asume que el valor del código de retorno es 0, lo que indica
que el código finalizó correctamente.

.topic packages.os.getenv

La función Getenv() recupera una variable de entorno de la shell que
invocó al procesador de Ego. Esta puede ser una variable de entorno de
una shell Linux, o una variable de entorno estilo DOS de la shell
CMD.EXE de Windows. El argumento debe ser el nombre de la variable
(distingue mayúsculas de minúsculas), y el resultado es el valor de la
variable de entorno. Si la variable no existe, la función siempre
devuelve una cadena vacía.

    func main() int {
        shell := os.Getenv("SHELL")

        fmt.Println("You are running the ", shell, " shell program")

        return 0
    }


Si se invoca esto en un sistema macOS o Linux mientras se ejecuta la
shell "bash", el resultado será una salida similar a:

text
    You are running the  /bin/bash  shell program

Funciones relacionadas: os.LookupEnv(name) (string, bool) es similar a
Getenv(), pero además indica si la variable llegó a estar definida.
os.Setenv(name, value) error y os.Clearenv() modifican el entorno del
proceso actual. os.Environ() []string devuelve cada par "nombre=valor"
del entorno. os.ExpandEnv(s) string reemplaza las referencias $name o
${name} en s por sus valores de entorno.

.topic packages.os.remove

La función Remove() elimina un archivo del sistema de archivos.

    fn := "newdata.txt"
    os.Remove(fn)


Cuando este programa se ejecuta, el archivo físico "newdata.txt" habrá
sido eliminado del sistema de archivos, siempre que el usuario actual
tenga permiso para eliminarlo. os.RemoveAll(path) error elimina path
y todo lo que contiene, y no falla si path no existe.

.topic packages.os.readfile

os.ReadFile(filename string) ([]byte, error) lee todo el contenido de
un archivo en un arreglo de bytes en una sola llamada. Como comodidad
específica de Ego, un filename que sea exactamente "." lee una sola
línea de texto desde la consola (stdin) en lugar del sistema de archivos.

    b, err := os.ReadFile("mydata.txt")
    lines := strings.Split(string(b), "\n")

os.WriteFile(filename string, data []byte, mode int) error escribe
data en filename, creando el archivo si no existe y truncándolo si ya
existe. data también puede ser una simple cadena. mode establece los
permisos del archivo si se crea de nuevo, generalmente expresado como
un valor octal:

    err := os.WriteFile("mydata.txt", "hello, world", 0o644)

.topic packages.profile

El paquete profile ayuda a administrar la configuración persistente del
perfil. Son los mismos valores a los que se puede acceder desde la línea
de comandos mediante el comando ego config. Se aplican a los valores que
se encuentran en el perfil activo actual.

Todos los valores de perfil tienen un nombre, que es una cadena que
identifica la clave. Hay tres tipos de nombres de valores:

* Un pequeño conjunto de claves restringidas especialmente sensibles
  (claves de firma, tokens de inicio de sesión guardados y similares)
  nunca se pueden leer, escribir ni eliminar mediante este paquete,
  bajo ninguna circunstancia.
* Las claves que comienzan con "ego." están reservadas para la
  configuración propia del compilador, el entorno de ejecución y el
  servidor. Set() sobre una de estas claves requiere que la clave ya
  exista, y los cambios en ego.runtime.*, ego.server.* o ego.compiler.*
  solo afectan a la copia en memoria del proceso actual -- nunca se
  escriben de vuelta en el disco.
* Todo lo demás es configuración propia de tu aplicación: puedes crear,
  leer, actualizar y eliminar estos valores libremente, y cada cambio
  se guarda en el archivo de perfil en disco. Usa tu propio prefijo
  (como "myapp.") para mantener tus valores diferenciados de los
  propios de Ego.

Los valores de perfil se almacenan en ~/.ego/ como archivos JSON --
default.profile para el perfil predeterminado, y <name>.profile para
cualquier otro perfil con nombre seleccionado con ego --profile <name>.
Un valor modificado con Set() o Delete() se escribe de vuelta en ese
archivo la próxima vez que Ego finalice normalmente.

.topic packages.profile.delete

La función Delete() elimina un valor del perfil activo por su nombre.
Si el valor de perfil no existe, no se produce ningún error. Está
sujeta a las mismas reglas de claves restringidas y de ego.* que Set().

.topic packages.profile.get

La función Get() recupera el valor actual de un valor de configuración
dado por su nombre. Por ejemplo,

    path, err := profile.Get("ego.runtime.path")


En este caso, la variable path es una cadena que contiene la ubicación
en el sistema de archivos de la ruta principal de Ego, donde se
encuentran las funciones de servicio, las bibliotecas de importación
y los programas de prueba. Si solicitas un valor de perfil para un
valor de configuración que no existe, se devuelve una cadena vacía
(no un error).

.topic packages.profile.keys

La llamada Keys() devuelve un arreglo de cadenas con los nombres de
todos los valores de perfil actualmente definidos, ordenados
alfabéticamente y excluyendo cualquier clave restringida. Esto se
puede usar para determinar si existe un valor de perfil antes de
obtener su valor.

profile.Config() map[string]string devuelve todos los valores de
perfil actualmente definidos como un único mapa de clave a valor,
excluyendo las claves restringidas -- una forma práctica de volcar
toda la configuración activa de una sola vez, en lugar de llamar a
Get() una vez por cada clave obtenida con Keys().

.topic packages.profile.set

La función Set() crea o actualiza un valor de perfil por su nombre,
con el valor indicado. El valor se convierte a una representación de
cadena y se almacena en los datos del perfil bajo la clave indicada.
La clave no necesita existir todavía; puedes crear una nueva clave
simplemente nombrándola. Establecer value en "" equivale a llamar a
Delete().

.topic packages.rest

El paquete rest proporciona un cliente HTTP/HTTPS de propósito general
que se puede usar para comunicarse con un servidor, autenticarse ante él
(ya sea mediante nombre de usuario y contraseña o un token de
autenticación), y realizar operaciones GET, POST y DELETE contra puntos
de conexión (endpoints) de URL.

El paquete admite el envío y la recepción de estructuras de datos
arbitrarias de Ego, expresadas como datos JSON hacia el servidor, o el
envío y la recepción de contenidos de texto.

Si el servidor con el que te comunicas es un servidor Ego, puedes usar el
comando ego logon para crear un token local que se usa para autenticarte
ante el servidor.

.topic packages.rest.parseurl

rest.ParseURL(path [, template] string ) map[string]any

Esto analiza una cadena de URL y devuelve un mapa que contiene cada parte
de la cadena. Si se proporciona una plantilla, el componente de ruta
también se vuelve a analizar para crear elementos adicionales en el mapa
por cada parte de la ruta. Los elementos de ruta del mapa que coinciden
con el texto de la plantilla tienen como nombre el propio elemento de
ruta y un valor true. Si la plantilla contiene un pseudonombre, como
{{name}} en la ruta de la plantilla, esa parte de la ruta se considera un
elemento con nombre, y se crea una entrada en el mapa con el valor
indicado (en este caso, "name"). Otros elementos del mapa que proporciona
el analizador incluyen:


+-------------+---------------------------------------------------------------+
| Campo       | Descripción                                                   |
+-------------+---------------------------------------------------------------+
| urlScheme   | el esquema de la URL, como "http" o "https"                   |
| urlHost     | el host de la URL, como "abc.com"                             |
| urlPort     | la cadena del puerto de la URL, si se indicó                  |
| urlUsername | El nombre de usuario de la URL, si se indicó                  |
| urlPassword | La contraseña de la URL, si se indicó                         |
| urlPath     | La cadena de ruta sin procesar de la URL                      |
| urlQuery    | Un map[string][]string por cada parámetro de consulta         |
|             | especificado                                                  |
+-------------+---------------------------------------------------------------+


Ten en cuenta que si no hay parámetros de consulta, o si falta cualquier
otra parte de la URL, entonces no hay entrada en el mapa para la parte
correspondiente. Además, el nombre de usuario y la contraseña generalmente
no son seguros cuando se usan como parte de una URL transmitida por una red.

.topic packages.rest.new
rest.New([username, password] string) (rest.Client, error)

Esto devuelve un identificador de conexión rest.Client, junto con un
error (nil si tiene éxito). Si se proporcionan el nombre de usuario y
la contraseña opcionales, el cliente usa autenticación HTTP Basic con
esas credenciales.

Nota de seguridad: New() nunca adjunta automáticamente el token de ego
logon de la sesión actual, ni siquiera sin argumentos, ya que Base()
de un cliente puede apuntar a cualquier servidor, incluido uno que no
controles. Un script que realmente necesite volver a llamar a su
propio servidor Ego usando la identidad ambiental debe activarlo
explícitamente con UseToken(true).

El elemento resultante se puede usar para realizar llamadas mediante la
conexión recién creada. Por ejemplo, si el valor de rest.New() se guardó
en la variable r, estarían disponibles los siguientes métodos de
configuración encadenables (fluent setters), cada uno de los cuales
devuelve el propio cliente para poder encadenar llamadas:

+-----------------+-------------------------------------------------------------+
| Método          | Descripción                                                 |
+-----------------+-------------------------------------------------------------+
| r.Base(url)     | Especifica una "URL base" que se antepone a la url usada en |
|                 | Get(), Post(), etc.                                         |
+-----------------+-------------------------------------------------------------+
| r.Media("type") | Especifica el tipo de medio/contenido del intercambio       |
+-----------------+-------------------------------------------------------------+
| r.Verify(b)     | Habilita o deshabilita la validación del certificado TLS del|
|                 | servidor                                                    |
+-----------------+-------------------------------------------------------------+
| r.Auth(u,p)     | Establece BasicAuth con el nombre de usuario y la contraseña|
|                 | indicados                                                   |
+-----------------+-------------------------------------------------------------+
| r.Token(t)      | Establece autenticación Bearer token con el valor de token  |
|                 | indicado                                                    |
+-----------------+-------------------------------------------------------------+
| r.UseToken(b)   | Adjunta (true) o quita (false) el token actual de ego logon |
|                 | como el bearer token de este cliente. Se rechaza en modo    |
|                 | sandbox.                                                    |
+-----------------+-------------------------------------------------------------+

Los métodos que realmente realizan una solicitud devuelven (value, error),
donde el error refleja únicamente un fallo a nivel de transporte -- un
estado de error a nivel HTTP como 404 no se considera un error para
estos métodos, y queda disponible después como r.Status:

+-----------------------+----------------------------------------------+
| Método                | Descripción                                  |
+-----------------------+----------------------------------------------+
| r.Get(url)            | Envía una solicitud GET                      |
+-----------------------+----------------------------------------------+
| r.Post(url [, body])  | Envía una solicitud POST                     |
+-----------------------+----------------------------------------------+
| r.Put(url [, body])   | Envía una solicitud PUT                      |
+-----------------------+----------------------------------------------+
| r.Patch(url [, body]) | Envía una solicitud PATCH                    |
+-----------------------+----------------------------------------------+
| r.Delete(url [, body])| Envía una solicitud DELETE                   |
+-----------------------+----------------------------------------------+
| r.Close()             | Cierra las conexiones inactivas que mantiene |
|                       | el cliente                                   |
+-----------------------+----------------------------------------------+

Además, los campos de solo lectura r.Status, r.Headers, r.Cookies,
r.Response y r.MediaType se pueden usar para examinar el código de
estado HTTP, los encabezados, las cookies y el cuerpo de la respuesta
de la última solicitud. El cuerpo de la respuesta es un valor de Ego
decodificado para una respuesta JSON, o una simple cadena en caso
contrario. La función a nivel de paquete rest.Status(code) string
devuelve una breve descripción legible de un código de estado HTTP
(por ejemplo, 200 -> "OK").

Aquí tienes un ejemplo sencillo:

    server := rest.New().Base("https://localhost")

    server.Get("/services/debug")

    if server.Status == http.StatusOK {
        // La carga útil de la respuesta es JSON, así que se decodifica
        // en una estructura. Ten en cuenta que este ejemplo solo
        // proporciona un parámetro, lo que significa que la estructura
        // resultante se define según lo que se encuentre en el JSON.
        resp := json.Unmarshal(server.Response)
        fmt.Println("Server session ID is ", resp.server.id)
    }

.topic packages.runtime

El paquete runtime expone una pequeña cantidad de información sobre la
plataforma en la que se ejecuta Ego y sobre el propio entorno de
ejecución de Ego, junto con algunas funciones que reflejan el paquete
runtime propio de Go.

runtime.GOOS y runtime.GOARCH son constantes que contienen el sistema
operativo y la arquitectura de procesador para los que se compiló Ego
("darwin", "linux", "windows", etc.; "amd64", "arm64", etc.).

runtime.Version() string devuelve la versión del compilador de Go
usada para compilar el ejecutable ego en ejecución. runtime.Ego()
string devuelve la versión del propio ejecutable ego.
runtime.Buildtime() (time.Time, error) devuelve la marca de tiempo en
que se compiló el ejecutable.

runtime.NumCPU() int devuelve el número de CPU lógicas disponibles.
runtime.GOMAXPROCS(n) int establece el número máximo de hilos del
sistema operativo que pueden ejecutar código Ego simultáneamente, y
devuelve el valor anterior; pasa 0 para consultar el valor actual sin
cambiarlo. runtime.GC() fuerza un ciclo inmediato de recolección de
basura.

.topic packages.runtime.frames

runtime.Frames(count int) []runtime.Frame devuelve hasta count marcos
de llamada que describen la pila de llamadas activa, comenzando por
el llamador inmediato y avanzando hacia afuera. Cada marco tiene un
Module (nombre de función o archivo), un Table (nombre del ámbito de
la tabla de símbolos) y un Line (número de línea de origen).

    func inner() {
        frames := runtime.Frames(5)
        for _, f := range frames {
            fmt.Println(f.Module, f.Line)
        }
    }

runtime.Stack(buf []byte, all bool) int da formato a una traza de
pila de llamadas legible dentro de buf y devuelve el número de bytes
escritos. El parámetro all se acepta por compatibilidad con
runtime.Stack() de Go, pero actualmente no tiene ningún efecto; solo
se formatea la pila de la goroutine que realiza la llamada.
.topic packages.sort

El paquete sort proporciona funciones de ordenación y búsqueda basadas en
el paquete sort de Go. Cada función modifica el arreglo in situ y también
devuelve el mismo arreglo (o un índice, en el caso de las funciones de
búsqueda) como su valor principal, junto con un error. Una estructura u
otro arreglo no escalar también se puede ordenar usando sort.Slice(), que
recibe una función de comparación personalizada; consulta el tema de
ayuda packages.sort.slice.

.topic packages.sort.ints

La función Ints ordena un arreglo de enteros. Los números negativos se
ordenan antes que los números positivos.

    a := []int{5, 3, 8, 0, -1}

    sort.Ints(a)


Después de ejecutar este código, el valor del arreglo es [-1, 0, 3, 5, 8].

.topic packages.sort.float32s

La función Float32s ordena un arreglo de números de coma flotante de 32
bits. Los números negativos se ordenan antes que los números positivos.

    a := []float32{5.3, 3, 8.001, 0, -1.5}

    sort.Float32s(a)


Después de ejecutar este código, el valor del arreglo es

    [-1.5, 0.0, 3.0, 5.3, 8.001].

.topic packages.sort.float64s

La función Float64s ordena un arreglo de números de coma flotante de 64
bits. Los números negativos se ordenan antes que los números positivos.

    a := []float64{5.3, 3, 8.001, 0, -1.5}

    sort.Float64s(a)


Después de ejecutar este código, el valor del arreglo es

    [-1.5, 0.0, 3.0, 5.3, 8.001].

.topic packages.sort.slice

La función Slice te permite ordenar un arreglo de un tipo que no sea
básico. Por ejemplo, podrías crear un arreglo de tipos de estructura; las
funciones de ordenación incorporadas no saben cómo ordenar esa
estructura. Puedes ordenarlo usando la función Slice proporcionando una
función constante capaz de decidir cuál de dos elementos del arreglo es
menor que el otro. Aunque los ejemplos podrían ser más complejos, aquí
tienes uno usando valores enteros:

    a := []int{ 101, 5, 33, -55, 239, 3, 66}

    sort.Slice(a, func(i int, j int) bool {
        return a[i] < a[j]
    })


Cuando esto se ejecuta, el arreglo a quedará ordenado. El algoritmo del
paquete sort llama a la función constante (la función de comparación)
tantas veces como sea necesario para comparar dos valores del arreglo. La
función debe aceptar dos valores enteros como argumentos y devolver un
valor bool. El resultado de la función determina si el elemento i del
arreglo es menor que el elemento j del arreglo. La función Slice gestiona
el algoritmo de ordenación y llama a la función que proporcionaste cada
vez que necesita comparar dos valores.

Ten en cuenta que la función de comparación debe definirse como una
función constante anónima en la propia llamada, de modo que tenga acceso
a valores fuera del ámbito de la función (específicamente, el valor del
arreglo)

.topic packages.sort.strings

La función Strings ordena un arreglo de cadenas. Una cadena vacía se
ordena al principio de la lista.

    a := []string{"apple", "pear", "", "cherry"}

    sort.Strings(a)


Después de ejecutar este código, el valor del arreglo es

    ["", "apple", "cherry", "pear"].

.topic packages.sort.other

Además de Ints, Float32s, Float64s, Strings y Slice, el paquete sort
también ofrece:

+---------------------------------------------+-----------------------------------------+
| Función                                     | Descripción                             |
+---------------------------------------------+-----------------------------------------+

+---------------------------------------------+-----------------------------------------+
| sort.Bytes(a)                               | Ordena un arreglo []byte                |
+---------------------------------------------+-----------------------------------------+
| sort.Sort(a) / sort.Stable(a)               | Ordena cualquier arreglo escalar        |

|                                             | de los elementos que se comparan iguales|

    sort.Slice(people, func(i int, j int) bool {

.topic packages.sql

El paquete sql proporciona acceso a bases de datos, con soporte para una
base de datos Postgres (o cualquier base de datos que use el protocolo
de red de Postgres), una base de datos SQLite en el sistema de archivos,
o un nombre de origen de datos (DSN) preregistrado con el servidor de
Ego. Cada función de este paquete que puede fallar devuelve un par
(valor, error).

.topic packages.sql.open

sql.Open(driver, connectionString) crea un identificador de conexión
sql.Database. El driver debe ser uno de los siguientes:

* sqlite   - connectionString es una ruta del sistema de archivos
             ("sqlite3" se acepta como alias obsoleto de este driver)
* postgres - una cadena de conexión o URL de Postgres, como
             "postgres://user:pass@host/dbname?sslmode=disable"
* dsn      - el nombre de un origen de datos preregistrado con el servidor

    d, err := sql.Open("sqlite", "/tmp/example.db")
    r, err := d.QueryResult("select * from member")
    d.Close()

QueryResult() siempre obtiene todo el conjunto de resultados de una vez,
lo cual puede consumir mucha memoria en una consulta sin filtrado; usa
Query() y su cursor en su lugar para conjuntos de resultados grandes.
Los parámetros de la consulta se pasan como argumentos adicionales y se
sustituyen posicionalmente usando $1, $2, etc.

    age := 21
    r, err := d.QueryResult("select * from member where age >= $1", age)

Como medida de seguridad, siempre se rechaza abrir una base de datos
SQLite cuyo nombre de archivo coincide con el de la propia base de datos
de credenciales del servidor, sin importar el directorio.

.topic packages.sql.database

El identificador sql.Database devuelto por sql.Open() tiene estos campos:

+-------------+--------+--------------------------------------------------+
| Campo       | Tipo   | Descripción                                      |
+-------------+--------+--------------------------------------------------+
| StructMode  | bool   | Se establece mediante AsStruct(). Cuando es true,|
|             |        | las filas de Query() y QueryResult() son         |
|             |        | estructuras indexadas por nombre de columna en   |
|             |        | lugar de arreglos.                               |
+-------------+--------+--------------------------------------------------+
| Rowcount    | int    | Filas afectadas o devueltas por la llamada más   |
|             |        | reciente. Se restablece a -1 con Close().        |
+-------------+--------+--------------------------------------------------+
| Constr      | string | La cadena de conexión (con la contraseña oculta) |
|             |        | usada para abrir esta base de datos.             |
+-------------+--------+--------------------------------------------------+

y estos métodos:

+-------------------------------+-------------------------------------------+
| Método                        | Descripción                               |
+-------------------------------+-------------------------------------------+
| Begin()                       | Inicia una transacción. Solo puede haber  |
|                               | una transacción activa por conexión a la  |
|                               | vez.                                      |
+-------------------------------+-------------------------------------------+
| Commit()                      | Confirma la transacción activa            |
+-------------------------------+-------------------------------------------+
| Rollback()                    | Descarta la transacción activa            |
+-------------------------------+-------------------------------------------+
| Execute(q [, args...])        | Ejecuta una sentencia que no sea SELECT   |
|                               | con argumentos opcionales. El resultado   |
|                               | es el número de filas afectadas.          |
+-------------------------------+-------------------------------------------+
| Query(q [, args...])          | Ejecuta un SELECT y devuelve un cursor    |
|                               | sql.Rows                                  |
+-------------------------------+-------------------------------------------+
| QueryResult(q [, args...])    | Ejecuta un SELECT y obtiene de inmediato  |

+-------------------------------+-------------------------------------------+
| AsStruct(flag)                | Establece StructMode. Devuelve el         |

Mientras una transacción está activa (después de Begin() y antes de

.topic packages.sql.rows

El cursor sql.Rows devuelto por Database.Query() recorre un conjunto de
resultados fila por fila, sin cargarlo todo en memoria.

+-----------+---------------------------------------------------------------+
| Método    | Descripción                                                   |
+-----------+---------------------------------------------------------------+
| Next()    | Avanza a la siguiente fila. Devuelve false cuando el conjunto |
|           | de resultados se agota. Debe llamarse antes de cada Scan().   |
+-----------+---------------------------------------------------------------+
| Scan()    | Lee la fila actual; consulta más abajo sus dos formas de      |
|           | llamada.                                                      |
+-----------+---------------------------------------------------------------+
| Headings()| Nombres de columnas, en el orden de la lista SELECT.          |
+-----------+---------------------------------------------------------------+
| Close()   | Libera los recursos del cursor. Cierra siempre un cursor      |
|           | cuando termines de usarlo, incluso si se consumieron todas    |
|           | las filas.                                                    |
+-----------+---------------------------------------------------------------+

Scan() tiene dos convenciones de llamada. Sin argumentos, devuelve la
fila como su valor: un arreglo de valores de columna en el orden de la
lista SELECT (el comportamiento por defecto), o una estructura indexada
por nombre de columna cuando StructMode es true. Con un puntero
*interface{} por columna, imita el propio sql.Rows.Scan() de Go,
escribiendo cada valor de columna en el puntero correspondiente.

    rows, _ := d.Query("select id, name, age from member order by id")
    for rows.Next() {
        row, _ := rows.Scan()
        fmt.Println(row)
    }
    rows.Close()

.topic packages.strconv

El paquete strconv realiza conversiones de datos hacia o desde un valor
de cadena.

.topic packages.strconv.atoi
strconv.Atoi(text string) (int, error)

La función Atoi convierte una cadena (que contiene solo caracteres
ASCII) en un valor entero. Si la cadena no contiene una representación
válida de un entero, el resultado es cero y el valor de error indica que
la cadena no era válida.

    v, err := strconv.Atoi("42")

Atoi siempre usa base 10 y no reconoce los prefijos de radix 0x/0o/0b,
igual que el propio Atoi de Go (definido como ParseInt(s, 10, 0)). Usa
strconv.ParseInt(s, 0, 64) si necesitas que la base se infiera
automáticamente a partir del prefijo de la cadena.

Funciones de análisis relacionadas: strconv.ParseInt(s, base, bitSize)
(int64, error), strconv.ParseUint(s, base, bitSize) (uint64, error),
strconv.ParseFloat(s, bitSize) (float64, error),
strconv.ParseComplex(s, bitSize) (complex128, error), y
strconv.ParseBool(s) (bool, error), que acepta "1", "t", "T",
"TRUE", "true", "True" como true, y sus equivalentes como false.

.topic packages.strconv.formatbool
strconv.FormatBool(b bool) string

La función FormatBool da formato a un valor booleano. El resultado es la
cadena "true" o la cadena "false". No existe condición de error.

.topic packages.strconv.formatfloat
strconv.FormatFloat(f float64, format byte, precision int, bitsize int) string

La función FormatFloat da formato a un valor de coma flotante. El valor
format es un único byte que contiene un carácter que describe el formato
de salida esperado. El valor format debe ser uno de los siguientes:

+-----------+---------------------------------------------------------------+
| Formato   | Descripción                                                   |
+-----------+---------------------------------------------------------------+
| 'b'       | (-ddddp±ddd, un exponente binario)                            |
| 'e'       | (-d.dddde±dd, un exponente decimal)                           |
| 'E'       | (-d.ddddE±dd, un exponente decimal)                           |
| 'f'       | (-ddd.dddd, sin exponente)                                    |
| 'g'       | ('e' para exponentes grandes, 'f' en caso contrario)          |
| 'G'       | ('E' para exponentes grandes, 'f' en caso contrario)          |
| 'x'       | (-0xd.ddddp±ddd, una fracción hexadecimal y exponente binario)|
| 'X'       | (-0Xd.ddddP±ddd, una fracción hexadecimal y exponente binario)|
+-----------+---------------------------------------------------------------+


El valor precision describe la cantidad de dígitos que se formatearán a
la derecha del punto decimal (los ceros finales no se imprimen). Por
último, el valor bitsize indica si el valor de coma flotante presentado
es un float32 o un float64. No se permite ningún otro valor entero que
no sea 32 o 64.

.topic packages.strconv.formatint
strconv.FormatInt(i int64, base int) string

La función FormatInt da formato a un valor entero con signo en la base
indicada (2-36). Requiere un argumento int64; en modo dinámico, un int
simple se convierte automáticamente, pero en modo estricto se requiere
una conversión explícita int64(i). strconv.FormatUint(i uint64, base
int) string es el equivalente para enteros sin signo.

.topic packages.strconv.itoa
strconv.Itoa(i int) string

La función Itoa es una forma más simple de FormatInt y da formato a un
valor asumiendo base 10. Así, el entero 123 se convierte en la cadena
"123".

.topic packages.strconv.quote
strconv.Quote(text string) string

La función Quote encierra entre comillas el valor presentado. También
escapa cualquier comilla que ya esté presente en la cadena. Las funciones
relacionadas QuoteRune(r), QuoteToASCII(s), QuoteRuneToASCII(r),
QuoteToGraphic(s) y QuoteRuneToGraphic(r) ofrecen variantes que solo
escapan caracteres no ASCII o no gráficos.

.topic packages.strconv.unquote
strconv.Unquote(text string) (string, error)

La función Unquote elimina cualquier comilla de una cadena y también
convierte los caracteres de comilla escapados de vuelta a comillas
dobles en el valor de la cadena. También acepta un literal de rune entre
comillas simples o una cadena entre comillas invertidas (raw), y
devuelve un error si text no está correctamente entrecomillado.

.topic packages.strconv.roman

strconv.Itor(i int) (string, error) convierte un entero en el rango
1-3999 a una cadena de número romano; los valores fuera de ese rango
devuelven un error. strconv.Rtoi(s string) (int, error) convierte una
cadena de número romano de vuelta a un entero, sin distinguir mayúsculas
de minúsculas. Estas son incorporaciones exclusivas de Ego, sin
equivalente en el paquete strconv de Go.

    r, err := strconv.Itor(1994)   // "MCMXCIV"
    n, err := strconv.Rtoi("MCMXCIV")   // 1994

.topic packages.strings

El paquete strings contiene una biblioteca de funciones para manipular
datos de cadena. Salvo que se indique lo contrario, las cadenas se
interpretan como un conjunto de caracteres, de modo que algunos
caracteres unicode pueden ocupar más de un byte de almacenamiento.

.topic packages.strings.chars

La función Chars devuelve un arreglo de valores de cadena. Cada valor
representa un único carácter en esa posición de la cadena.

    runes := strings.Char("test")


El valor de runes es un arreglo de cadenas con los valores ["t", "e",
"s", "t"]. Si la cadena es una cadena vacía, el resultado es un arreglo
de cero elementos.

.topic packages.strings.compare

La función Compare compara dos valores de cadena y devuelve un entero
que contiene -1 si la primera cadena es menor que la segunda, 0 si son
iguales, o 1 si el segundo valor es menor que el primero.

    fmt.Println(strings.Compare("peach", "apple"))


Esto imprimirá el valor 1, ya que el segundo valor se ordena por encima
del primero.

.topic packages.strings.contains

La función Contains examina una cadena en busca de una subcadena y
devuelve un valor booleano que indica si la subcadena existe dentro de
la cadena

    a := strings.Contains("This is a test", "is a")
    b := strings.Contains("This is a test", "isa")


En este ejemplo, a contiene el valor true y b contiene el valor false.
Ten en cuenta que la subcadena debe coincidir exactamente, incluidos los
espacios en blanco, para considerarse una coincidencia.

.topic packages.strings.containsany

La función ContainsAny examina una cadena para comprobar si aparecen en
ella instancias de alguno de los caracteres de una subcadena.

    a := strings.ContainsAny("this is a test", "satx")
    b := strings.ContainsAny("this is a test", "xyz")


En este ejemplo, a es true porque la cadena contiene al menos uno de los
caracteres de la subcadena (hay instancias de "s", "a" y "t"). El valor
de b es false porque la cadena no contiene ninguna instancia de ("x",
"y" o "z")

.topic packages.strings.equalfold

La función EqualFold compara dos cadenas para ver si son iguales, sin
tener en cuenta las diferencias de mayúsculas y minúsculas.

    a := strings.EqualFold("symphony b", "Symphony B")
    b := strings.EqualFold("åto", "Åto")


En ambos ejemplos, el resultado es true.

.topic packages.strings.fields

La función Fields divide una cadena en cadenas individuales según los
caracteres de espacio en blanco.

    s := "this is    a test"
    b := strings.Fields(s)


El resultado es que b contendrá el arreglo ["this", "is", "a", "test"]

.topic packages.strings.join

La función Join une un arreglo de cadenas usando una cadena separadora.
El separador se coloca entre los elementos, pero no al principio ni al
final de la cadena resultante.

    a := []string{ "usr", "local", "bin"}
    b := strings.Join(a, "/")


El resultado es que b contiene la cadena "usr/local/bin". Esta función
se usa habitualmente para crear listas (con "," como separador) o rutas
de archivo (usando un separador de ruta específico del sistema, como
"/" o "\").

.topic packages.strings.format

La función Format() es equivalente a fmt.Sprintf(): el primer argumento
es una cadena de formato que usa los verbos estándar %d/%s/%f/%q/etc., y
los argumentos restantes se sustituyen en ella en orden. El resultado
con formato se devuelve como una cadena en lugar de imprimirse.

    strings.Format("%s has %d items", "cart", 3)   // "cart has 3 items"

.topic packages.strings.index

La función Index busca en una cadena la primera aparición de la cadena
test. Si la encuentra, devuelve la posición del primer carácter de
string que contiene el valor de test. Si no se encuentra ninguna
instancia de la cadena test, la función devuelve -1.

    a := strings.Index("this is a test", "is")
    b := strings.Index("this is a test", "isa")

Las funciones relacionadas IndexAny(text, chars), IndexByte(text, c) e
IndexRune(text, r) buscan, respectivamente, cualquiera de un conjunto de
caracteres, un único byte o un único rune.

.topic packages.strings.ints

La función Ints devuelve un arreglo de valores enteros. Cada valor
representa el carácter Unicode de esa posición en la cadena, expresado
como un valor entero.

runes := strings.Ints("test")


El valor de runes es un arreglo de enteros con los valores [116, 101,
115, 116], que son los valores de carácter Unicode de las letras "t",
"e", "s" y "t". Si la cadena pasada es una cadena vacía, la función Ints
devuelve un arreglo vacío.

.topic packages.strings.left

La función Left() devuelve los caracteres situados más a la izquierda de
la cadena dada. Si el valor del parámetro count es menor que 1, se
devuelve una cadena vacía. Si el valor de count es mayor que la longitud
de la cadena, se devuelve la cadena completa.


    name := "Bob Smith"
    first := strings.Left(name, 3)


En este ejemplo, el valor de first será "Bob".

.topic packages.strings.length

La función Length() devuelve la longitud de una cadena en caracteres.
Esto es diferente de la función incorporada len(), que devuelve la
longitud de una cadena en bytes. Esta diferencia se debe a que un
carácter puede ocupar más de un byte. Por ejemplo,

    str := "\u2813foo\u2813"
    a := len(str)
    b := strings.Length(str)


En este ejemplo, el valor de a será 9, que es el número de bytes
almacenados en la cadena. Pero como el primer y el último carácter son
caracteres unicode que ocupan varios bytes, el valor de b será 5, lo que
indica que hay cinco caracteres en la cadena.

.topic packages.strings.right

La función Right() devuelve los caracteres situados más a la derecha de
la cadena dada. Si el valor del parámetro count es menor que 1, se
devuelve una cadena vacía. Si el valor de count es mayor que la longitud
de la cadena, se devuelve la cadena completa.

    name := "Bob Smith"
    last := strings.Right(name, 5)


En este ejemplo, el valor de last será "Smith".

.topic packages.strings.split

La función Split() divide una cadena en un arreglo de cadenas, según un
carácter delimitador proporcionado. Si el carácter no está presente, se
asume un salto de línea como carácter delimitador.

    a := "This is\na test\nstring"
    b := strings.Split(a)


En este ejemplo, b será un arreglo de cadenas con tres elementos, uno
por cada línea de la cadena:  ["This is", "a test", "string"]. Si la
cadena proporcionada era una cadena vacía, el resultado es un arreglo
vacío.

Si deseas usar tu propio delimitador, puedes proporcionarlo como segundo
parámetro. Por ejemplo,

    a := "101, 553, 223, 59"
    b := strings.Split(a, ", ")


Esto usa la cadena ", " como delimitador. Ten en cuenta que debe
coincidir exactamente, por lo que el espacio es significativo. El valor
de b será

    ["101", "553", "223", "59"].
.topic packages.strings.string

La función String() construye una cadena a partir de un arreglo de
valores numéricos o valores de cadena.

    a := strings.String(115, 101, 116, 115)


Esto da como resultado a con el valor "sets", donde cada valor
entero se utilizó como una especificación de carácter Unicode para
construir la cadena.

    b := strings.String("this", "and", "that")


También puedes especificar argumentos que sean valores de cadena
(incluyendo caracteres individuales), y se concatenan entre sí para
formar una cadena. En el ejemplo anterior, b contiene la cadena
"thisandthat".

.topic packages.strings.substring

La función Substring() extrae una parte de la cadena proporcionada.
La posición de inicio es la posición del primer carácter a incluir
(basada en 1), y count es el número de caracteres a incluir en el
resultado. Por ejemplo,

    name := "Abe Lincoln"
    part := strings.Substring(name, 5, 4)


Esto haría que part contuviera la cadena "Linc", que representa el
inicio a partir del quinto carácter, con una longitud de cuatro
caracteres.

.topic packages.strings.template

La función Template() ejecuta una operación de plantilla, utilizando
las estructuras de datos proporcionadas. Consulta la directiva
@template para más detalles sobre cómo crear un nombre de plantilla.
La estructura contiene valores que pueden sustituirse en la plantilla
a medida que se procesa. Los campos de la estructura se usan como
nombres de sustitución en la plantilla, y los valores de los campos
se usan en su lugar dentro de la cadena.

    @template myNameIs Hello, my name is {{.First}} {{.Last}}

    person := { First: "Tom", Last: "Smith"}
    label , err := strings.Template( myNameIs, person )

    if err != nil {
        fmt.Println(err)
    } else {
        fmt.Println(label)
    }


Este programa imprimirá la cadena "Hello, my name is Tom Smith". Las
sustituciones de plantilla {{.First}} y {{.Last}} extraen los nombres
de campo especificados de la estructura. Ten en cuenta que, a
diferencia de las plantillas de Go, puedes referenciar una plantilla
dentro de otra plantilla sin necesidad de ninguna acción especial
adicional. Así, la plantilla puede usar la sintaxis
{{template "name"}}, y mientras hayas ejecutado una operación
@template para la plantilla "name", esta se incluirá automáticamente
en la plantilla antes de ejecutar la consulta.

Ten en cuenta que @template crea un símbolo con la plantilla dada,
pero ese valor solo puede usarse en la llamada a strings.Template()
para identificar la plantilla específica a utilizar.

.topic packages.strings.tolower

La función ToLower() convierte los caracteres de una cadena a la
versión en minúsculas de ese carácter, si existe una. Si no hay
versión en minúsculas para un carácter dado, ese carácter no se ve
afectado en el resultado.

    a := "Mazda626"
    b := strings.ToLower(a)


En este ejemplo, el valor de b será "mazda626".

.topic packages.strings.toupper

La función ToUpper() convierte los caracteres de una cadena a la
versión en mayúsculas de ese carácter, si existe una. Si no hay un
valor en mayúsculas para un carácter dado, ese carácter no se ve
afectado en el resultado.

    a := "Bang+Olafsen"
    b := strings.ToUpper(a)


En este ejemplo, el valor de b será "BANG+OLAFSEN".

.topic packages.strings.tokenize

La función Tokenize() utiliza el analizador léxico incorporado para
dividir una cadena en sus tokens según las reglas del lenguaje Ego.
El resultado se devuelve como un arreglo.

    s := "x{} <- f(3, 4)"
    t := strings.Tokenize(s)



Esto hace que t sea un arreglo []struct. Por ejemplo, t[0] contiene
la estructura

    {kind:"Identifier", spelling:"x"}

y t[1] contiene la estructura

    {kind:"Special":, spelling:"{}"}

Ten en cuenta que {} se considera un único token en el lenguaje,
igual que <-, por lo que cada uno ocupa un único token en el arreglo
resultante de estructuras de token. El analizador léxico también
convierte valores enteros en otras bases (como el valor binario
0b101) en enteros decimales, de modo que la estructura resultante
para ese token sería

    {kind: "Integer", spelling: "5"}

.topic packages.strings.truncate

La función Truncate() trunca una cadena que es demasiado larga, y
añade el carácter de puntos suspensivos ("...") al final para
mostrar que hay más información que no se incluyó.

    a := "highway bridge out of order"
    msg := strings.Truncate(a, 10)


En este ejemplo, el valor de msg es "highway...". Esto es para
asegurar que la cadena resultante tenga solo diez caracteres de
longitud (la longitud especificada como segundo parámetro). Si la
cadena no es más larga que el número indicado, se devuelve la cadena
completa.

.topic packages.strings.urlpattern

La función URLPattern() puede usarse en un servicio web para
determinar qué partes de una URL están presentes. Esto es
particularmente útil cuando se usan nombres de URL de estilo
colección, donde cada parte de la ruta podría definir un tipo de
colección, seguido opcionalmente de un identificador de instancia de
un miembro específico de dicha colección, etc. Considera el
siguiente ejemplo:


    p := "/services/proc/{{pid}}/memory"
    u := "/services/proc/1553/memory"

    m := strings.URLPattern(u,p)


La variable p contiene un patrón. Contiene varios segmentos de la
URL, y para uno de ellos, especifica el indicador de un valor de
sustitución. Es decir, en esa parte de la URL, se acepta cualquier
valor y se nombrará "pid". El mapa resultante generado por la
llamada se ve así:

    {
        "services" : true,
        "proc": true,
        "pid": "1553",
        "memory": true,
    }


Para los elementos que son segmentos constantes de la URL, el mapa
contiene un valor booleano que indica si se encontró en el patrón.
Para el (los) operador(es) de sustitución en el patrón, la clave del
mapa es el nombre proveniente del patrón, y el valor es el valor
tomado de la URL. Ten en cuenta que esto puede usarse para
determinar rutas parciales:

    p := "/services/proc/{{pid}}/memory"
    u := "/services/proc/"

    m := strings.URLPattern(u,p)


En este caso, el mapa resultante tendrá un miembro "pid" que es una
cadena vacía, y un valor "memory" que es false, lo cual indica que
ni el valor de sustitución ni el campo con nombre están presentes en
la URL.

Puedes especificar un patrón que cubra toda una jerarquía, y el
resultado indicará cuánto de la jerarquía se devolvió.

    p := "/services/location/state/{{stateName}}/city/{{cityName}}


Si la URL proporcionada fuera /services/location/state/nc/city/cary
entonces el mapa sería:

    {
        "services" : true,
        "location" : true,
        "state" : true,
        "stateName" : "nc",
        "city" : true,
        "cityName" : "cary",
    }


Pero, si la URL proporcionada solo tuviera
services/location/state/nc, el mapa resultante sería:

    {
        "services" : true,
        "location" : true,
        "state" : true,
        "stateName" : "nc",
        "city" : false,
        "cityName" : "",
    }


Si la URL no incluyera el campo del nombre del estado, este quedaría
en blanco, lo cual podría indicarle al servicio que un GET sobre esa
URL tenía como intención devolver una lista de los valores de estado
almacenados, en lugar de información sobre un estado específico.

.topic packages.sync

El paquete sync proporciona acceso a operaciones primitivas de bajo
nivel usadas para sincronizar operaciones entre distintos hilos de
goroutine que podrían estar ejecutándose de forma concurrente.

.topic packages.sync.mutex

Este es un tipo proporcionado por el paquete sync, usado para
realizar operaciones simples de exclusión mutua para controlar el
acceso a recursos. El mutex puede ser bloqueado por un usuario, en
cuyo caso cualquier intento de otro hilo de bloquear el elemento
hará que ese hilo espere hasta que el mutex sea desbloqueado por el
primer propietario. Considera el siguiente código:

    var counter int

    func worker(id int) {
        counter = counter + 1
        myCount := counter

        fmt.Printf("thread %d, counter %d\n", id, myCount)
    }

    func main() int {
        workers := 5

        for i := 0 ; i < workers; i = i + 1 {
            go worker(i)
        }

        d, _ := time.ParseDuration("1s")
        time.Sleep(d)

        return 0
    }


Tal como está escrito arriba, el código lanzará cinco goroutines que
harán todas la misma operación simple: incrementar el contador y
luego imprimir su valor en el momento en que se ejecutó la
goroutine. Sabemos que las goroutines se ejecutan en un orden
impredecible, pero incluso si viéramos los números impresos fuera de
orden, seguiríamos viendo que los valores del contador se
incrementan como 1, 2, 3, 4 y 5.

Pero, dado que las goroutines se ejecutan de forma simultánea, entre
el momento en que una rutina obtiene el valor del contador, le suma
uno y lo vuelve a guardar, otra rutina podría haber realizado la
misma operación. Esto significa que sobrescribiríamos el valor del
otro hilo. En este caso, la salida del valor del contador podría
verse más o menos así:

    thread 0, counter 1
    thread 4, counter 1
    thread 2, counter 2
    thread 3, counter 2
    thread 1, counter 3


Para solucionar esto, usamos un valor mutex para bloquear el acceso
al contador para cada hilo, de modo que se vean forzados a turnarse
para incrementar el contador.


    var counter int
    var mutex sync.Mutex

    func worker(id int) {
        mutex.Lock()

        counter = counter + 1
        myCount := counter

        mutex.Unlock()
        fmt.Printf("thread %d, counter %d\n", id, myCount)
    }

    func main() int {
        workers := 5

        for i := 0 ; i < workers; i = i + 1 {
            go worker(i)
        }

        d, _ := time.ParseDuration("1s")
        time.Sleep(d)

        return 0
    }


Ahora que hay un mutex protegiendo el acceso al contador, sin
importar en qué orden se ejecuten las goroutines, el incremento del
valor del contador siempre será secuencial, resultando en una salida
que podría verse así:

    thread 4, counter 1
    thread 0, counter 2
    thread 2, counter 3
    thread 3, counter 4
    thread 1, counter 5

Mutex también admite TryLock(), que intenta adquirir el bloqueo sin
bloquearse: devuelve true si el bloqueo se adquirió (en cuyo caso el
llamador ahora es responsable de llamar a Unlock()), o false
inmediatamente si alguna otra goroutine ya lo tiene. Llamar a
Unlock() sobre un Mutex que no está actualmente bloqueado es un
error detectable de Ego, en lugar de una caída del programa.

.topic packages.sync.rwmutex

sync.RWMutex es un bloqueo de exclusión mutua de lector/escritor:
cualquier número de lectores puede tener el bloqueo al mismo tiempo
mediante RLock()/RUnlock(), pero un escritor que lo tenga mediante
Lock()/Unlock() lo posee en exclusiva. Esto es útil cuando un
recurso se lee con mucha más frecuencia de la que se escribe.

    var mu sync.RWMutex

    func read(key string) (int, bool) {
        mu.RLock()
        defer mu.RUnlock()
        v, ok := data[key]
        return v, ok
    }

    func write(key string, value int) {
        mu.Lock()
        defer mu.Unlock()
        data[key] = value
    }

RWMutex también admite adquisición sin bloqueo: TryLock() intenta
adquirir el bloqueo exclusivo de escritura, y TryRLock() intenta
adquirir un bloqueo de lectura; ambos devuelven true en caso de
éxito sin bloquearse, o false inmediatamente si el bloqueo no está
disponible en ese momento.

.topic packages.sync.waitgroup

Este es un tipo proporcionado por el paquete sync. Puedes declarar
una variable de este tipo y se crea un WaitGroup, que puede
almacenarse en una variable. Este valor se usa como un semáforo de
conteo y normalmente admite un número arbitrario de inicios y
finalizaciones de goroutines.

Considera este código de ejemplo:

    func thread(id int, wg *sync.WaitGroup) {               // [1]
        fmt.Printf("Thread %d\n", id)
        wg.Done()                                           // [2]
    }

    func main() int {
        var wg sync.WaitGroup                               // [3]

        count := 5
        for i := 1; i <= count; i = i + 1 {
            wg.Add(1)                                       // [4]
            go thread(i, &wg)                               // [5]
        }

        wg.Wait()                                           // [6]

        fmt.Println("all done")
    }


Este programa lanza cinco instancias de una goroutine thread, y
espera a que se completen. Este ejemplo simplificado no devuelve
ningún valor desde los hilos, por lo que no se usan canales. Sin
embargo, el llamador debe saber cuándo han terminado todas las
goroutines para saber que es seguro salir de esta función. Ten en
cuenta que si el código no incluyera la llamada a wg.Wait(),
entonces la función main saldría antes de que la mayoría de las
goroutines tuvieran oportunidad de completarse.

Aquí tienes un desglose de los pasos importantes de este ejemplo:

1. En esta declaración de la función usada como goroutine, se pasa
   un parámetro que es un puntero a la variable WaitGroup. Esto es
   importante porque las operaciones sobre la variable WaitGroup
   deben realizarse sobre la misma instancia de esa variable.

2. La llamada a Done() la realiza la goroutine cuando ha completado
   todas sus operaciones. Para asegurar que siempre se ejecute
   cuando la función termine, esto también podría implementarse
   como defer wg.Done()

3. Esto declara la instancia de la variable WaitGroup que se usará
   en este ejemplo. No se necesita inicialización; la instancia de
   la variable comienza en su estado de valor cero.

4. Antes de lanzar una goroutine, se suma 1 al valor de WaitGroup
   (en realidad puede ser un número distinto de 1, pero debe
   corresponder exactamente con el número de llamadas a Done() que
   se harán para indicar la finalización de la tarea). Es esencial
   que esta llamada se haga antes de la sentencia go, para asegurar
   que la goroutine no se complete antes de que se pueda realizar la
   llamada a Add().

5. Ten en cuenta que la variable WaitGroup debe pasarse por
   dirección. Por defecto, Ego pasa todos los parámetros por valor
   (es decir, se pasa a la función una copia del valor). Pero como
   las funciones deben operar sobre exactamente la misma instancia
   de una variable WaitGroup, debemos pasar la dirección del valor
   asignado. Ten en cuenta que es importante que este valor no salga
   de ámbito antes de que se pueda realizar la llamada a Wait().

6. La llamada a Wait() esencialmente espera hasta que se hayan
   realizado tantas llamadas a Done() como las indicadas por las
   llamadas correspondientes a Add(). Hasta entonces, el programa
   actual simplemente esperará, y luego reanudará la ejecución
   después de que se llame a la última Done().

.topic packages.reflect

El paquete reflect proporciona funciones que permiten que un
programa Ego descubra información sobre valores y tipos nativos.

Ten en cuenta que esto no corresponde al paquete nativo de Go del
mismo nombre.

En Ego, un tipo en sí mismo es un valor que puede almacenarse en una
variable, pasarse como argumento, compararse y reasignarse, igual
que cualquier otro valor (en modo dinámico, el predeterminado). Los
nombres de tipo incorporados (int, string, bool, etc.), los nombres
de tipos definidos por el usuario, y los resultados de
reflect.Type() son todos valores de este tipo:

    t := int      // t now holds the type value "int"
    var x t       // declares x with the type held in t; x is 0

.topic packages.reflect.type
reflect.Type(value any) type

Devuelve el tipo de value como un valor de tipo de primera clase. El
resultado puede compararse con un nombre de tipo incorporado, un
nombre de tipo definido por el usuario, o el tipo de otro valor,
usando ==/!=:

    a := 425.3
    b := reflect.Type(a)
    if b == float64 {
        fmt.Println("The value is a float64")
    }

reflect.Type() también está disponible como la función incorporada
typeof(), con una diferencia: typeof() es una extensión del lenguaje
y solo funciona cuando las extensiones están habilitadas;
reflect.Type() funciona sin importar esa configuración, ya que es
una llamada de función de paquete normal.

.topic packages.reflect.reflect
reflect.Reflect(value any) reflect.Reflection

Devuelve una estructura reflect.Reflection que describe value con
más detalle que reflect.Type() por sí solo. No todos los campos se
completan para cada tipo de valor.

+-------------+---------------------+-------------------------------------+
| Campo       | Tipo                | Descripción                         |
+-------------+---------------------+-------------------------------------+
| Type        | string              | El nombre de tipo Ego del valor     |
+-------------+---------------------+-------------------------------------+
| BaseType    | string              | El tipo subyacente                  |
+-------------+---------------------+-------------------------------------+
| Name        | string              | Nombre, para funciones/tipos con    |
|             |                     | nombre                              |
+-------------+---------------------+-------------------------------------+
| Package     | string              | Paquete al que pertenece el tipo, si|
|             |                     | aplica                              |
+-------------+---------------------+-------------------------------------+
| IsType      | bool                | true si value era en sí mismo un    |
|             |                     | tipo                                |
+-------------+---------------------+-------------------------------------+
| Native      | bool                | true si es un tipo/función nativo de|
|             |                     | Go                                  |
+-------------+---------------------+-------------------------------------+
| Members     | []string            | Nombres de campos/claves/miembros   |
|             |                     | exportados                          |
+-------------+---------------------+-------------------------------------+
| Declaration | reflect.Function    | Nombre, parámetros, tipos de retorno|
+-------------+---------------------+-------------------------------------+
| Size        | int                 | Tamaño en bytes, o cantidad de      |
|             |                     | elementos/miembros                  |
+-------------+---------------------+-------------------------------------+

    e := { name: "Dave", age: 33 }
    r := reflect.Reflect(e)
    fmt.Println(r.Type)     // struct
    fmt.Println(r.Members)  // ["name", "age"]

.topic packages.reflect.members
reflect.Members(value any) ([]string, error)

Devuelve los nombres de los campos (para una estructura), las claves
(para un mapa, ordenadas alfabéticamente), o los miembros exportados
(para un paquete, ordenados alfabéticamente) en value, junto con un
error. Cualquier otro tipo de valor produce un error distinto de
nil.

    e := { name: "Dave", age: 33 }
    m, err := reflect.Members(e)


Para una estructura, los nombres se devuelven en el orden de
declaración de los campos, no alfabéticamente: { name: "Dave", age:
33 } produce ["name", "age"]. Los nombres resultantes pueden usarse
para acceder a los campos de la estructura mediante notación de
índice:

    e[m[0]] = "Changed"   // sets e.name, since m[0] == "name"

.topic packages.reflect.instanceof
reflect.InstanceOf(value any) any

Devuelve un "valor cero" basado en el tipo de value: 0 para tipos
numéricos, "" para string, false para bool, un mapa vacío o un
arreglo de longitud cero para un mapa o arreglo, y una instancia
recién creada con valor cero para una estructura. value puede ser un
valor de ejemplo de cualquier tipo, un valor de tipo (un nombre de
tipo incorporado, un tipo definido por el usuario, o el resultado de
reflect.Type()), o un valor de estructura/arreglo/mapa (en cuyo caso
el resultado es una instancia vacía con la misma forma, no una copia
del contenido).

    a := reflect.InstanceOf(42)       // 0
    b := reflect.InstanceOf(string)   // ""
    c := reflect.InstanceOf(false)    // false

.topic packages.reflect.deepcopy
reflect.DeepCopy(value any [, depth int]) (any, error)

Crea una copia independiente de value, junto con un error (el único
modo de fallo es un depth no numérico). Los valores escalares se
copian de forma trivial. Para una estructura, arreglo, mapa o
paquete, cada miembro anidado también se copia de forma recursiva,
de modo que el resultado no comparte ningún estado mutable con el
original. depth limita cuántos niveles de anidamiento se copian
antes de que DeepCopy deje de recursionar (el valor predeterminado
es 100).
.topic packages.tables

El paquete tables ofrece funciones para ayudar a los programas a producir
tablas de texto con datos para la salida. El paquete te permite crear un
objeto de tabla con un conjunto determinado de nombres de columna. Puedes
añadir filas a la tabla, ordenarla, especificar opciones de formato para
la tabla y luego generar una versión en texto o json de los datos de la
tabla.

.topic packages.tables.new
tables.New("colname" [, "colname"...]) tables.Table

Esto da acceso al subsistema de formato e impresión de tablas para
programas Ego. Los argumentos deben ser los nombres de las columnas de
la tabla resultante. Se pueden pasar como argumentos separados, o como
un arreglo de cadenas. El resultado es un objeto Table que se puede usar
para insertar datos en la estructura de la tabla, ordenarla y darle
formato para la salida.


    t := tables.New(":Identity", "Age:", "Address")

    t.AddRow( {Identity: "Tony", Age: 61, Address: "Main St"} )
    t.AddRow( {Identity: "Mary", Age: 60, Address: "Elm St"} )
    t.AddRow( {Identity: "Andy", Age: 61, Address: "Elm St"} )

    t.Sort( "Age", "Identity" )

    t.Format(true,false)
    t.Print()
    t.Close()


Este programa de ejemplo crea una tabla con tres encabezados de columna.
El uso del carácter ":" controla la alineación de la columna. Si los dos
puntos están en el lado izquierdo o derecho del encabezado, así es como
se alinea el encabezado. Si no se usan dos puntos, el valor
predeterminado es alineado a la izquierda.

Se añaden los datos de tres filas. Ten en cuenta que los datos se pueden
añadir como una estructura, donde los nombres de columna deben coincidir
con los nombres de los campos de la estructura. Alternativamente, los
valores se pueden añadir como argumentos separados de la función, en
cuyo caso se añaden en el orden de los encabezados de columna.

El formato de la tabla se ajusta aún más ordenando los datos por Age y
luego por Identity, e indicando que se deben imprimir los encabezados,
pero no los subrayados debajo de esos encabezados. La tabla se imprime
luego en la salida predeterminada y se liberan las estructuras de
memoria.

.topic packages.time

El paquete time ayuda con funciones que acceden o calculan valores de
fecha/hora. Esto es similar al paquete "time" de Go, pero tiene
diferencias significativas y no es tan completo como la versión de Go.
Las funciones time.Now() y time.Parse() crean cada una un nuevo tipo de
variable time.Time, que tiene un conjunto de funciones que se pueden
ejecutar sobre él.

+------------+----------------------------+------------------------------------+
| Función    | Ejemplo                    | Descripción                        |
+------------+----------------------------+------------------------------------+
| Add        | n := t.Add(nt)             | Suma un valor de tiempo a otro     |
+------------+----------------------------+------------------------------------+
| Format     | f := t.Format("Mon Jan 2") | Da formato al valor de tiempo      |
|            |                            | según la fecha de referencia       |
+------------+----------------------------+------------------------------------+
| SleepUntil | t.SleepUntil()             | Pausa la ejecución hasta esa hora  |
+------------+----------------------------+------------------------------------+
| String     | f := t.String()            | Convierte el valor de tiempo en    |
|            |                            | una representación de cadena       |
+------------+----------------------------+------------------------------------+
| Sub        | n := t.Sub(start)          | Resta un valor de tiempo de otro   |
+------------+----------------------------+------------------------------------+

Una nota sobre el operador Format(). La cadena de formato debe estar
compuesta de elementos de la fecha de referencia, que es un valor de
fecha específico "Mon Jan 2 15:04:05 -0700 MST 2006". Este valor también
está disponible como time.reference si necesitas referenciarlo. Cada
parte de la fecha tiene un valor único, así que la llamada a Format() en
la tabla de arriba imprimirá el día de la semana, el mes y el día, ya
que esos son los valores usados de la cadena de referencia en la
especificación de formato.

.topic packages.time.now

La función Now() obtiene la hora actual en el momento de la llamada, y
la establece como el valor de tiempo en el resultado.

    now := time.Now()
    ...
    elapsed := time.Now().Sub(now)


En este caso, el código primero captura la hora actual y la guarda en
la variable now. Luego realiza otro trabajo para el programa, y cuando
termina queremos averiguar el tiempo transcurrido. El valor de elapsed
es una cadena de duración que indica cuánto tiempo pasó entre el valor
now y la hora actual. Por ejemplo, esto podría ser un valor como "5s"
para cinco segundos transcurridos.

.topic packages.time.parse

Esto convierte una representación textual de una hora en un valor de
tiempo. El primer parámetro es la cadena de formato para la fecha a
convertir, y el segundo parámetro es el valor a analizar. Esto usa los
mismos valores de fecha específicos de la hora time.reference.

    s := "12/7/1960 15:30"
    m := "1/2/2006 15:04"
    t := time.Parse(m, s)


El valor de tiempo guardado en t es el valor "Wed Dec 7 15:30:00 UTC
1960". Ten en cuenta que el modelo mostró un mes de 1 (para enero) pero
seguía usando los valores específicos de la hora de referencia. Las
barras no forman parte de la hora de referencia, así que deben existir
en las mismas posiciones en la cadena a convertir y serán omitidas.

Si hay un error al analizar, el valor de t será nil. Puedes averiguar
el error exacto permitiendo que la función time.Parse() devuelva dos
valores:


    t, e := time.Parse(m, s)


Si el valor de t es nil, entonces el valor de e será el código de error
que refleja el error de análisis. Si la llamada se hace especificando
solo un valor de retorno, el error se descarta.

.topic packages.time.sleep

La función Sleep() del paquete time hará que el programa duerma durante
el tiempo especificado. La duración se expresa como una duración, que
se puede analizar a partir de una cadena. Ten en cuenta que la
operación de análisis devuelve un segundo resultado de error si el
análisis no se puede procesar. Por ejemplo,

    d, _ := time.ParseDuration("10s")
    time.Sleep(d)


Esto hará que el programa duerma durante diez segundos. El sufijo puede
ser "h", "m" o "s" y puede incluir valores fraccionarios. Mientras el
sistema duerme, las goroutines seguirán ejecutándose, pero el programa
actual (o la goroutine actual) dejará de ejecutarse durante la duración
indicada.

.topic packages.util

El paquete util contiene funciones utilitarias diversas que pueden ser
convenientes para los desarrolladores que escriben programas Ego.

.topic packages.util.setlogger

La función SetLogger() habilita o deshabilita registradores específicos
en tiempo de ejecución. Esto se puede usar para activar el rastreo
(trace) en modo interactivo, por ejemplo.

    oldSetting := util.SetLogger("trace", true)


El valor de oldSetting es un booleano que describe el estado anterior
de ese registrador, lo que permite que un programa devuelva un
registrador a su estado original si así lo desea.

.topic packages.util.memory

La función Memory() devuelve una estructura que resume el consumo
actual de memoria del usuario, el consumo total durante la vida del
programa, la memoria del sistema en nombre de los procesos de Ego, y un
recuento de cuántas veces se ha ejecutado el recolector de basura que
gestiona la memoria de Ego.

    ego> fmt.Println(util.Memory())
    MemoryStatus{ Current: 36.22, GC: 4, System: 114.32, Time: "Mon Jul 13 2026 17:53:24 EDT", Total: 102.25 }


El resultado de la función siempre es una estructura. Current y System
se expresan en megabytes: Current es la memoria actualmente asignada
por el proceso Ego, y System es la memoria obtenida del sistema
operativo en nombre del proceso (siempre algo mayor que Current). Total
es la cantidad acumulada asignada durante toda la vida del programa;
solo crece, a diferencia de Current, que disminuye cada vez que el
recolector de basura recupera memoria sin usar. GC cuenta cuántos
ciclos de recolección de basura se han completado hasta el momento.

.topic packages.util.mode

La función Mode() indica el modo en que se está ejecutando el programa
actual. La lista de valores es:

+-------------+------------------------------------------------------------------+
| Modo        | Descripción                                                      |
+-------------+------------------------------------------------------------------+
| interactive | El programa ego se ejecutó aceptando entrada de consola          |
+-------------+------------------------------------------------------------------+
| server      | El programa se ejecuta como un servicio rest                     |
+-------------+------------------------------------------------------------------+
| test        | El programa se ejecuta como un comando de integración de test    |
+-------------+------------------------------------------------------------------+
| run         | El programa se ejecuta usando ego run con un archivo de entrada  |
|             | o una tubería (pipe)                                             |
+-------------+------------------------------------------------------------------+


.topic packages.util.symbols

La función Symbols() genera un informe sobre el estado actual de la
estructura activa de la tabla de símbolos. Esto imprime los símbolos
definidos en cada ámbito (incluyendo bloques de sentencias, funciones,
programas y la tabla de símbolos raíz). Para cada uno, el informe
incluye el número de espacios de la tabla de símbolos usados de un
máximo permitido, y luego una línea por cada símbolo, mostrando su
nombre, tipo y valor.

    fmt.Println(util.Symbols())


Ten en cuenta que los símbolos internos al funcionamiento del programa
no se muestran; solo se muestran los símbolos creados por el usuario o
para paquetes definidos.

.topic packages.uuid

El paquete uuid ofrece soporte para identificadores únicos universales.
Esta es una forma estándar en la industria de crear un identificador
que está (para todos los efectos prácticos) garantizado como único,
incluso entre distintas instancias de ego ejecutándose en computadoras
diferentes. Un valor uuid es una cadena que consiste en grupos de
valores hexadecimales, donde cada grupo está separado por un guion. Por
ejemplo, "af315ffd-6c57-46b9-af62-4aac8ba5a212".

.topic packages.uuid.new

La función New() genera un nuevo valor identificador único generado
aleatoriamente, devuelto como un uuid.UUID. Un uuid.UUID es su propio
tipo distinto, no una cadena; imprimirlo o compararlo con == funciona
directamente, pero usarlo como una cadena (concatenación, o pasarlo a
una función que espera una cadena) requiere una llamada explícita a su
método String().

    id := uuid.New()
    fmt.Println(id)            // af315ffd-6c57-46b9-af62-4aac8ba5a212
    fmt.Println(id.String())   // el mismo texto, mediante una llamada explícita

Su método Gibberish() devuelve una codificación alfanumérica en
minúsculas del UUID, omitiendo "o", "l" e "i" para evitar confusión con
0 y 1.

.topic packages.uuid.nil

La función Nil genera el valor cero de un UUID, que es un UUID
compuesto enteramente por ceros. Este valor nunca será generado por la
función New() y nunca coincidirá con otro valor UUID. También es el
valor cero de un uuid.UUID declarado con var.

    if id == uuid.Nil() {
        fmt.Println("id value was not set")
    }

.topic packages.uuid.parse

La función Parse() se usa para analizar y validar un valor de cadena
UUID. Esto es útil para valores de cadena recibidos mediante llamadas a
una API REST, etc. La función Parse() devuelve dos valores: el
resultado del análisis y un error que indica si el análisis tuvo éxito.

    id, err := uuid.Parse(uuidString)


Si la variable de cadena uuidString contiene una especificación UUID
válida, entonces se guarda en id (con las mayúsculas y minúsculas
normalizadas) y la variable err es nil. Pero si hubo un error, id será
nil, y err describirá el error.

.topic user-packages

Puedes crear tus propios paquetes que contengan definiciones de tipos y
funciones que se usan mediante el prefijo de paquete que especifiques.
Considera los siguientes archivos de ejemplo.

El primer archivo es "employee.ego" y describe un paquete. Comienza con
una sentencia package como el primer elemento de sentencia, y luego
define un tipo y una función que acepta un valor de ese tipo como el
receptor de la función.

    package employee

    type Employee struct {
        id int
        name string
    }

    func (e *Employee) SetName( s string ) {
        e.name = s
    }


El segundo archivo es "test.ego" y es el programa que usará este
paquete. Comienza con una sentencia import, que hace que la
compilación incluya la definición del paquete dentro del archivo
llamado "employee". Puedes especificar la extensión de archivo ".ego"
pero no es necesario.

    import "employee"

    e := employee.Employee{id:55}

    e.SetName("Frodo")

    fmt.Println("Value is ", e)


Este programa usa las definiciones del paquete. Crea una instancia de
Employee a partir del paquete employee, e inicializa uno de los campos
del tipo. Luego usa el objeto para invocar una función de ese tipo, el
método SetName. Ten en cuenta que, cuando se llama así, no especificas
el nombre del paquete; en su lugar, especificas el objeto que se creó
usando la definición del paquete. En este ejemplo, debería imprimir el
contenido de la estructura mostrando el id de 55 y el nombre "Frodo".

Usa la sentencia package para definir un conjunto de funciones
relacionadas en un paquete dentro del archivo fuente actual. Un archivo
fuente dado solo puede contener una sentencia package, y debe ser la
primera sentencia.

    package factor


Esto define que todas las funciones y constantes de este módulo se
definirán en el paquete factor, y deben referenciarse con el prefijo
factor, como en

    y := factor.Intfact(55)


Esto llama a la función Intfact() definida en el paquete factor.

.topic directives

Las directivas son sentencias especiales de Ego que realizan funciones
especiales fuera de la sintaxis normal del lenguaje, a menudo para
influir en el entorno de ejecución del programa o dar instrucciones al
propio compilador.

.topic directives.capture
@capture <var> := | = { code }

La directiva @capture redirige todo lo que un bloque de código imprime
(mediante fmt.Println, fmt.Printf, fmt.Print, o la extensión de
lenguaje print) a una variable de cadena, en lugar de dejar que aparezca
en la consola. Esto es útil principalmente dentro de bloques
@test/@assert, para que una prueba pueda comprobar exactamente lo que
imprime un fragmento de código.

    @capture output := {
        fmt.Println("Hello")
        fmt.Printf("%d\n", 53)
    }
    fmt.Println(output)

Al igual que una asignación normal, @capture admite tanto := (declara
una nueva variable) como = (asigna a una variable existente, verificado
en tiempo de compilación). Usa el nombre de descarte _ en lugar de una
variable real si solo quieres que la salida del bloque no aparezca en
la consola y no necesitas inspeccionarla.

Un bloque @capture se comporta como un try implícito alrededor de sus
sentencias. Si ocurre un error a mitad del bloque, la captura se
desactiva de forma ordenada, <var> aún recibe el texto que se capturó
antes del error, ese texto se imprime en la consola con un
encabezado que nombra la variable, y el error mismo se vuelve a
generar para que aún pueda ser capturado por un try/catch que lo
englobe.

.topic directives.compile
@compile [block] { code }

La directiva @compile permite que un programa de prueba capture
errores del compilador en un bloque de código, y evalúe el error de
compilación. Actúa como un bloque try/catch, donde el código entre
llaves se compila (pero no necesariamente se ejecuta), y cualquier
error de compilación se señala como un error capturable en lugar de
abortar el programa.

    @compile block {
        x = bob
    } catch(e) {
        fmt.Println("Compile error, ", e)
    }

Si se omite la cláusula catch, un error de compilación se señala en
lugar de ser capturado. Si no está presente la palabra clave block, el
código entre llaves debe ser un programa completo (declaraciones de
función, etc.) en lugar de solo un bloque de sentencias. Se pueden
colocar palabras clave adicionales después de block para controlar la
compilación:

+---------------+--------------+-----------------------------------------+
| Palabra clave | Valores      | Descripción                             |
+---------------+--------------+-----------------------------------------+
| disasm        |              | Imprime un desensamblado de bytecode    |
|               |              | una vez que el bloque compila con éxito |
+---------------+--------------+-----------------------------------------+
| eof           | "marker"     | Usa un marcador de texto en lugar de    |
|               |              | llaves { } para delimitar el código a   |
|               |              | compilar                                |
+---------------+--------------+-----------------------------------------+
| optimize      | 0, 1, or 2   | Nivel de optimización para esta         |
|               |              | compilación                             |
+---------------+--------------+-----------------------------------------+
| unknown       | true/false   | Si es true, las referencias a símbolos  |
|               |              | desconocidos generan un error de        |
|               |              | compilación                             |
+---------------+--------------+-----------------------------------------+
| unused        | true/false   | Si es true, las variables sin usar      |
|               |              | generan un error de compilación         |
+---------------+--------------+-----------------------------------------+

Esta directiva se usa sobre todo al escribir pruebas unitarias para el
propio compilador.

.topic directives.extensions
@extensions true|false|default

Las extensiones de lenguaje están desactivadas de forma predeterminada
cuando ejecutas Ego por primera vez. Puedes sobrescribir el valor
predeterminado configurándolo en la línea de comandos:


    ego config set ego.compiler.extensions=true


Cuando las extensiones están activadas, hay disponibles funciones
adicionales del lenguaje. Estas incluyen:

* El comando print como una forma más corta de fmt.Println()
* Las sentencias try y catch para la captura de errores
* El uso de len() con cualquier tipo de dato
* La incorporación de la función index() para buscar en cualquier tipo
  de dato
* Soporte para listas de argumentos de longitud variable en funciones
  (a distinguir de funciones con listas de argumentos variádicos ...)

También puedes establecer temporalmente este valor dentro de cualquier
función usando la directiva @extensions, seguida de uno de true, false,
o default. El valor default restablece la configuración al valor que
tiene en la configuración predeterminada.

Ten en cuenta que si la directiva se usa dentro de una función, solo
permanece vigente para esa función. Si la directiva se usa al inicio de
un archivo fuente, permanece vigente para todo el archivo fuente.

.topic directives.global

Puedes guardar un valor en la tabla de símbolos Root (la tabla que es
el padre último de todos los demás símbolos). No puedes modificar un
valor de solo lectura existente, pero puedes crear nuevos valores de
solo lectura, o valores que el usuario pueda modificar.

    @global base "http://localhost:8080"


Esto crea una variable llamada base que está en la tabla de símbolos
raíz, con el valor de la expresión dada. Si no especificas una
expresión, la variable se crea como una cadena vacía.

.topic directives.localization

La directiva @localization define propiedades de cadenas localizadas
para cualquier idioma admitido en el programa Ego actual. La directiva
guarda los datos en el diccionario de propiedades de localización, al
que se puede acceder mediante la función i18n.T(). La localización se
define usando notación de estructura, con un campo por cada idioma.
Dentro de cada idioma hay campos para cada propiedad de mensaje. El
nombre de la propiedad es el nombre del campo (que puede ir entre
comillas dobles si no es un identificador válido) y el valor es la
cadena localizada.

    @localization {
        "en": {
            "hello.msg": "hello, {{.Name}}",
            "goodby.msg": "goodbye"
        },
        "fr": {
            "hello.msg": "bonjour, {{.Name}}",
            "goodbye.msg": "au revoir"
        },
        "es": {
            "hello.msg": "hola, {{.Name}}",
            "goodbye.msg":"adios"
        }
    }

    func main{
        m := i18n.T("hello.msg", {Name: "Tom"})

        fmt.Println(m)
    }


Solo puede haber una especificación @localization en un programa dado.
Puede aparecer antes o después de las funciones en el programa (se
procesa durante la compilación).

Usa la función i18n.T() para obtener el valor de cadena localizado. En
el ejemplo anterior, se usa el segundo argumento opcional, que contiene
un mapa de parámetros para cada elemento indicado en el texto del
mensaje. Ten en cuenta que el texto del mensaje se procesa usando el
código de sustitución de localización de Ego, así que puedes
referenciar los valores nombrados y darles formato según sea necesario.

Un tercer argumento opcional indica el código de idioma ("en", "fr",
"es", etc.) a usar. Si se omite, se usa el idioma de la sesión actual.
En el caso de un servicio web, el servicio puede querer determinar el
idioma de quien llama para ofrecer resultados web específicos de ese
idioma.

.topic directives.optimizer
@optimizer on|off

Puedes activar y desactivar el optimizador del compilador durante una
compilación usando la directiva @optimizer, seguida de la palabra clave
"on" u "off". El efecto se establece de inmediato; cuando termina la
siguiente prueba, función o unidad de compilación, si el optimizador se
ejecuta o no está controlado por esta configuración.

El optimizador es útil para programas que ejecutan muchas iteraciones
de bucle, o que tienen código que se llama con frecuencia. Para
programas más cortos que se ejecutan una sola vez, el optimizador puede
generar sobrecarga con poco o ningún beneficio. De forma
predeterminada, el optimizador siempre está deshabilitado al ejecutar
el comando ego test.

.topic directives.template

Puedes guardar una plantilla de Go con nombre como código en línea. La
plantilla puede referenciar cualquier otra plantilla definida.

    @template hello "Greetings, {{.Name}}"


Las plantillas resultantes están disponibles para la función
template(), cuyo primer parámetro es el nombre de la plantilla y el
segundo parámetro opcional es un registro que contiene todos los
valores nombrados que podrían sustituirse en la plantilla. Por ejemplo,


     print strings.template(hello, { Name: "Tom"})


Esto da como resultado que se imprima la cadena "Greetings, Tom" en la
consola de salida estándar. Ten en cuenta que hello se convierte en una
variable global en el programa, y es un puntero a la plantilla que se
compiló previamente. Este valor global solo se puede usar con funciones
de plantilla.

.topic directives.type
@type strict|relaxed|dynamic

Puedes cambiar temporalmente la configuración del lenguaje que
controla cuándo la verificación de tipos es strict (estricta), relaxed
(relajada) o dynamic (dinámica).

Cuando está en modo strict,

* Todos los valores de una constante de tipo arreglo deben ser del
  mismo tipo
* No puedes guardar un valor en una variable de un tipo diferente
* No puedes crear ni eliminar miembros de una estructura

Cuando está en modo relaxed,

* Si es posible, un valor se convertirá antes de guardarse para
  coincidir con el tipo de la variable receptora
* En las expresiones, los tipos de datos se promoverán automáticamente
  al tipo más complejo de la expresión

Cuando está en modo dynamic,

* Cualquier valor se convertirá automáticamente al tipo requerido para
  cualquier operación

Este modo solo tiene efecto dentro del bloque de sentencias actual
(delimitado por los caracteres "{" y "}"). Cuando el bloque termina, la
aplicación de tipos vuelve al estado del bloque anterior. Este valor se
controla mediante el elemento de preferencias types o la opción de
línea de comandos correspondiente.
